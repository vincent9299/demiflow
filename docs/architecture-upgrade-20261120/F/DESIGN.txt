3. F1：可供真人裁定的归属建议

推荐 F1-OWN-KEEP：五模块仍作为 Forge 的既有公共接口，被工作台直接复用；本批不搬工具。
这是推荐，不把用户休息当选择；在策略裁定前保留现状，F2 独立进入设计审阅。

3.1 十个“中立候选”按行为分类，不是马上移入底座：
io 的 no_symlinks/read_json/atomic_write_text/atomic_write_json/write_exclusive/fsync_directory；
schema 的 digest/required_text；platform 的 bounded_json；platform_environment 的 read_bounded。
它们确有通用算法，但现在有真实 Forge/工作台消费者并使用 ForgeError/现有编码或路径政策；没有底座消费者要求移层。
纯工具移动会改平台 revision、Forge 快照和可能的函数 source_hash；异常转换、已有字节/持久顺序不是“改几条 import”。
read_json 的 stat/read 检查弱于 read_bounded 的稳定 fd 身份检查；bounded_json 逐片累计不等于所有 encoder 片分配前有硬界；
schema.digest、platform.content_digest、artifacts.digest 的编码与预算不同，禁止直接统一替换。

3.2 五个工程合同留 Forge：ForgeError、content_digest、limits_with、platform_declaration、environment_inventory。
ForgeError 的七个代码参与应用错误映射；平台声明/依赖证明是 Forge 工程能力，不是底座的权威执行身份。
limits_with 的 key/default 是平台证明额度；environment_inventory 只证明元数据，不证明所有安装文件和 native 依赖。
将这些下沉会把工程流程/策略扩成底座必需依赖，收益不成立。

3.3 八个 operation_budget 符号是一个应用控制协议：OPERATION_SECONDS、current_deadline、check、scope、controlled、
child_deadline、clear_worker_environment、bind_worker。它们共享同一个 ContextVar 与进程内 _worker_bound，携带经过父进程验证的
oneshot deadline transport；不是容量、run/attempt 或引擎预算 owner。保持 token reset、父期限取小、只绑定一次、清除陈旧环境，
不能把常驻 reader/native worker 绑定成定时控制 worker；60秒不是整个finally/不可抢占IO的硬上界。拆其中几函数会复制状态，故一起保留。
模块内 worker_environment 等协同函数即使未被工作台直接引用仍保留，不根据23符号表删除它们。

3.4 备选 F1-OWN-EXTRACT-DESIGN：若真人希望为未来底座消费者建立中立工具域，只选择上述十个候选另做具体提取设计。
需先逐名定目标消费者/收益、错误类型与catch迁移、编码/持久顺序、对象身份和历史策略；不是批准现在批量移动。
ForgeError 与控制/工程合同仍不一起搬，不加永久转导入垫片。完整仓内消费者已列，外部未知仍保护原公开入口直到具体兼容裁决。
KEEP 的代价是保留已有 import 方向；没有运行故障证据。EXTRACT-DESIGN 增加接口/异常/身份工作，当前无核心用户收益，故不推荐作为前置。

4. F2：已成立合同与需明确注入的边界

20 合同保持原定义、编码和真实类型；20 中立服务由调用 actor/client/session 拥有资源，并不因位于 execution 就变成 Pipeline 管理。
例如 BlockingIOPool 已在提交前准入，取消先排空已启动工作；IsolatedWorkerPool 对进程组排空后才还 slot，frame 字节界不是RSS界；
run_isolated/部分文件helper自身没有总字节硬界，必须保留调用方小引用/小回执约束，不能借归类宣称资源已全部有界。
RequestGate/AdaptiveRequestGate 的共享并发、fatal ServiceStopped 与有限排空原语是实际服务生命周期，不能复制到每行或每个入口。

P1 既有原生装配：bind_lance_action、spec_from_identity、RawFetch、RunContext/current_run、RunJournal 保留精确用途。
registered_write 先读原locator与原Journal/ACK/receipt，再决定原run继续；绑定回调先于source/worker且消费前清空，不能新造注册成功事实。
RawFetch/raw_fetch_facts 在冻结 raw_fetch.py，完全不动；run_journal.ExecutionConflict 保持原对象；旧 cleanup registry 保留但不新增用途。

状态注入边界详见 F2-SERVICE-CONTRACTS.txt。优先项按实际收益排序：
- F2-PROMPT：确认并固化已成立的 verified journal/view 注入，保留真实类检查和 driver capability/预算/occurrence 校验；当前不制造新port层。
- F2-SEARCH：真正可改善的局部切口。SearchWeb 目前直接拼 child RunAction、访问 runtime_reservations/raw budgets 并驱动 CommitCoordinator；
  复用现有 execution.dataflow_search_runtime.SearchRuntime owner 来承接原生协议，库保留搜索参数/请求/结果语义。
- F2-IMAGE：remote 路径已经由 bind_media_adapter 给 RemoteImageStore；本地 _store_image 仍读 store.run/lock/usage 和水位。
  保留既有注入，未来只在有收益的本地能力切片把原生会计/重放检查还给原owner，不能新造image账本。
- F2-INDEX：DataFusionSession 独立能力保留，lance.index 的 _prepare_lance_index 和 _save 私有跨模块使用是局部边界候选，
  不扩大成统一查询服务，也不为清理一条 import 拆出通用文件写框架。低影响，后延不拖 Search/Prompt 或 G。

各建议属于后续实施候选，不等于 F 已获实施授权。没有必要为了实现分类表本身修改产品。F2 审阅可独立于 F1 策略完成。

6. 身份、历史与权限

本阶段仅 docs/ 下文档和只读探针，demiflow/ 文件字节与基线一致；引擎 platform_identity 及对象源码身份输入没有改变，Git SHA 会前进。
Forge platform_snapshot 的 package/source/声明/环境输入未改；项目开发 snapshot 按 watch/sources，可能覆盖docs，不能自动复用开发证据。
未来 F2 普通源码调整会改现有全树 platform revision，类方法/整源函数 source_hash 也可能变，必须逐对象出精确差异而非说“签名未变所以身份不变”。
沿用精确跨版本拒绝、保留旧提交/环境、原历史只读；旧 seal/Journal/ACK/receipt、对象路径和业务数据不重签/迁移。
不采用 C 未批准的 S2 或最小摘要，不把 C 全案当普通源码修改的前置。若提议真的搬序列化类/改变模块加载、封存表示/恢复承诺或触冻结文件，
再绑定 C 对应获审结论和具体范围裁决；不能只更新冻结摘要。Search 候选不需要改冻结七件，若预检发现需要就退出该项另审。
不触业务仓/Notebook/开发对话/在线预览；分析配置factory只读，绝不执行。没有公共工具导入能授予运行/数据写权限。

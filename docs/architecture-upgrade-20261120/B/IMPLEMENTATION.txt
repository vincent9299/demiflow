实际职责与边界

projects 核心为 workspace/checks/discovery/definitions/documents/io/index 七模块；registry/watch/flow_arguments 三模块仍是应用模块，__init__ 无副作用。新增 workbench/project_operations、directory_operations、table_bindings、pipeline_policy；不宣称应用组合层或 runs 内部整体无环。七核心的可解析静态路径及冷导入均不能进入 runs、worker、api、两个应用操作模块或三项目应用模块；index 不读 workspace/P4。

index 只管理 SQLite、pending generation、游标、临时库替换。所有者 run_index_entry/report_index_entry 生成真实摘要，publish_* 在同一异常边界内检查有效 deadline、求摘要并发布；普通失败和日志失败不撤销源成功，不把不可读/损坏/预算耗尽当 Missing。BaseException 传播并留下 pending。Missing 只收尾该 marker，不删除旧成员；generation 不符不能改新 marker。

start 的 authority.require、development/preflight/history 检查及 authority/development guard 仍先于 begin。begin 在本次 fence/reserve/claim/starting 前执行；未获得 reservation 的异常不记 launch_failed。已有 execution.lock 内容为空时，_lease_owner 的 legacy adoption 原样保留；非空无效 owner 拒绝。本次 admission 的无变化承诺以这些真实前序维护完成后、begin 前为准，不是整个请求零写入。reserve replace 成功而 fsync 失败、Python reservation 尚未返回时，既有 durable slot/owner/fence 保留，reconcile 按原协议处理，之后 reserve 可惰性回收；不能声称失败时已释放容量。

_prepare 的已持久 prepared 源发布与可回滚准备区分开；摘要/索引失败不再 rmtree 成功源。_resume 保留此前 register_results/clean_stopped，begin 拒绝不新增 attempt/status/usage；真实恢复登记不能回滚。refresh 在 begin 前耗尽不建 marker，在 begin 后耗尽留下 pending，使用当前请求和维护 deadline 的较早值。

首轮失败的处理原则与已定位夹具问题

新生命周期故障探针初轮在普通 pytest 进程直接调用 worker 私有读取，被原 finite-allocation guard 拒绝；后改到真实有界子进程，复用原 prepare_native 线程/地址空间限制。一次缺 native 线程上限的探针由作者仅终止本人进程组，首轮未完成回执保留，不算通过。真实执行不能放在只读 metadata worker 的较小继承 hard limit 下；后来保持实际 execution 原管理路径，只将 _resume 维护故障注入放进有界子进程。

现有 test_forge_resume 的三个负例从未执行的 prepared 人造 interrupted，缺少原 public resume 所需 recovery_identity，先被原历史守卫拒绝。对照 baseline 后，仅把负例起点换成真实 execute/stopped 的私有记录，再注入未知 accounting、耗尽预算或来源变动，原拒绝断言和 attempt=1 保留；不能通过补造恢复证书求绿。

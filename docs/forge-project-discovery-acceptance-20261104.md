# 原项目识别闭环：实施与验收

本次只实施通用平台识别、展示和检查衔接。实现位于 `demiflow`；不参与另一会话的 DemiForge 目录规则清理，不迁移或修正业务项目。

## 实现与职责

- `forge/project_discovery.py`：按公开声明版本读取原入口、算子角色、配置引用、Lance 引用和历史产物引用，提供来源及内容摘要。无业务项目名、目录前缀或客户端分支。
- `forge/project_check.py`：复用现有 `SourceTree` 和原生 Flow 检查器；记录实际读取的源码、未覆盖部分及当前检查器摘要。识别成功、源码前置检查、完整 Flow 检查分别表达。
- `workspace.py / workspace_worker.py`：公共接口、变化观察、受限固定版本预览；不建立新的表登记或执行体系。
- `workspace_cli.py / workspace_view.py / web/app.js`：CLI、HTTP、Web 消费同一份事实。原项目保持原位；新增客户端使用同一公开接口。

完整协议、支持范围及资源上限见 [原项目识别](forge-project-discovery.md) 和 [HTTP 接口](forge-http-api.md#original-project-recognition)。

## 验收矩阵

| 场景 | 结果 |
| --- | --- |
| 无关业务的订单项目登记 | 自动显示原入口、配置、算子目录、文档数据引用；无代码复制或导入 |
| 原生 `{path,symbol}` 入口与任意项目内算子路径 | 按声明读取；复用已有原生检查与执行准入 |
| 旧 `config → run_pipeline` 协议 | 可查看、可做源码前置检查；完整 Flow 语义明确未覆盖 |
| 缺失声明、不支持版本、重复归属、协议冲突 | 明确列出来源与原因，不冒充空项目或检查通过 |
| 符号链接、越界、隐藏文件、重复 JSON、资源超限 | 拒绝相关读取或标记未识别；不扩大项目权限 |
| 普通图片/文档 URI、文档模板路径 | 不误识别为可用数据表；未解析文档引用不表示历史数据丢失 |
| 固定表与未指定版本的文档位置 | 打开后固定版本；追加新版本不移动当前页；引用变化拒绝旧绑定 |
| 原代码、配置、父声明、检查器变化 | 同步识别结果，检查依据标记过期；不自动重检为通过 |
| 两个浏览器页面与 CLI/HTTP | 读取一致事实；配置变更自动可见；无浏览器脚本错误 |

整合回归 29 项通过；配置引用边界修订后，通用识别与浏览器用例 24 项通过。随后保留并行会话的同文件多入口读取优化，连同其 5 项边界用例再次验证，当前版本 29 项全部通过，并核对测试后的平台摘要未变化。已有原生 Flow 的检查、运行及拒绝未允许作用也完成回归。Review 修正了 Case 行 ID 的字符串处理、重复缺失诊断、配置引用预算、协议与版本匹配，以及文档引用被误当成规范结论的问题。

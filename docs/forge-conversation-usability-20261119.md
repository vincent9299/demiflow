## 行为与契约

- `development_protocol` 新增 `input` 操作。用户不需要填写位置配置；代理可从默认项目父目录开始发现，也可直接使用项目外路径。`list`、`find`、`read`、`inspect` 提供目录、文件名查询、UTF-8 文本和 Lance/Parquet 结构及有限样本。上游 `.forge/runs` 的普通输出可用作读取来源。
- 输入工具绑定当前 turn/epoch，执行固定只读动作。结果携带真实路径、文件身份、分页和截断信息，不复制全量数据或建立输入目录白名单。宿主内部传入控制状态、运行域、部署配置、Web token/ready 文件和已知模型凭据的排除路径；不把这些文件的整个父目录误禁成数据禁区。
- 原生表读取复用现有外部只读边界，最多 7 秒、10 行和 16 列；提供 schema-only 模式。超时、取消、旧 epoch 拒绝并清理所属进程。普通输入读取不扩 CLI 写权限，不更改输出、生产运行权限和 verifier 数据范围。尚不支持任意远程协议或任意二进制解析；物理路径别名会拒绝，不绕过为全宿主 shell 读取。
- DeepSeek 使用提交身份与连续片段区分消息，公开过程采用 `channel=process`；Codex 仅接收公开摘要 `channel=summary`，不保存或重建隐藏 reasoning。前端兼容原始旧事件，按 session/turn/epoch/片段排列正文与工具，不重写历史记录。
- 长最终回复保持助手正文角色；原文分页限定当前可见片段。旧远端仍可用原有 `dev-events` 分页过滤，不要求同步升级服务端。保留 100 卡、64 KiB 单卡、1 MiB 总预览预算和现有事件存储预算。
- DeepSeek 当前 CLI 在提交 assistant message 后发布公开块；工作台收到块即展示，不能承诺模型逐 token 透传。
- Forge 投影新增 `unchanged_checked`，只表达经过检查的零候选改动。身份、上下文、只读区域、staging、当前 developer 证据及最终指纹检查仍成立；缺少 verifier/review 不再让这种纯读对话强制进入验收链。`ready`、历史验收和证据语义不变，所有有改动候选仍走原门禁。

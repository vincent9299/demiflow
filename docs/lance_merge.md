# Lance 部分列合并

业务使用 `Dataset.write_lance(mode='merge', on=..., update_columns=...)` 表达键、列归属和缺失键行为。Demiflow 管理物理写入策略；Dataset API 不提供 `rewrite_rows`、`rewrite_columns` 或引擎会话参数。

## 自动选择

Linux 本地执行器从固定版本、没有过滤或表达式投影的直接 Lance 扫描取得精确行数，包含扫描 limit。它只读取行数元数据，不提前运行 Python 回调，也不额外扫描过滤后的数据。该内部提示不进入 `LanceWriteSpec`，不改变请求身份、业务配置或提交回执。

满足以下全部条件时，平台选择 Lance 12 的列重写：

- 缺失键策略为默认的 `error`，只更新已有行。
- 来源至少包含一个非键列，同时省略至少一个目标列。
- 已知来源行数大于 0 且不超过目标行数。
- 来源携带的字段及其目标字段均无 Blob 标记或 Arrow 扩展类型，含嵌套字段。

列重写复用省略列的数据文件，只对触及的 fragment 写替换列文件。替换文件覆盖整个 fragment，因此少量更新也可能产生较多写入。2026-10-03 移除原先的 50% 行数门槛：行数比例不能说明被省略宽列的字节成本，约 39% 的文档关系补丁曾因此退回整行路径并触发 32 GiB 进程树保护。当前优先避免读取未更新载荷，接受稀疏更新的片段级写放大，不宣称全场景 I/O 最优。

来源规模未知、经过回调或关系计算的流、过滤扫描、插入、整行更新、特殊字段及其他操作系统保留 Lance 原生 `auto`。原生 `auto` 本身可以按索引选择列更新，不能把它一律理解为整行重写。无索引的普通部分列更新通常重写整行。平台记录实际选择和来源/目标行数的日志，不把策略选择交给业务配置。

## 正确性与资源边界

两种策略共用原有键唯一性、非空、列集合、类型、缺失键及提交版本检查。自动选择的列重写在独立 worker 中准备未提交事务，只传回事务元数据；原始 writer 核对准备版本并完成唯一一次提交。失败不发布部分结果，不因选择策略而重放回调或自动重试提交。旧 Lance 版本保留；原生准备失败可能留下未引用的数据文件，不能据文件存在判断已经提交。

这一步属于 Lance 存储写入，Lance 有自己的内部排序池。自动列重写与 Dataset 关系任务共享平台准入槽、CPU/RSS 预算和 cgroup 余量检查。当前大容器配置为最多 12 GiB 排序池、每个准入名额 24 GiB RSS 预算、128 GiB 临时目录保护，按容器容量缩小。已知补丁不少于 2,000,000 行时，合并最多独占两个已有名额；本机相应 RSS 保护为 48 GiB，总预留容量不增加，其他共享该池的原生任务需等待。单名额容器仍只使用一个名额。Lance 排序和片段写入使用单路 CPU 并发，减少同时归并和写片段的缓冲。预算只在子进程环境设置，不改主进程环境，不关闭 spilling。池预算不是预先占用量、最低要求或整个进程的上限；RSS 采样保护也不是内核硬限制。

准入、超时、RSS、空间或 cgroup 保护失败时没有事务提交，不自动换回可能占更多内存的整行路径。worker 有父进程退出终止保护，临时目录随后清理；写到目标目录的未引用暂存文件不计入临时目录限额。当前非适用路径仍按原方式执行，不能宣称所有 Lance 合并都已隔离或有资源上限。来源键重复检测最多保留 100,000 个键，之后转为临时 SQLite 唯一索引，使用完整类型化键而非哈希，页面缓存为 8 MiB、禁用 mmap；单次转换不超过 8,192 个键。它保留跨批和溢写前后重复检测，结束后清理，不是业务结果或新公共依赖。这个界限限制常驻键数量，不是对任意单个超大值或整个进程 RSS 的硬上限。

## 验证

`tests/test_lance_merge_strategy.py` 使用真实临时 Lance 表，验证固定扫描/limit/过滤的策略边界、原字段与旧版本、文件复用、复合键和嵌套空值、缺失/重复/空键失败不提交，以及目标 Blob 标记不被来源 schema 遮蔽。还覆盖跨内存/磁盘边界的晚到重复键、复合 binary 键、临时索引清理、准备后提交竞争、RSS 保护终止及多名额排斥。与既有部分列更新、Arrow 复制、写入模式、内存保护及原生关系执行回归一起复核，共 82 项通过。

## 尚未完成的低内存目标

全量在 48 GiB 进程保护线内成功，不代表可以在 8 GiB 总内存内完成。池预算内确有外排，但部分排序归并和片段写入缓冲不能再溢写，Arrow/Python/原生分配也可能在池外。触发保护时停止合并是失败保护，不是把超出的全部内存自动转成磁盘后继续完成。

下一步需验证：只对键和固定行号做匹配，大字段留在原 Lance 文件中，按有界批次回取；逐片段准备更新，最终只提交一个事务。Lance 12 提供 fragment.update_columns 与未提交 Update 事务的组合，但其片段内 hash join 仍可能需要显著内存，不能仅凭接口存在就承诺低内存完成。合理最低预算还必须容纳单个最大记录及必要缓冲；预算更少应优先更多分块/落盘/降低并发，实测无法满足时清晰拒绝，不能承诺任意内存容量均可运行。

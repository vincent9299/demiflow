# 工作台节点：定义与流程接线的四个视角

本轮从 `b29bd11` 开始，在 `workbench/project-operators-20261118` 隔离分支实施。原端口 59866；主仓、引擎及业务数据保持不变。

## 确认的产品结构

用户希望在目录和 Pipeline 内都能完整阅读同一份定义，重复展示可以，重复维护不可以。目录属于项目；节点属于某条流程中的一次使用。

| 页签 | 展示内容 | 事实来源 |
| --- | --- | --- |
| Dataset API | 平台接口签名、参数、默认值、已声明返回契约；长说明折叠 | 解析时的 SDK 源码，或运行封存的平台源码 |
| Prompt 算子 | 原 Prompt 正文、模板变量及类型、响应 Schema、定义版本和已有默认值 | 本节点实际编译的原生 PromptDefinition；历史使用封存源文件 |
| 代码算子 | 完整函数/类源码、签名、已声明参数与返回类型 | 本节点编译声明及同一次源码摘要；历史使用封存源文件 |
| 流程接线 | 本次实际 API 调用、上游 Dataset Schema、输入字段映射、实际参数、输出字段映射及 Schema、下游节点 | 同一节点的调用记录、编译参数、Schema 材料和真实 DAG 边 |

节点默认打开“流程接线”。代码和 Prompt 正文直接在节点中阅读，不要求跳到目录；目录仍可查看当前定义及 Git 文件版本历史。没有引用时隐藏对应页签；已经引用但材料不可用时保留页签并解释原因。

类型注解与实际 Dataset 行 Schema 分开。不执行函数去猜返回字段，不把未知结构写成已经验证的 Schema。默认值来自接口源码或已有原生定义，不从业务名称编造说明。

四个页签共用一个阅读区。代码/Prompt 默认展开正文，输入输出契约按需展开；接线的原始参数描述和快照依据放进“高级信息”。没有新增配置方案、独立算子登记库或运行账本。

## 实现与边界

- `definition_contracts.py` 提供公共的被动 AST / Prompt 定义投影。动态默认表达式仅呈现原文，不调用；无注解时明确未声明。类算子定位 `__call__` 及所在类，不实例化 actor。
- `web/definition-reader.js` 同时用于项目算子目录和节点面板。正文/契约由同一个组件渲染；读取来源仍由当前目录、Git 版本、编译快照或封存运行分别授权。
- `graph/api_definition.py` 只从指定平台源码文件提取已有 API 签名。历史 API 必须来自运行 manifest 列出的平台文件并通过摘要校验；不存在时说明缺失，不填入当前 SDK。
- 现有 `callsite/configuration/schema/implementation/prompt` 材料协议保持。新增定义信息是快照内的展示数据；不参与执行计划编译、身份重算或运行提交。
- `source_views.referenced` 区分“没有引用”和“引用材料暂不可读”。超出材料预算仍保留图及原因，不冒充该节点没有 Prompt。
- Prompt 明确绑定 `when` 函数时，节点同时呈现 Prompt 和该业务函数。多路无法唯一定位时不借用别路的函数。
- 刷新只恢复同一快照摘要下的节点和视角，一次装载。接线材料顺序读取；切换节点后停止开始旧选择的后续请求，迟到响应受选择与快照身份保护。
- 材料沿用单正文 64 KiB、单材料 128 KiB、总材料约 4 MiB 的展示预算；源码与 AST、目录索引保持既有预算。大材料明确降级。

工作台/引擎依赖边界检查保持原来的 ratchet，没有增加待整改引擎导入项。原有静态捕获适配仍是既存待整改边界，不在本轮宣称已经消除。

## 验收角度

1. **信息结构**：源节点仅显示 API 与接线，函数节点显示代码，模型节点展示 Prompt；模型节点显式引用业务条件函数时四项均可用。
2. **完整阅读**：节点内完整代码/Prompt 可直接读，契约不需要跳转目录。目录与节点 Prompt 正文逐字一致。
3. **定义与使用**：API 展示默认版本参数；接线显示真正传入的固定版本、字典展开和字段绑定。join 左右 Dataset 单独展示。
4. **被动读取**：函数动态默认/注解不执行；类构造器和行函数设置必抛异常，读取仍成功。
5. **精确快照**：解析后修改源文件，原节点材料逐字不变；错误节点身份拒绝读取。
6. **历史保护**：真实运行封存后改当前源码；历史入口和 API 仍读原封存字节。把当前 API 读取函数替换成必抛异常，历史读取仍成功。
7. **缺失与预算**：原生编译能接受、展示预算不能接受的深 Schema 保留 Prompt 页签及明确原因，图不丢失。
8. **并发与迟到**：延迟旧节点材料、切换到新节点、释放旧响应，新正文不被覆盖；过期快照清除旧正文。
9. **刷新和导航**：恢复选中节点/视角、返回整条 Pipeline 源码、切换 7 节点与 47 节点流程；修复恢复时重复读取触发页面并发上限的问题。
10. **呈现**：1600px 正常布局、900px 窄窗口截图；测试覆盖 1440/780/390px 不产生整页横向溢出。图放大、方向切换、键盘选择与全文阅读保持。
11. **架构和保持**：主仓 HEAD/dirty、原端口 token/registry、冻结七件；依赖边界检查与相关旧用例复验。

最终测试、原端口截图与输入摘要在 `workbench-node-definition-evidence-20261118/verification.json`。

## 本轮没有扩大的能力

- 未声明 Schema、动态源码、无法唯一定位或超预算的定义仍明确未知/不可用。
- Git 历史仍是实际文件提交历史，不冒充全局发布版本库；没有新增恢复/发布操作。
- 真实标杆两条流程继续用于编译图与材料验收。本轮没有重复调用外部模型；沿用上一轮真实原生执行的结果。
- 复杂标杆的旧工作台受管提交准入缺口仍在，不能把编译/阅读通过写成工作台一键运行已完成。

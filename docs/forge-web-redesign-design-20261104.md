# Forge Web 阅读与引导改版设计

日期：2026-11-04。状态：设计 Review 稿；本轮未修改正式平台源码、测试、服务、登记或业务内容。

## 推荐方向

把 Forge 做成一个从项目出发的轻量工作台：**先说明能做什么，再给一个下一步，以可阅读的内容为主体**。采用浅色、留白、收敛导航的视觉语言，保留 Forge 名称与数据/流程语义。DeepSeek 只作为用户指定的简洁方向；未验证其当前官方页面细节，不声称复刻。没有聊天框、聊天模型、模型切换或新的助手后台。

## 真实问题与依据

阅读了根及仓库 `AGENTS.md`，现行工作区、原项目识别、HTTP/客户端指南、四个 Web 文件与相关浏览器用例。视觉基线来自 [现有控制台截图](assets/forge-project-management-20261104/formal-console.png) 和 [注册后截图](assets/forge-project-management-20261104/registered-project.png)。截图是已有验收记录，当前源码又含后续识别增强；截图中的数量不作为当前事实。

- `overview()` 同时摆出指标、原项目识别表、说明、源码、位置和规则。各 panel 权重近似，项目名重复，不能迅速回答“先看哪里”。注册后的未识别状态还容易被数量解读为没有内容。
- `context.readme` 目前进入 `.readme` 文本节点，标题、强调和链接仍是 Markdown 原码。长文没有清楚的阅读层级。
- `originalData()` 的 Case 点击结果仍是整条 JSON；`renderCase()` 虽按字段展示，但长字符串继续平铺。表格摘要、阅读正文和准确原文缺少明确分工。
- 全局巡检、复制引用、参数、摘要、规则和调试信息不断叠加在工作区域。真正的限制必须看得见，完整技术信息可以按需展开。

## 页面与导航

宽屏：224px 浅灰侧栏，顶部是当前项目选择器，下面只显示该项目的五个任务入口。主区顶部保留项目/位置路径、有效权限、刷新/帮助；内容区最大约 1100px。移除项目放进项目设置，并保留原有确认和并发校验。

| 用户看到的入口 | 原有视图 | 页面主体 |
| --- | --- | --- |
| 项目总览 | `overview` | 一个下一步 + README 预览；侧列用简短清单显示项目内容、检查摘要 |
| 数据与 Case | `tables/table/case` | 数据来源/固定版本、短摘要列表、单条字段阅读 |
| 流程与配置 | `flows/inspection` | 入口与实际配置绑定；源码、接线、单入口检查及原有准备运行操作 |
| 规范检查 | `checks` | 整体结论、静态/行为/审查证据、覆盖缺口与具体诊断 |
| 运行记录 | `runs/run/run_compare` | 实际 attempt、状态与产物；历史/独立对照引用分别标明来源 |

不合并检查状态，不新增路由协议。总览的完整识别表迁至对应任务页，技术明细留在原有展开区；不删除已有源码、对照、运行、巡检或历史查看能力。

窄屏：侧栏收起为“展开项目导航”，当前项目和当前位置持续显示；说明与正文单列，Case 记录列表缩为短横向选择器。表格/代码块各自在容器内横滚，页面本身不横滚。键盘能返回、换字段、开关导航；焦点和选中状态不能只靠颜色。

## 首次使用的四种状态

| 状态 | Forge 是什么 / 现在能做什么 | 主行动及下一步 | 必须可见的事实 |
| --- | --- | --- | --- |
| 无项目 | “在原项目目录中阅读说明、查看数据与 Case、核对流程和检查结果。” | 主按钮“注册已有项目”；次按钮“新建项目”。三步小字解释选择目录→读内容→核对检查 | 使用服务器绝对目录；新建只接受空/不存在目录；登记只补必要管理信息；单项目服务未授予项目管理时说明限制，不显示无效按钮 |
| 刚新建/注册 | “项目已登记，从已有内容开始。” | 注册后先读 README；有可读数据时再进入一条 Case。新建空项目提示在原目录保存说明和代码 | 已登记≠已检查；不制造默认目录、说明、数据位置或可执行入口；不把新建空目录显示成识别失败 |
| 识别不完整 | “项目已登记，部分内容尚未识别。” | “查看入口与配置”，可继续读说明/源码；按实际原因给出下一步 | 未识别≠没有内容；缺原生绑定、未知协议、项目外数据、超限分别说明，不自动生成声明或扩大权限 |
| 已有项目 | “阅读原项目，查看固定版本数据，并核对流程、检查和结果。” | 首先推荐“查看数据与 Case”；数据不可读时改为“查看入口与配置”或阅读说明 | 当前对象、版本、来源、检查与运行权限清楚；建议依据当前事实生成，不发明业务结论或“最近使用”历史 |

四种状态由当前事实推导，不用“已经看过引导”标记替代真实项目状态。刷新不能自动检查、执行、修复或重绑。注册、移除等动作仍由用户主动提交。

## 阅读体验

README 默认 **预览**，旁边固定提供 **原文**。保留来源文件名和显式刷新，缺失/读取错误直接说明，不呈现为成功载入的文档。原文必须能准确核对字符和空白。

Case 页持续显示“项目 → 表 → Case”、返回当前表的入口、表别名、固定版本、业务键和来源。`row_id` 仍是字符串行定位，放在身份明细，不冒充跨表业务键。正文、参考答案与其他字段按已有字段声明组织，不按业务字段名猜角色；样稿中的角色来自虚构示例。

- 复用现有 `display.fields.kind=text`：以阅读模式呈现，提供预览/原文；已有 JSON、图片、证据类型保持原语义。
- 无展示声明的原项目数据/普通字段：展开的长字符串或多行文本默认 Markdown 预览，始终可切准确原文；短身份标量/路径紧凑显示，嵌套对象保持可展开结构与准确 JSON。首期长文本判定建议为 ≥240 字符或包含换行；显式展示声明和原始类型优先。不会要求业务补展示配置后才能阅读，也不凭 `question/answer` 名称解释业务。
- 原源码、配置、JSON、日志、显式 image/evidence 与结构化对象仍按原类型展示，不因内容较长就当作 Markdown。字节或结构超预算的长文明确退回原文，不伪装为完整预览。
- 表格继续使用有界纯文本摘要（现有约 140 字符），不在每个单元格渲染 Markdown。选一条 Case 才挂载正文；其他字段和对照记录按需展开，不把全部 JSON 当默认视图。
- 对照继续明确业务键，展示零匹配/多匹配。历史或独立准备的数据不变成当前运行证据；固定行读取、图片与调用证据各自沿用原有校验。

## Markdown 与可信边界

推荐浏览器本地使用固定版本 markdown-it，解析结果经标签白名单构建 DOM，文本只通过 `textContent`/Text 节点插入。不写正则 Markdown 解析器，不使用 CDN，不引入前端框架。样稿使用 [markdown-it 14.1.0 官方发布](https://github.com/markdown-it/markdown-it/releases/tag/14.1.0)；保留其 [MIT 许可证](https://github.com/markdown-it/markdown-it/blob/14.1.0/LICENSE) 及浏览器依赖通知。

支持标题、段落、强调、嵌套列表、引用、行内代码、代码块、分隔线、表格与安全链接。代码不执行，不自动高亮；暂不扩展公式、图表、编辑器、嵌入页或自动链接识别。

| 内容 | 规则 |
| --- | --- |
| 原始 HTML、脚本、事件、SVG | `html:false`，作为文字；禁止业务 `innerHTML`、任意属性或样式注入 |
| Markdown 图片 | 显示 alt/未加载占位；不生成 `img`，不自动读取远程、本地、data 或 blob 资源。原有显式图片按钮继续走固定行及授权接口 |
| HTTP(S) 链接 | 校验协议及用户信息；用户点击才打开，`noopener noreferrer` 与 `no-referrer`；不附加会话 token，不传授权头，不预取 |
| 相对文档/源码/数据链接 | 仅对当前项目已识别且已有接口支持的目标提供站内按钮，复用摘要及版本校验。不拼网页 URL，不新建任意文件读取；未支持引用显示原路径及原因。样稿无真实 resolver，所以这些链接保持不可跳转并可读 |
| 文内锚点 | 在当前阅读区域内定位，不覆盖 Forge 的 `#view` 深链接协议；找不到标题时显示引用说明 |
| 非法协议、认证 URL、凭据参数 | 不生成活动链接；sessionStorage、token、页面 hash 不进入渲染上下文、日志或复制内容 |

输入、解析与 DOM 都要有预算。建议单字段 64 KiB、4096 行、解析嵌套 16，累计最多 6000 token，生成树深度 24、DOM 节点 8000；一个可见文本区解析一次，最多一个进行中的渲染。过限整段退回原文，不裁掉半个 Markdown 后伪装完整。原文分块显示，JSON/行投影仍遵守后台预算。实现阶段用独立 worker 限制在线解析时间，详见源码方案；字节/节点预算不声称等价于 RSS 硬上限。

## 视觉系统与状态文案

白色主背景、`#f8f9fb` 侧栏、细灰分隔线；Forge 字标保留深青色，任务主按钮使用克制蓝色 `#3b63cf`。不使用大面积彩色状态块、渐变或等权指标卡。8/16/24/32px 间距，主标题 26–30px、正文 14–15px、辅助字 11–12px；阅读区约 60–76 字符宽。圆角 8–12px，无装饰性图片。

主动作每个任务段只突出一个。复制引用、完整 JSON、规则表、哈希、调试元数据降为次级或展开；实际错误、缺证据、越界、断线/过期、未完整扫描不可只藏在展开区。巡检可以压缩，但越界/无法核验/过期时主区或顶栏必须出现可见提示。

| 事实 | 推荐文案 |
| --- | --- |
| 有效运行权限关闭 | “可查看、检查 · 运行未开启”，而不是将可保存检查的会话统一称“只读” |
| 静态通过但其余证据缺失 | “整体仍缺少证据；静态检查通过，行为验证与语义审查尚未完成” |
| 旧检查发生变化 | “依据已变化，旧报告保留；请核对当前依据” |
| 无支持的原项目运行状态 | “尚未识别受支持的运行状态；不表示项目从未运行” |
| 独立对照 / 历史来源 | “独立准备的对照数据” / “历史结果；不是本次 Flow 的执行证据” |
| 暂时断线 | “暂未更新，保留上次内容”；恢复仍只读取，授权失效停止轮询 |
| 识别/索引超限 | “本次只覆盖已显示范围”，同时显示具体缺口、计数与原因 |

## 验收与交付

1. 不懂 Forge 的读者在每种首次状态都能回答“是什么、能做什么、下一步点哪里”；不需先读规则表或 JSON。
2. README 与两类 Case 的长文本默认 Markdown 阅读并有准确原文；短标量保持紧凑，表格保持摘要，结构化数据及显式资源类型不被当作文档解释。判定依据类型、长度/多行和展示声明，不依据业务字段名。
3. 当前项目、选中对象、返回路径、真实限制和证据缺口持续可见；现有深链接、历史 attempt、固定版本及读取竞争保护保持语义。
4. 恶意 Markdown 不执行脚本、不请求图片/任意文件、不泄露凭据；超限明确降级，不产生无界 DOM。
5. 宽屏 1440px 与窄屏 390px 可审阅；额外检查 320px 无页面级横滚。键盘导航、字段切换及焦点提示可用。
6. 视觉样稿验证不宣称平台回归通过；后续实施须完成源码方案的相关测试与正式 Review。

交付入口：[独立 HTML 样稿](assets/forge-web-redesign-20261104/index.html)，[场景/截图索引](assets/forge-web-redesign-20261104/README.md)，[源码实施方案](forge-web-redesign-source-plan-20261104.md)。样稿为虚构数据，不连接真实 API；预览/登记按钮只切换示例。

主会话 Review 已确定：Case 全页阅读纳入首期，原项目未声明的长文本也默认 Markdown；不只上线配色。A（导航/视觉）与 C（资产/打包/离线/集成）由一个实施负责人独占相关正式文件，B 独立交付纯阅读模块、本地 parser/许可和在线单 worker，不持有 token、HTTP 或项目状态。正式实施先在自有临时完整源码副本完成，主会话 Review 后统一发布，避免磁盘资产混入正在运行的旧页面。本设计阶段的样稿验证不代表正式 worker、分块原文或平台预算已实施。

仍需保持的范围取舍：原项目独立 Case 深链接与任意文档读取留待单独协议 Review；离线报告不增加业务样本，不能声称拥有在线 worker 的硬超时保证。依赖生产封存的构建来源/许可审计由实施集成阶段完成。

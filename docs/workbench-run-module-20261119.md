# 工作台运行模块：界面交付与契约交界

本轮目标是让用户按一次真实运行查看封存图、状态、日志、参数、停止／恢复和固定结果。用户随后明确选择“先完成运行界面，原生提交接口另做”，因此 RefGen 原生流程的受管提交不属于已完成能力。本轮没有新增引擎执行入口，也没有改写业务项目。

## 产品行为

- 管道负责阅读当前流程及发起运行。确认页展示本次入口、业务参数与输出信息；确认前不创建运行。未接入受管提交的流程显示具体原因。
- 运行页左侧常驻“管道与运行”目录，不再提供整栏收起。目录保留全部登记管道，可搜索、展开查看运行；“最近运行”提供跨管道的最新记录。管道分支按创建时间翻阅历史，状态过滤仍明确只作用于当前页。主区域分为执行图、输出结果、本次参数与版本。
- 执行图来自选中 run/attempt 的封存事实；右侧提供执行情况、定义与接线、日志。没有观测的数据保持“未测量”，不从相邻节点推造状态。
- 停止与恢复均操作选中的当前 attempt，沿用原控制器、准入与清理协议。恢复保持同一 run 并创建下一 attempt，历史尝试只读。
- 查看旧 attempt 不改变左侧最新运行摘要。过期的参数请求不能覆盖新选择；参数展示取本次封存值，不取当前文件内容。
- 输出只显示已验证的提交结果。不同阶段的输出行数不相加当作总处理量。已停止运行中的已提交输出仍可读。
- 结果入口携带 run、输出名称和 attempt；沿用原表身份、Lance 版本、提交证明和位置校验，再进入现有数据／Notebook／Case 能力。

## 复用与边界

UI 继续使用现有 WorkbenchState、Commands 和 Observer；不另建运行账本、轮询器或提交协议。P4 的 host inspection/control 契约沿用已有实现。

读取运行结果时，提交证明检查会再次请求固定版本元数据。原路径在已有有界 reader 中启动子 worker，触发子进程守卫。本轮只让该 reader 中的 metadata 请求使用同一个固定 dispatcher；其他操作保留隔离，原时间、RSS、响应大小和子进程守卫不变。

P12 负责工作台内部 projects/runs 解耦。本轮不代做该重构；后续迁移必须保留下列行为：

1. `run:<run_id>:<output>:<attempt>` 是固定尝试选择器；原三段选择器仍兼容。
2. 已选中的历史 attempt 不能被 resolver 的默认当前 attempt 覆盖。
3. 参数解析、结果预览与继续分析都保留完整固定表身份与版本复核。
4. 目录摘要只是查询数据；运行状态仍由原运行事实决定。

并行导航改造需要保留新静态资源及上述别名语义；本轮 app.js 只调整运行标签与结果别名，未替换开发对话布局。

## 验收范围

新增 `tests/test_workbench_run_module.py` 使用真实 HTTP、浏览器、RunContext、journal 和 Lance 文件，覆盖：确认后提交并读结果；写入一份结果后停止、清理、恢复、原版本不重复提交及历史结果读取；两个真实 run 间迟到参数响应；原生未接入流程不创建 run 或输出。

停止／恢复测试还验证 1920、1440、1024、390 像素布局没有横向溢出。项目定义、节点材料、P4 边界、原 workspace reader、表读取和客户端协议按受影响面进行组合检查。逐次结果、失败原因、提交和源文件摘要见共享交付证据，不把多次重叠验收简单相加，也不宣称全仓测试通过。

RefGen 七条流程的只读准入检查均返回 `managed_output_binding_missing`。目前提交器要求静态检查报告的显式输出绑定；这与 P12 的内部调用方向改造不同。本轮未运行 RefGen 模型、未修改其历史结果、未放开其提交权限，不能把其他受支持流程的验收当成 RefGen 真实受管提交已完成。

工作区与证据：`_demiflow/shared-review/workbench-runs-20261119/`；原始测试、截图：`/tmp/demiflow-workbench-runs-20261119-6pqhyldx/`。主仓只读，预览发布必须另行记录实际 HEAD 和 PID。

## 2026-11-19 左导航细化及组合验收发现

管道与运行使用同一个项目上下文。每个管道下的一行是一份 run，恢复产生的 attempt 留在该 run 内；不把恢复显示成另一条业务管道。未运行的管道仍在目录中。日期、状态和短 ID 帮助区分重复提交，ID 与封存快照绑定不变。桌面目录常驻左侧，窄屏目录保留为可滚动的顶部区域。

现有目录 API 按全项目分页，没有按入口建立索引。本版复用该 API：每次分支翻页最多读取 3 页、每页 20 条，过滤所选入口；不一次下载全部历史、不新建运行账本。没有匹配但仍有游标时如实提示继续查看较早记录，不能误报此管道从未运行；分支数值只表示当前载入数。P12 后续若补入口索引，可保持这个 UI 与身份契约，提高稀疏历史的查询效率。

P4 依赖登记、reader 和固定结果独立 Review 已通过。但 e6f954d 组合真实停止恢复验收得到 5 passed / 1 failed：CPU 原生容量根落在 executor 的 attempt 临时目录，supervisor 清理时选择了不同根，原容量域守卫拒绝恢复。该失败没有改测试绕过，完整证据为共享目录 `P4-managed-cpu-cleanup-blocker.json`。运行界面与导航可验收；停止恢复整条链路尚不能宣称在最终组合通过，需原容量/host 合同负责人共同处理。RefGen 原生受管提交仍按用户决定另做。

## 后续 UI 收窄（2026-11-19）

以本节覆盖上节的导航控件：移除“管道与运行”标题、搜索框、状态筛选、最近运行按钮、展开箭头、页码及翻页按钮。管道名为单行轻标题，运行记录为约30px单行（时间与状态）；身份留在tooltip、无障碍标签及右侧详情。每组先显示5次，使用淡色“显示更多”逐步展开，不自动全量读取。底层继续每次最多3×20条有界读取，呈现侧仅缓存run_id/entry/created_at/status，最多200条；深历史加载采用有界窗口，重新选择管道回到最新记录。

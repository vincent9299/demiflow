# 真实项目正式接入：方案复审与验收矩阵

日期：2026-11-03。状态：方案自审，不是独立审查或实施验收。配套：[架构方案](forge-project-onboarding-design-20261103.md)、[源码方案](forge-project-onboarding-source-plan-20261103.md)。

## 1. 自审依据与轮次

本轮读取了当前 workspace/server/checker/runs/worker、原生 query/sink/checkpoint/journal/model/preview/位置解析、两条业务入口及关键算子、DemiForge 标准和结构检查。未修改这些实现，没有运行真实模型、生产 pipeline 或更新演示服务。

| 轮次 | 发现的问题 | 已写入方案的修订 |
| --- | --- | --- |
| 1 来源与产品 | 只换 viewer root 无法打开非空仓库，也没有明确入口和多项目身份 | 非覆盖工作区初始化、稳定 ID、明确入口索引、单服务项目清单 |
| 1 数据边界 | 数据目录和平台 workspace 不同；历史大位置索引会被预览拒绝 | 原生精确解析、受限缓存、实际版本引用验证，禁止复制 demo 冒充接入 |
| 2 执行语义 | 漏了 reduce/count/save_lance/schema，而非只有模型契约缺口 | 列入原生能力表、源码责任表和负例验收 |
| 2 副作用 | 文件/图片读取藏在普通算子，纯类型声明不足以放行 | 显式原生资源节点，业务纯处理，保留 OP-06 边界 |
| 2 第三方依赖 | mwparser 对象和 PIL 不能凭注解当作可静态证明的业务函数 | 原生有界语法/媒体能力输出可检查结构，业务判断不进平台 |
| 2 动作先后 | 简单 DAG 展示会遗漏统计断言、写后读、覆盖完整性 | 带来源的 query/receipt 值、固定动作依赖、原生 guard；不新增执行 IR |
| 3 结果语义 | 将稳定 identity 输出改为 run 新表会改变业务契约 | 显式 CAS 更新与新表模式并存，隔离测试目标明确，禁止静默重定向 |
| 3 恢复 | 旧 action facts 唯一键不能承载多次尝试，取消后不能只重跑 Python | 原生日志 attempt 隔离与 CAS、同一 checkpoint、累计预算、旧 worker 拒绝 |
| 3 状态 | 进程成功不等于业务 complete，filtered 不等于技术失败 | 页面区分执行状态和业务摘要；业务状态不写平台分支 |
| 3 长期使用 | 128 条全扫、每轮遍历大表和短模型时限仍是演示限制 | 有界派生列表索引、本次写入计量、部署/工作区/运行预算与排空联合校验 |
| 4 通用性 | 为两个业务加入名称分支或 legacy adapter 会产生长期垫片 | 平台只接受通用契约，第三种非模型 Flow 验收，旧入口标准化后退出 |
| 4 规范冲突 | DemiForge 固定 config/run_pipeline 和 Notebook 与统一 flows 冲突 | 新候选标准与结构检查同步；旧版本/旧任务保留，不改规范文件制造旧通过 |
| 4 认证阻塞 | 256 MiB watch 限制不能通过缩范围或删输出绕过 | 完整流式快照和显式资源预算，先完成通用标准工具升级再启动迁移任务 |
| 5 同表更新 | checker 目前拒绝输入/输出同 URI，仅放开 runner overwrite 仍不闭环 | 固定旧版本读取与显式 CAS 更新共同校验；禁止动态 head |
| 5 索引完整性 | 源事实提交与派生索引不是原子操作，崩溃可能漏项 | 有界待更新标记、源事实复核和 CAS 清除；缓存不用于执行准入 |
| 5 规范资源 | 只增快照总额度仍可能在读取大 Notebook JSON 时失控 | 全文件流式哈希保护与有界结构解析分开，旧输出不删除 |
| 5 模型身份 | 配置中的 revision 不能证明实际部署 | 声明身份与实际部署/响应证据分别记录，真实运行前核对 |

这些是对实际代码和设计的自审修订，不表示已经通过下列测试。后续实现每阶段再次对照。

## 2. 保证边界

| 层 | 能够验收的保证 | 不能据此宣称 |
| --- | --- | --- |
| 项目登记 | 身份/位置/权限/入口明确，现有内容不被覆盖 | 任意登记代码已符合契约 |
| 静态检查 | 支持子集内签名、字段、拓扑、源码闭包、声明效果/资源一致 | 业务正确、真实模型质量、任意 Python 的形式化安全 |
| 实际计划核验 | 原生执行与封存报告/资源对应 | 全量执行已完成 |
| 运行时验证 | 实际值、返回类型、预算、版本、提交和恢复条件被检查 | 所有外部请求 exactly-once、多表事务 |
| 历史表/证据 | 固定引用可读、来源和缺失依据可追溯 | 当年代码满足当前契约或已有正式质量认证 |
| 隔离测试 | 对覆盖场景的业务等价性和技术边界成立 | 真实模型/全量性能已验收 |
| DemiForge handoff | 当前任务范围、版本和证据符合绑定标准 | 全仓合规或生产放行 |

## 3. 验收矩阵

| ID | 验收点 | 必须覆盖的正例/负例 | 通过标准 |
| --- | --- | --- | --- |
| GP-01 | 既有项目初始化 | 非空仓库、冲突文件、部分失败、重复操作 | 无覆盖、无业务执行、失败仅清理本次自有未提交内容 |
| GP-02 | 项目登记/隔离 | 两根同 alias/run、重复 ID、换根、越界、未登记请求 | 正确路由；不存在跨项目混读或共享 server.root 竞态 |
| GP-03 | UI 切换与同步 | 慢响应后切项目、外部改配置、未提交草稿、断线重连 | 旧响应不覆盖新项目；草稿与历史版本不被刷新替换 |
| GP-04 | 入口与配置 | 一个 Flow 多配置、helper、失效符号、未知参数 | 只展示登记入口，检查绑定正确配置，错误可定位 |
| GP-05 | 旧格式/链接 | 旧工作区、旧报告、旧 URL、未登记旧路径 | 只读保留原保证，不自动扩权/升级认证 |
| GP-06 | 精确位置解析 | 大索引、缓存失效、构建中变更、无映射、越界目标 | 原生一致解析；失败不回退其他表；时间/磁盘有界 |
| GP-07 | 真实数据预览 | 实际 identity@44392、summary@21、固定公共输入，嵌套标签与原始记录 | 原位固定读取；真实 Case 可见；不以临时复制样本代替 |
| GP-08 | 预览资源 | 宽行、超大对象、无索引搜索、多 fragment、慢 I/O | 先限范围/投影，隔离 worker 超限失败并可恢复；服务不被拖死 |
| GP-09 | 图片与证据 | 外部对象位置、哈希不符、符号链接、伪造 request_ref、敏感值 | 只能访问声明位置的合法引用；详情限制/脱敏有效 |
| GP-10 | 普通算子闭包 | 缺类型、借用输入写入、动态 import、隐藏读表/模型、第三方对象 | 缺保证时拒绝；声明/注解不构成豁免 |
| GP-11 | 归约/查询/guard | 重复键、join 扩行、超输入范围、统计后失败 | 真实原生统计和类型可核验；失败在后续模型/提交前生效 |
| GP-12 | 运行时值 | 伪 receipt、错误 stage、读 head、动态路径/拓扑、摘要超限 | 只消费真实且有来源的有限值；动态拓扑仍拒绝 |
| GP-13 | schema/空流 | 嵌套/nullable/字段顺序、物理类型、合法空输入 | schema 与原生一致；空表真实提交；非法 schema 不被降级 |
| GP-14 | 模型协议 | 文本/图片、单题/多题、乱序/缺答/未知 ID/非法概率 | 原始证据和单题错误保留；静态与 runtime 同一有效配置 |
| GP-15 | 模型预算 | 请求/重试/问题/字符/token/图片/字节/ledger/超时 | 各量纲独立，跨恢复累计；不会通过改模型名称获得豁免 |
| GP-16 | 模型独立性 | 两个配置/节点、第二节点误绑第一答案 | 输入绑定可见可测，业务要求的独立输入成立 |
| GP-17 | 写入所有权 | create 冲突、CAS 漂移、只读目标、共享 append、表外路径 | 提交前拒绝；旧版本和非本次字段不被误写 |
| GP-18 | 提交部分成功 | 明细已提交后 summary/引用登记失败、提交前后进程终止 | 真实 receipt 可核对，保留部分结果，不报全局回滚/全部成功 |
| GP-19 | checkpoint 恢复 | 整图/部分块已提交、图片错误、完整覆盖不足、外部改 head | 同一原候选重建，合法块复用，覆盖不足不写完成声明 |
| GP-20 | 恢复尝试 | 并发 resume、旧 worker 回报、配置改动、剩余额度不足 | CAS/attempt 正确；不覆盖旧事实；改绑定新 run |
| GP-21 | 状态语义 | 进程成功但业务未完成、低分正常完成、合法空结果 | 执行和业务字段分开显示，分母不因失败消失 |
| GP-22 | 长期列表 | 超过原 128 项、派生索引损坏/漏更新、分页中新增 | 有界分页；完整性提示真实；索引失败不破坏运行事实 |
| GP-23 | identity 等价性 | 完整标签/模型原始字段、未映射/重复/范围外、更新保留标签、导语规则 | 原语义与固定历史字段保持；隔离导入零模型调用 |
| GP-24 | 关系审核等价性 | 单关系、双侧阈值边界、分歧/缺答、多 accept、分块恢复 | 同固定输入得到预期完整明细/accepted；不触碰公共关系表 |
| GP-25 | 第三种业务加入 | 非模型多输入归约/多输出；不同字段与数据根 | 仅添加业务代码、配置、登记及 fixture，无平台业务分支 |
| GP-26 | 规范迁移 | 旧标准任务、Notebook 输出、大 watch、修改项目绑定后续接 | 新旧不混用，完整脏基线受保护，新标准检查/验证一致 |
| GP-27 | 消费者与分发 | 像素能力活动消费者、旧报告/表、安装包外 worker/UI | 活动导入和行为回归通过；封存源码/历史输出不改 |
| GP-28 | 同入口真实操作 | 固定端口服务重启、加入项目、查看 Case、显示新隔离 run | 无新 SSH 转发；重启后登记保留；无聊天/Notebook 依赖 |

## 4. 实施 Review 门槛

- P0 检查规范是否仍含相互冲突的入口/Notebook 要求，预算是否暗中缩小保护范围。
- P1 检查服务路由是否将用户输入当本地路径，数据是否偷换为复制样本，数据身份是否被展示配置污染。
- P2 对每种新原生能力同时检查签名、纯分析、真实计划事实、资源执行和失败测试；没有闭环就不批准受管运行。
- P3 对照原业务规则逐项检查数据流和 schema；搬迁不是重新设计业务的许可，不能删除失败记录或扩大过滤条件。
- P4 用实际工作区和独立第三种 Flow 检查通用性；浏览器演示、模拟调用、真实业务质量分别列证据。

发现失败修订对应阶段并复验受影响矩阵项，不为保住方案而降低检查。当前设计没有需要靠业务特例填补的执行入口；具体原生支持若实现中无法达到，必须保持诊断并返还设计 Review，不能交付伪通过。

# 工作区变化核验与后台巡检：设计复审与验收矩阵

状态：方案已批准并实施。本文保留设计复审与验收要求；逐项实际证据及尚未做出的保证见[实施记录](demi-workspace-audit-implementation-20261103.md)，不把下表的预期直接当作测试结果。对应[中粒度方案](demi-workspace-audit-design-20261103.md)与[源码级方案](demi-workspace-audit-source-plan-20261103.md)。

## 1. 源码核对结果

已核对 `workspace.py` 的元数据提示、封闭 workspace 格式、报告生成/绑定、实际状态核验与 per-Flow policy；`runs.py/run_worker.py` 的 prepare/start/resume、封存和执行锁；现有隔离 worker、report index、console registry、HTTP 字段/权限、Web 单同步链。

同时核对 DemiForge 的定位文档与 task/project 基线实现：其 task check 会写开发检查状态，不能由平台巡检反向调用。本文不以访问过这些源码为授权修改该仓库。

当前已有机制不被抹去：原生执行、固定表版本、sealed source、attempt CAS、预算、恢复和页面同步继续保留。新增范围约束解决“允许改哪里”，不能冒充原有业务规范和行为测试。

## 2. 第一轮：职责与完整性复审

| 发现的问题 | 修订后的决定 |
| --- | --- |
| 只看变化指纹，无法解释“预期外” | 报告依据与任务允许范围分开；scope 未启用必须可见 |
| 用最近文件/报告代替上次通过依据不可靠 | 显式 pin `(entry, 参数文件)` 对应报告；不使用 mtime/latest 推断 |
| 准备运行会产生有效参数的内联报告 | 不自动把它当作开发参数文件的巡检基准 |
| 重新检查可能把越界修改洗成合法 | 新报告只更新报告依据；任务内容基线不移动 |
| 上层已存在任务管理，再造一次容易漂移 | 平台只维护一份生效约束，使用中性导入；不维护任务/聊天状态机 |
| 平台直接读 DemiForge task.json 会反向耦合 | 平台定义通用契约；上层适配负责原基线导出，不在本平台实现私有格式识别 |
| 原 workspace v2 字段是封闭的 | 显式 v3；旧项目不静默迁移；审计字段与运行 scope 分别绑定 |
| 页面对每个项目启动计时器会重复工作 | 一个后台 watcher，UI 保留当前单同步链，不承担持续检查 |

## 3. 第二轮：执行正确性与竞态复审

| 发现的问题 | 修订后的决定 |
| --- | --- |
| 可选 request scope 可被遗漏 | scope 从当前工作区读取；CLI/HTTP 均不能靠少传字段关闭检查 |
| 当前 start 的重检查在 execution_lock 前 | 将最终有界 preflight 放入进入 starting 前的准入区，明确锁顺序 |
| watcher 缓存被伪造或服务停止 | prepare/start/resume 永远现场检查，不读缓存授权 |
| 切换观察报告使所有运行失效 | manifest 只绑定 scope 身份；观察报告集合不进入执行 policy |
| 工作区 audit 指向基线，基线再哈希原 workspace 造成自引用 | 固定投影只排除 audit；其结构/作用域由专门校验与运行绑定保护 |
| 旧 run 没有新范围字段 | 新 manifest v4；历史保留，新规则不补写到旧事实；升级工作区后旧准备需重新准备 |
| 修改工作树可能被误说成影响正在执行的代码 | 运行继续封存代码；后续启动/恢复复核，不自动杀进程 |
| 未合作编辑器不遵守锁 | 明示稳定读取/封存的能力边界，不宣称 workspace 事务或沙箱 |
| scope 坏了，连 cancel/reconcile 都被阻断 | scope 深读仅用于审计/准入；历史读取与恢复提交登记不依赖 scope 合规 |

## 4. 第三轮：成本、观测与兼容复审

| 发现的问题 | 修订后的决定 |
| --- | --- |
| 报告被外部改写但 index 不变 | 直接读取 pin 对应报告并验证 digest；周期完整核验不依赖 index 变化 |
| mtime/size 相同被当作内容不变 | 快速标记只触发；定期和准入必须读取内容 |
| 将每 5 分钟写成所有规模保证 | 明确是调度目标；每对象显示核验年龄、due/overdue 和待检查覆盖 |
| 一个 HTTP 请求串行扫所有报告 | 每请求检查一个对象；CLI all 有总 deadline，返回未完成对象 |
| 大 Notebook 或权限错误被跳过 | 限额前置、流式哈希；超限/不可读为未完成，不是通过 |
| 只看 PID/心跳让旧结果长期绿 | 心跳与每项 verified_at 独立；时钟异常亦保守显示 |
| 界面“最近检查”其实只是轻量同步 | 改为“最近同步”，另显示最后完整核验时间 |
| 新结果自动登记引发整个任务违规 | 作者范围排除运行资产；报告核对其实际依赖表引用；无关新增结果不误伤 |
| 基线 import 重拍当前文件，清除原越界 | 仅接收真实原基线；无法等价转换时拒绝导入，不声称已覆盖原任务 |
| 内容缓存写入被叫作完全无副作用 GET | GET 只读；显式 POST 核验只写派生观察缓存；权限、重试语义明确 |
| 已登记报告被移除入口后，无法退出观察集合 | 提供显式 unbind/CAS，保留历史报告；缺失或失效不自动换基准 |

复审后的设计满足分层目标：下层 audit 算法不依赖 workspace/HTTP，workspace 为公共用例，runs 在原准入层加检查，watcher 仅调度观察，Web/插件仅消费协议。仍需实现后测试与代码 Review 才能验证实际正确性。

## 5. 验收矩阵

| ID | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| AU-01 | 开始前已有 dirty、untracked、Notebook 输出 | 基线保留当前内容；不把它们当成本任务新增；不修改原文件 |
| AU-02 | 修改允许文件 | 范围内；相关旧报告 stale；真正重新检查后可以准备 |
| AU-03 | 修改未允许文件 | 明确越界；CLI/HTTP prepare/start/resume 均拒绝 |
| AU-04 | 越界后重新 inspect | 可生成新的检查结果，但范围违规仍存在；不得执行 |
| AU-05 | 新增、删除、改名、文件/目录替换、空目录 | 全部被比较；改名按删/增检查；授权父目录不能掩盖违规子项 |
| AU-06 | 读取中替换/修改文件、目录、控制 | 检出竞态时 incomplete/拒绝；无错误通过、无无限重试 |
| AU-07 | symlink/FIFO/越界路径/与数据根重叠 | 在读取分配前拒绝，不能跟随至任意路径 |
| AU-08 | 修改另一条无依赖 Flow | 当前 Flow 报告保持原判断；如违反生效任务 scope，单独显示范围拒绝原因 |
| AU-09 | 正常新增运行结果表引用/账本推进 | 不产生作者范围违规；相关视图仍通过原变化链更新 |
| AU-10 | 无 UI、无 watcher，从 CLI 准备/启动 | 仍现场核验；越界和实际失效不能靠页面关闭绕过 |
| AU-11 | 将缓存改为全部通过，或删除缓存 | 准入不受影响；观察状态不能冒充执行授权 |
| AU-12 | prepare 后改 scope、改源码、改原参数 | start 冲突/拒绝；不自动用最新 scope 或另一参数重试 |
| AU-13 | 在 preflight/starting 边界注入正式控制更新 | 锁/CAS 阻止旧依据准入；明确同一 attempt，不重复启动 |
| AU-14 | 运行中改工作树 | 已运行代码保持封存；后续恢复复核；已有结果不删除 |
| AU-15 | 违规时 cancel/reconcile/历史查看 | 仍按原身份和提交核对工作，不能连清理/恢复证据都锁死 |
| AU-16 | 手工改写或删除 pin 报告，index 不变 | 周期完整核验发现报告身份错误/不可读；不选择另一报告补位 |
| AU-17 | 同尺寸修改并恢复 mtime | 完整核验仍比较真实字节；轻量同步不算通过证据 |
| AU-18 | 表旧版本不可读、平台快照失配 | 明确依据失效或无法核验；不偷偷读取最新表或重绑平台 |
| AU-19 | 关闭所有页面，修改工作区 | watcher 在预算允许的轮次形成新状态；重新打开读同一结果 |
| AU-20 | 停掉 watcher、重启 watcher、时钟异常 | 显示超期/未知与独立时间；重启需复核，不刷新旧绿灯 |
| AU-21 | 两个 registry/客户端同时扫描同工作区 | watch/审计租约控制重复扫描；忙有界返回；不阻断现场准入 |
| AU-22 | 一个慢/大项目和另一个小项目 | 单对象超时后轮转，小项目可前进；过期项明确，队列/并发有界 |
| AU-23 | 文件数/字节/深度/输出/磁盘达到小预算 | 分配前拒绝/有限终止；结果 incomplete；不跳过文件制造通过 |
| AU-24 | scope 基线损坏/丢失/超限 | 准入拒绝，观察状态明确；旧运行查看/取消不依赖该基线可读 |
| AU-25 | 旧 workspace/run 与显式 v3 升级 | 不自动迁移/补写；旧运行历史可读；新准入要求可解释 |
| AU-26 | inspect --track 保存成功但绑定 CAS 失败 | 报告保留，绑定未变，回执说明两者；无自动重试 |
| AU-27 | 导入旧任务基线，其后已有越界修改 | 导入不重拍当前树；越界保持；不兼容投影/范围明确拒绝 |
| AU-28 | 单独改变 pin 报告/巡检心跳 | scope digest 不变；不使准备运行或其他 Flow 语义失效 |
| AU-29 | Web、插件协议客户端、CLI 同看工作区 | 相同身份/覆盖/时间；草稿、固定历史选择保持；无宿主专有字段 |
| AU-30 | 失败、断网、认证错误、旧响应迟到 | 不自动重发 POST；按已有 epoch/attempt/CAS 规则处理 |

两条真实 pipeline 的验收以登记入口/参数为身份，读取其检查依赖与真实配置；任何故障注入、范围违规、数据写入都放在隔离工作区副本或 fixture。第三种 Flow 验证通用性，不添加按项目名或算子名分支。真实模型调用、生产跑数和原 training/ 修改均不属于此验收。

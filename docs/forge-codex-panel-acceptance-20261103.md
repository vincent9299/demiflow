# Forge 与 Codex 面板联动：实施与验收

日期：2026-11-03。依据：[中粒度方案](forge-codex-panel-design-20261103.md)、[源码级方案](forge-codex-panel-source-plan-20261103.md)、[验收矩阵](forge-codex-panel-review-20261103.md)。

状态：获批代码已落地，自动化回归及分发验证通过。用户已批准更新原演示入口，服务已更新且原控制文件/历史记录摘要不变。真实 Codex 宿主的注释发送与站点工具调用单独验收，不能以注入测试代替。

## 1 用户得到的能力

- Case、检查报告/节点、运行/节点有明确位置；复制链接、刷新和前后导航可以恢复位置。
- 表详情、图片和工具续读核对同一个固定绑定；旧别名换绑、位置变化或当前源码偏离报告时，明确拒绝混用。
- 支持原生注释的 Codex 页面可从具体卡片发起讨论，引用绑定点击时的对象。
- 支持 Site Tools 的客户端可注册四个只读工具，读取当前位置、定位页面、按字段读 Case、刷新依据。
- 编辑与看结果仍用原工作树、原检查器和原执行路径；准备、运行、结果对照、继续加工保持原有操作。
- 无宿主 API 时可正常独立查看；离线报告仍不连接工作区。

## 2 最终职责及改动范围

| 模块 | 实施职责 |
| --- | --- |
| `workspace.py` | 新增 `preview_binding`、`describe_table`，采样传递可选预期身份；保留旧控制引用摘要 |
| `workspace_worker.py` | table/sample/media 一次解析 ref/URI，核对预期摘要后消费同一结果 |
| `workspace_view.py` | 只读单表描述、封闭 query、图片身份头、当前源码 hash、静态资源与离线导出 |
| `workspace_cli.py` | show/sample 支持 `--expected-binding`，复用相同工作区 API |
| `web/view.js` | 无 DOM/网络的视图规范、验证、URL 编解码和有界引用 |
| `web/app.js` | 页面状态、选择、草稿、请求代次、原 HTTP 和页面渲染 |
| `web/codex.js` | 官方 API 能力检测、工具注册和注释；只接受 app 的四个回调 |

仅新增两个生产 JS 模块。没有 Codex SDK、MCP 服务、App Server、第二执行器、数据库、业务注册层或聊天同步。运行层、Dataset、原生预览和平台快照过滤规则未因本次集成修改。wheel/sdist 原有资源规则已覆盖新文件，无需改打包配置。

## 3 分阶段 Review 及修正

1. 身份与后端：把 CLI 的描述入口归入 workspace；control digest 与 preview binding 分开；media 在同一 worker 使用已解析引用，响应头携带真实摘要。故障注入验证核对后 alias 改变仍消费原 ref。
2. 页面与宿主：共用页面操作和视图规范；token 只留会话存储，不进入复制链接/工具上下文；row_id 全链保持字符串；注释使用可见 HTML 卡片与最多六个扁平字段。
3. 竞态和生命周期：加入页级读取取消、同表选择代次、源码响应代次、固定图片绑定和工具并发拒绝。草稿不被工具切换配置覆盖；POST 不因刷新重发。
4. 深度复审：补测首次 Case 尚未加载时再次选行、失败目标刷新、运行节点与 A/B 页刷新、HTTP 空摘要/未知 query、图片身份头、离线资源完整性及工具并发。新增反例曾复现“Case 已切换但 URL 仍为总览”，以修复后的测试结果作为最终证据。

以上为本次实施的自审与测试，不声称独立审查。

## 5 保证范围

preview binding 保护受管读取的身份，不锁定外部文件系统，也不固定外部图片字节。工具 64 KiB 输出限额不等于 native 分配或进程 RSS 限额。草稿只保留于当前页面生命周期；浏览器整页刷新不承诺持久化。取消页面 GET 不等于取消运行。

注释 `accepted` 只证明宿主接受打开请求；工具注册成功只证明页面完成登记。是否发送、是否获权、模型是否调用，以实际宿主行为为准。离线 HTML 不携带宿主模块。

升级 UI 也会改变现有平台快照。本次不放宽快照门禁，不重绑原演示工作区。用户明确批准后仅重启原查看服务；历史运行/报告保持原样，当前报告需要按既有规则复核。临时 59901 演示服务已停止，保留原入口，避免要求用户维护额外转发。

## 7 用户意图修订与刷新问题修复

用户随后明确：始终在 Codex 对话，操作台只需与工作区事实保持一致，不需要 Case 对话流程。后续目标及验收改用[共享工作区修订方案](forge-shared-workspace-panel-design-20261103.md)。原 CP-18 未完成的实际调用部分保留历史状态，不再推进为新功能门槛。本轮未实施新的周期同步。

“刷新当前视图”故障现场：59865 无监听进程，原临时工具会话返回退出码 143。浏览器保留已显示内容，但后续读取连接被拒绝。已在原端口恢复现有查看服务，使用独立进程会话、标准输入关闭、输出写入本任务日志，启动工具退出后 PID 仍在运行；没有新增服务层、端口转发或改动工作区数据。

恢复服务后还复现了重复刷新问题：页面重新可见自动刷新未完成时点击手动刷新，会出现 `busy：页面仍在读取`。修复如下：

- 同一页的重复刷新共用一个在途 Promise；无额外队列、自动重试或写操作重放。
- 切页后旧刷新不会改写新页状态。
- GET 连接失败显示可理解的重试提示；POST 无响应提示核对操作结果，不声称写操作未发生。
- 按钮重试清除自身上次错误，恢复后不遗留旧报错。

证据目录 `/tmp/forge-panel-refresh-20261103`：`reproduce.log` 记录恢复服务后普通刷新正常、并发刷新触发 busy；`after.log` 对应两个场景均无错误；`tests.log` 为 **5 passed / 137.98 秒**，覆盖刷新合并、断网恢复、深链接/无效节点、Case 乱序及既有工具刷新回归。新增测试 2 项，未重跑全仓或重复宣称原生宿主调用通过。原入口仍为本机 55971 → 服务器 59865。

# Forge 第二阶段工作区与可见组合设计

日期：2026-11-01。状态：过程稿，未实施，已由 [2026-11-02 接线契约与工作区方案](forge-stage2-contract-design-20261102.md) 替代。后续 Review 和实施以新方案为准；本文保留设计演变的追溯信息。

第二阶段交付一个能独立浏览项目、找表、看 case、查看和比较加工组合的工作区。工作区、数据表、case 和加工组合是核心对象；人可以直接使用统一界面，coding agent 使用同一组底层接口。组合接线集中维护在 flows/，图与检查报告从代码派生。

Flow 是通过平台 API 表达的标准接线程序，必须通过契约检查；不是把任意 Python 放进指定目录后尽量画图。Operator 承担平台节点内部的业务计算，不得隐藏另一段数据流程或接管执行器职责。灵活性来自平台能力的组合和参数变化；能力不足时扩展原生平台契约，不通过普通函数绕过。

可视化是本阶段的核心交付。用户无需 agent 解读或打开 Notebook，就能了解项目用途、查看实际数据内容并定位对应接线。Notebook 和普通脚本均可作为辅助使用方式，不决定平台的对象和界面设计。

## 1 交付范围与用户结果

| 完成本阶段后可以做 | 本阶段的保证 |
| --- | --- |
| 建工作区，接入本地或共享源表 | 明确物理位置、只读边界及固定版本，接入不复制表 |
| 在统一界面看表、case 和对应材料 | 查看文本、图片、表格与原始字段；按需读取，固定版本并限制解码和展示规模 |
| 脱离 agent 了解项目 | 项目说明、表用途、组合用途、接线和诊断可独立浏览，信息来自保存的项目内容 |
| 由人或 coding agent 编写多个原生组合 | 同一工作区可有多个文件、函数和方案，不要求唯一 Pipeline |
| 检查接线和查看连接图 | 展示输入、转换、多输入关系、条件分支、物化和计划输出，定位源码与缺口 |
| 修改方案后比较 | 区分代码变化、表绑定变化和连接变化，旧报告不被改写 |

本阶段不接通 Forge 新格式的业务执行、局部重跑、运行状态叠加、正式 Verify/Freeze 或生产发布；它们分别在第三、四阶段接通。表元数据读取和显式样本读取属于本阶段允许的只读操作，候选业务代码、模型请求和服务启动不属于检查或绘图过程。

本阶段的 case 审阅是浏览和对照，不包含通过/驳回、评分、修改原始数据或多人审核记录。后者需要独立的数据写入契约。本轮不实现 Agentic 自主编排、拖拽编辑器、远端统一 Catalog 或自动数据清理。

## 2 架构与权威来源

```text
工作区说明 + 表引用 + 组合绑定 ──────────────→ 项目总览、表与组合导航
固定表版本 ─→ 有界只读数据接口 ─────────────→ case 浏览、材料查看与对照
组合源码 + 当前 API 语义 + 工程标准 ─→ 静态检查报告 ─→ 接线图、诊断与源码
                                               ↑
                     CLI / Python / 本地工作区界面共用接口
```

| 内容 | 权威来源 | Forge 职责 |
| --- | --- | --- |
| 真实表数据和版本 | Lance 表本身 | 按明确位置与版本检查、读取元数据和受限样本 |
| 已登记的表版本 | 原生 Catalog | 有界查询，不另造一套数据登记系统 |
| 工作区中的表名 | 工作区的固定引用文件 | 把可读名称绑定到位置和 DatasetRef，名称不是数据身份 |
| 接线与控制逻辑 | flows 中符合接线规范的平台 API 调用 | 按契约检查并提取；不从任意代码猜测合格流程 |
| 项目与组合用途 | 项目说明、组合说明与函数 docstring | 原样呈现来源；没有说明则标明缺失，不靠 agent 猜测 |
| 接口签名和连接语义 | 平台公开 API 及其就近声明 | 动态发现，不在 Forge 写第二份方法名单 |
| 图、诊断和比较 | 同一次检查生成的报告 | 保留来源与摘要，不允许手改图来修改流程 |

整个设计不新增 Dataset 代理、业务 operator 基类、注册装饰器或执行引擎。参数绑定负责提供普通值，原生 Dataset API 负责表达加工。

## 3 工作区结构与所有权

登记组合的主数据接线及组合 helper 集中在 `flows/`，其中可有多个入口和文件。目录规范不限制节点数量或排列。既有项目接入时需明确并统一接线目录，不能让同一个组合依赖散落在 Notebook cell 中的补充接线。

```text
workspace/
  README.md                     # 项目用途与使用说明，界面直接展示
  workspace.json                # 工作区 ID、数据位置、平台绑定
  tables/
    gt.json                     # 固定版本引用，非表数据
    labels.json
  flows/
    questions.py                # 平台 API 接线、默认参数与 A/B 入口
    questions_a.json            # 参数较多时就近保存，可选，不包含 nodes/edges
  operators/
    text.py                     # 普通业务函数或 actor
  configs/                      # 按需存在的原生配置
  data/                         # 默认数据根，真实 .lance 表在这里
  .forge/
    platform/                   # 不可覆盖的平台快照
    inspections/                # 按摘要保存的派生报告和 HTML
  runs/                         # 第三阶段使用，本阶段不生成伪运行记录
```

`flows/` 通过平台 API 连接 Dataset，并就近维护默认参数、变体和必要配置；`operators/` 保存符合节点调用契约的业务函数或 actor。取消独立的 compositions 目录和管理层。少量参数直接在 flow 入口中表达，较长的参数文件与 flow 放在一起，不要求每组参数都生成文件。

Notebook 本质也是代码，可自行放在辅助目录，默认不要求创建。它可以调用 flows 的入口、查看数据或开展探索，但不承担登记组合的隐藏连接或内存依赖。这里按职责区分，不把 Notebook 统称为第三方代码，也不要求项目采用 Notebook。

工作区配置拟用 `demiflow_forge_workspace_v1`，关键字段是 `workspace_id`、`locations`、`default_output_location` 和平台快照引用。每个数据位置具有独立 `location_id`、root 和 `read`/`read_write` 模式。默认 `local` 指向工作区相对的 `data/`；外部位置显式绑定绝对本地路径，初版只允许只读接入。

平台绑定指向有内容摘要的快照文件。更新平台版本是明确的重新绑定操作，不在每次检查中悄悄刷新。

`workspace init` 只创建指定工作区的缺失控制文件和默认目录；已有文件冲突即停止，不覆盖业务源码、AGENTS.md 或数据。外部根必须已经存在，初始化不创建或修改外部目录。

工作区没有唯一业务 request。README 描述项目用途，每个组合可保存简短 title/description，业务函数 docstring 说明步骤含义；这些是说明文字，不是另一套接线。缺失时界面明确显示“未说明”。正式交付的需求审批在第四阶段绑定。

工作区根不能成为所有业务文件的无差别快照边界：检查只绑定选定组合、其源码依赖、配置、使用的表引用和数据位置。项目说明另行绑定展示版本；其他实验变更不会改写该组合的历史报告。辅助代码是否影响实现身份由实际依赖决定，不能仅凭目录名排除。

## 4 数据表与固定引用

### 4.1 表实际在哪里

真实表默认位于 `workspace/data/`。共享表可以位于另一个显式绑定的数据根，例如 `shared_gt → /data/ground_truth`。表引用使用相对于该根的位置，所有读写目标最终解析为明确的绝对路径，不依赖 shell 或 Notebook 的当前目录。

工作区引用拟用 `demiflow_forge_table_binding_v1`，仅包含 `location_id` 和原生 `DatasetRef` 等绑定信息；alias 由引用文件名确定。DatasetRef 的现有字段、序列化格式及登记主键保持不变。

现有 `DatasetRef.resolve(root)` 由调用方提供 root，`identity` 没有包含工作区的位置范围。因此 Forge 的检查必须同时绑定 `location_id`、实际 root 配置和原生引用，不能把不同根里同名、同版本的表当作同一表，也不重写 DatasetRef 的 store_id 来伪装全局解析。

更改数据根是显式重新绑定，需要重新核对表；受影响的检查报告失效。同样的行数、schema 和版本号不能证明两个物理目录内容相同。第二阶段不默认全表计算内容摘要，也不把元数据核验称为数据内容认证。

### 4.2 接入与刷新

1. 用户指定 alias、数据位置、相对路径和版本。若显式选择 `--head`，工具只在此次接入中解析 head，并立即保存具体整数版本。
2. 使用原生表检查读取 schema、实际版本及行数，创建固定引用；已有 Catalog 记录可用时核对它。
3. 已有 alias 不被覆盖。刷新版本使用显式 replace，并校验调用者提交的旧绑定摘要；冲突返回 conflict。
4. 运行检查始终使用已固定版本。源表出现新版本不会使旧固定引用自动指向新数据；旧版本不可读时明确失败，不退回 latest。

接入共享表只写工作区引用，不写对方 Catalog。未在原生 Catalog 登记的表可以被只读接入，报告明确其登记状态；这不等于正式发布登记。工作区引用目录不存储另一份业务数据或虚构表版本。

原生 DatasetRef 必须携带 dataset_id、schema_name 和 schema_version：已登记表从明确匹配的 Catalog 记录取得；匹配不唯一时要求选择 dataset_id。未登记表首次接入需显式提供这三项声明，不能用 alias 或工具版本冒充业务 schema 版本。工具读取并核对实际 Lance 版本、schema_hash 和 row_count；业务 schema 名称/版本标为用户声明，不能据此宣称业务验证通过。`inspect_lance` 本身不返回行数，行数通过同一固定版本的原生 count_rows 获取。

alias 是可显式更新的便捷入口，报告保留当时解析出的固定引用。更新一个被 A/B 共用的 alias 会使两者的新检查都使用新绑定，并使旧报告相对当前工作区过期；要让 A/B 长期使用不同版本，应分别绑定 `gt_v3`、`gt_v4`。历史报告内容始终不变。

`table list` 默认列出已绑定 alias；可显式选择一个位置，分页查询该位置原生 Catalog 的已登记版本。初版不递归扫描磁盘寻找所有 `.lance` 目录。数据根中存在但未接入的表不会被默认为已授权输入。

### 4.3 输出目标与生命周期

组合绑定可以声明默认数据根中的输出位置。输出的 mode、expected_version、schema 等执行参数写在原生调用里，绑定文件不重复保存同一组参数。

第二阶段只检查目标位置、访问模式和已知冲突，不创建业务表。图中的输出是“计划输出”，没有 committed_version。第三阶段写入成功后才依据真实回执生成输出引用和登记。

取消 alias 或删除组合不会删除表；删表、版本回收和跨位置搬迁不在本阶段命令中。只读位置不能通过别名、符号链接、路径跳转或重定位映射变成输出位置；解析后仍需核对最终路径归属。

### 4.4 Case 浏览与对照

case 首先是一张固定版本表中的一条可定位记录；不要求新增 Case 数据库或把整行复制成另一个业务对象。浏览位置绑定数据根、表引用、Lance 版本和原生版本内的行定位信息。显示行号不作为跨版本或跨表身份。

打开表后按需分页浏览，列表优先读取用户选择的摘要列；点击记录再读取选定字段。schema 查看不读行。首轮支持文本展开、图片缩略与放大、结构化字段/小表格、原始字段，以及上一条/下一条。显示顺序可选择；不写死 question、answer、image 等业务字段名。字段类型来自 schema，业务显示用途可由用户选择，不引入另一套业务 schema 或可执行视图脚本。

输入输出或 A/B 对照必须选择明确的关联字段与固定表版本。初版支持等值查找；无匹配、重复匹配、缺少对应关系都明确展示，不按行号拼接、不默认取第一条、不推断血缘。复杂一对多组织由已有业务数据表达，查看器不增加业务 join 规则。

列表默认最多 20 行、16 列、展示总计 256 KiB；详情投影选定字段，文本默认展示前 16 KiB，展开仍受单次读取预算约束。截断标记只表示展示范围，不改变原数据。固定宽度列按宽度和批次准入；变长字段须有可核对读取上界或原生分块读取能力，不能先完整解码巨大字段再截断。若当前 Lance 接口无法在分配前控制所需表示的读取，需要在所属数据模块补足能力，或明确报告该字段暂不可浏览；普通受限文本和图片应作为实际验收项，不能仅交付 schema 查看。

图片按明确选定字段查看。外部文件只从已绑定位置解析，先检查文件大小和图片头，再限制解码像素并生成缩略图；初始上限为原始文件 8 MiB、16 百万像素、缩略图 512 KiB。内嵌二进制同样受读取准入约束。普通字符串不自动作为远端 URL 或本机任意路径读取。外部媒体没有固定内容身份时标明“媒体未固定”，不因表版本固定就宣称图片也不可变。

数据读取通过隔离进程处理原生分配，设时间和输出上限并清理资源；编码大小不宣称为 RSS 硬上限。绘图不触发 case 读取。导出时只包含用户显式选择、通过预算检查的 case；默认仅导出结构与元数据。浏览本身不写回原表，也不保存审核结论。

## 5 组合入口与接线标准

### 5.1 平台 API 接线与就近参数

一个 flow 选择 flows 内明确的公开入口，以 Python 作为调用平台 API 的载体。入口、参数和变体在同一接线目录内维护，不要求继承 PipelineProgram，也不提供新的 Forge 上下文、Dataset 代理或业务注册体系。多个入口可以调用同一个受检查的接线 helper，并传入不同参数。

首轮入口为同步函数，参数能以关键字明确绑定；不透明装饰器、位置专用参数或动态参数装配不作为完整检查入口。默认值仅允许静态可解析的普通值。代码按正常 Python 包组织，示例中的 flows/operators 可包含 `__init__.py`，不创建 Forge 专用模块加载协议。

入口的实际参数可以通过界面/命令明确提供；需要保存时，在 flows 内使用可选的 `demiflow_forge_flow_parameters_v1` 参数文件。参数支持四种绑定：`value` 为有限 JSON 值，`table` 引用固定 alias，`output` 指定自有数据位置内的目标，`resource` 指向明确配置文件。表解析成普通 `{uri, version}` 值，输出解析成普通 `{uri}` 值，资源解析成明确文件路径。无论是否保存文件，检查报告都绑定本次完整参数；这不形成独立的组合注册层。

绑定文件不保存操作列表、连线、平台参数 schema 或第二份执行顺序。示意：

```json
{
  "format": "demiflow_forge_flow_parameters_v1",
  "arguments": {
    "gt": {"kind": "table", "alias": "gt"},
    "labels": {"kind": "table", "alias": "labels"},
    "target": {"kind": "output", "location_id": "local", "relative_uri": "questions/a.lance"},
    "min_score": {"kind": "value", "value": 0.8}
  }
}
```

对应代码仍然直接调用原生接口；以下代码仅是待检查的源码，本阶段不会调用 compose：

```python
from demiflow import data
from operators.text import normalize_title, score_at_least

def compose(*, gt, labels, target, min_score):
    source = data.read_lance(gt["uri"], version=gt["version"])
    normalized = source.map(
        normalize_title, inputs={"text": "title"}, output="clean_title"
    )
    metadata = data.read_lance(labels["uri"], version=labels["version"])
    joined = normalized.join(metadata, on="id")
    selected = joined.filter(score_at_least, fn_kwargs={"minimum": min_score})
    return selected.write_lance(target["uri"], mode="create", return_receipt=True)
```

normalize_title 和 score_at_least 在 operators 中实现。前者按原生 inputs 接收 text，后者按原生 filter 接收 row 和 minimum；flow 只传引用和参数，不直接处理记录。其返回值类型若仅来自 Python 注解，图中标为声明类型，不能视为数据验证。将来执行仍调用同一入口和原生执行器，不解释查看用图来重新搭建流程。

### 5.2 Flow 与 operator 的职责约束

| 层 | 负责 | 不允许承担 |
| --- | --- | --- |
| Flow | 用平台 API 声明输入、转换、关联、模型节点、物化和输出；传递 Dataset 与明确参数 | 自行迭代表处理记录、直接调用业务函数完成表级加工、直接调用模型客户端、私有线程/任务调度、隐藏数据连接 |
| Operator | 处理原生 API 指定的行、批次或 actor 调用，遵循输入输出及生命周期契约 | 内部另建 Dataset 流程、隐式读写业务表、隐藏模型阶段、自己管理跨节点并发/重试/调度 |
| 原生平台 | API 契约、节点效果、执行策略、资源预算和实际执行 | 将业务接线名单硬编码进 Forge，或要求业务复制一套平台契约 |

Operator 继续使用原生 fn/actor 形式，但必须有明确的调用签名、消费与产出结构、资源及副作用边界。原生 inputs/outputs、已有 schema/config 和函数签名能表达的内容只维护一次；不增加平行 YAML 算子目录、强制基类或业务注册装饰器。必要的资源访问使用平台已有资源/工具协议，普通计算节点不能用一个 map 包住整个 pipeline。

内部业务算法可调用计算库、拆分辅助函数；这不授予它自行组织表级数据流或外部调度的权限。缺少平台能力时先在所属原生模块增加版本化契约、实现与测试，再由 flow 组合。

### 5.3 硬检查与通过条件

| 规则 | 检查内容 |
| --- | --- |
| 平台 API 接线 | 每个主数据步骤必须解析为当前平台承认的 API，或展开为同样受检查的 flow helper；普通不透明调用不能作为合法连接 |
| 输入固定 | 表输入来自明确绑定或可核对的原生固定引用；缺省 version=None 标为未固定 |
| 输出显式 | 目标和提交调用可定位；已知路径不能逃离允许写入的位置 |
| 主数据依赖可见 | Dataset 的来源、传递、多输入和产出可以追踪；不靠隐藏内存状态解释连接 |
| 原生参数契约 | 参数名、位置与必需参数依据当前 API 目录，字段绑定遵循原生含义 |
| 职责明确 | 表级加工与调度属于平台节点；普通行函数/actor 不得隐藏数据接线，模型请求使用原生模型节点 |
| 名称与身份分开 | 变量名与可选原生 label 用于阅读；不作为缓存或数据复用证明 |
| 物化明确 | 共享计算节点不等于共享执行结果；需要持久复用时显式 checkpoint/写表 |
| 缺口阻断 | 未解析主连接、未知节点效果、动态数据来源或确定的越界均不能通过；诊断图仅用于修复 |

硬检查按证据分工：第二阶段阻断接线语法、API 来源、签名、字段绑定和可确认的越界；operator 的输入输出与行为由契约测试验证，实际执行的权限/预算由原生运行机制约束，后续阶段接通。不能宣称 AST 能证明任意第三方 Python 没有隐藏副作用；尚未验证的 operator 边界必须单独列出，在完成对应门禁前不放行受管执行。

同一入口和参数必须能得到完整的标准连接事实。已知违规返回 invalid；无法确认或超限返回 incomplete，两者都是未通过。可显示局部图用于定位错误，但不能作为合格 flow，也不能靠“先运行再记录”绕过接线契约。

### 5.4 接线语言的支持范围

接线层仅接受平台调用、赋值、明确参数、静态 import/别名、受同一规范检查的 flow helper，以及传给平台节点的 fn/actor 引用。多个输入、多个输出、共享 Dataset 变量、join/union 等都通过原生 API 表达。登记组合不反向依赖 Notebook cell、kernel 状态或辅助脚本追加的步骤。

常量求值只解释白名单内的字面量、绑定值索引和有限比较，不调用 Python eval、repr、自定义比较方法或属性。import 按明确的工作区包与已绑定平台来源解析；不从任意 sys.path 猜同名模块，名称遮蔽不能把普通对象误判为 Dataset。

参数已绑定、结果可确定的 if 和有限 for 只能用于装配平台调用；for 首轮最多展开 32 次。这是构建前可确定的接线，不允许通过读取业务行、运行模型或任意计算来决定下一步拓扑。按行筛选使用平台 filter 等能力；运行时流程控制需有对应平台 API 和明确契约后再支持，不把普通 Python 分支自动视为平台控制节点。Operator 内部的业务逻辑作为该平台节点的实现关联，不展开成行级流程图。

反射选方法、eval、动态 import、从运行数据生成拓扑、不可解析的 kwargs、未绑定全局状态、递归组合和不确定循环均不能作为本阶段合格接线。目录中的普通实验代码仍可保留，但平台不能把它当作已通过契约的 flow。动态组合意味着可以修改平台节点、连接和参数，不意味着接线层接受任意 Python。

## 6 原生接口语义与第一阶段的扩展

现有平台目录的 native_semantics 为 unknown。真实签名能校验调用形状，但不能证明 `checkpoint_lance` 会提交数据，也不能仅凭返回 Dataset 推断全部输入关系。原生 LogicalPlan 只描述部分单 Dataset 计划，实际构建还可能发生 import、配置装配或元数据读取；第二阶段不运行候选代码来取得它。

本方案选择在原生 API 定义所在模块补充只读连接语义，Forge 统一读取。声明使用版本化 `demiflow_api_flow_v1` 数据，至少描述：receiver 是否为 Dataset、哪些参数接收 Dataset、返回值形态、表 URI/版本参数角色、物化/写入/模型请求等效果，以及配置资源参数的角色。字段引用必须对应真实签名；普通参数类型与默认值不再抄一遍。

声明就近绑定原生函数，不使用全局运行注册表，不要求业务 fn/actor 增加装饰器。签名或声明缺失的 API 仍可出现在目录中，但不能据此作为通过接线检查的节点。初始覆盖原生表读取、转换、多输入组合、checkpoint、sink 和模型节点；能力来源是平台实现及其契约，不是 Forge 写死的方法或三节点排列。

原生测试负责验证声明与实际实现一致。新增公开方法并提供同版本连接语义后，目录、检查器和通用图节点应自动接入；无需在 Forge 添加方法名分支。特定 schema 变换如 join 字段合并、投影、原生 inputs/outputs 映射的规则归原生 API 所有，无法推导时明确 unknown。

声明表达连接角色，不排列业务步骤。例如 join 只声明 Dataset receiver、Dataset 参数 other 和 Dataset 结果；输入来自哪两个变量、它前后连接哪些调用，由候选源码决定。声明采用有限数据字段，不接受分析回调。首轮只推导元数据和可验证的字段保留/映射等关系，不建设通用 Python 类型推断器；尚无可靠原生规则的 schema 变换保持 partial/unknown。

为保存新增语义事实，平台目录和快照升级到明确的 v2 格式，复用第一阶段的发现、哈希、进程和差异机制。旧 v1 按原格式和范围验证；比较时构建相同格式的当前事实，不能把旧 unknown 升格为已知或静默改写旧快照。工作区初始化绑定 v2；已有 v1 对象需显式建立新绑定。只做已知格式分派，不引入版本插件框架。

保留旧格式的可读取、可比较能力不等于旧快照继续 current：本次平台源码变更会按第一阶段的内容身份规则使旧绑定 stale，需要明确重新绑定。

工程标准内容更新版本：FE-02 明确工作区可多入口、每次提交入口明确，并记录本阶段静态覆盖。新增公开命名空间 `demiflow.lance`。全部变化要由新快照和兼容回归覆盖，不影响已保存证据的内容。

## 7 纯静态检查与结构报告

处理顺序固定：读取工作区与选定 flow → 解析固定参数和表引用 → 有界读取代码/配置 → 按接线语法检查 AST 与 API 来源 → 依据原生连接契约构建标准连接事实 → 检查边界并生成诊断 → 校验读取前后身份 → 原子保存报告。检查器处理受约束的接线表达，不建设任意 Python 流程还原器。

候选模块不 import，函数、构造器、property、装饰器和默认值表达式不执行。原生平台反射继续使用第一阶段的受限检查进程。查表由独立的只读路径执行；检查器不调用候选 Dataset.schema 或通过终结动作获取信息。

工作区 helper 递归解析需要绑定实参来源，识别调用上下文；重复调用不是同一个业务步骤。未使用的文件不进入该组合的实现身份，已引用的文件完整内容参与摘要，避免只哈希局部函数漏掉常量或 helper 变化。无法确定的 import/依赖闭包必须标记，不声称已捕获任意 Python 的全部依赖。

源码扫描从选定入口及可定位 import 出发，不遍历 data、runs、.forge 或外部表根。配置只按明确资源引用读取；列表功能读取有限控制文件，不扫描所有业务数据。

派生报告使用 `demiflow_forge_inspection_v1`，包含：组合与入口、使用的表与资源、源码清单、平台/标准绑定、节点/边、诊断、覆盖范围和摘要。它是事实报告，不是执行器输入。JSON 与 HTML 使用同一份报告。

节点最少包含本报告内 ID、种类、API/callable 来源、源码位置、已解析参数、schema 状态和效果声明；边包含起止节点、原生参数/结果角色及 data/control 类型。表节点另含固定引用；未解析节点保留原因和源码。查看器不为 join、map 等业务名称另写语义分支。

主要身份包括 `implementation_digest`、`bindings_digest`、`platform_digest`、`standard_digest`、`wiring_digest` 和完整报告摘要。源码位置变化可使实现身份变化而不一定改变连接；图对比应分别显示。节点 ID 只在报告版本内标识调用位置，不用于缓存认证；无法可靠匹配的节点按删除/新增展示。

状态口径：

| 字段 | 含义 |
| --- | --- |
| status=checked | 全部主数据连接与绑定通过结构检查；界面显示“结构检查通过”，operator 行为验证和执行许可另列 |
| status=incomplete | 语义缺失、来源无法解析或资源超限，未通过；局部事实只供诊断 |
| status=invalid | 入口/参数错误、已知字段缺失、非法引用或确定的约束冲突 |
| status=stale | 平台或所依赖内容与报告绑定已变化，需要重新检查/绑定 |
| schema=known / declared / partial / unknown | 分别表示元数据或可靠原生推导、业务声明、部分可知、未知 |
| execution_permission=not_assessed | 第二阶段不签发运行许可 |
| operator_validation=not_run / declared / verified / failed | 显示 operator 契约验证覆盖；类型声明和结构检查不能替代实际验证 |

已知缺列是错误；未知输出 schema 是待验证项，不能当作兼容通过。即使连接结构已通过，仍需分别展示 operator 契约和数据验证缺口，不能显示整体“合格可运行”。模型配置以原生格式和摘要关联；Prompt 可复用纯文本检查，Agent 配置若会 import 自定义工具，仅记录声明并保留语义验证阻断，不复制另一套解析器。

## 8 统一工作区界面

首版以本地工作区界面支持日常查看，离线 HTML 作为显式导出的快照。单个组合的离线图不足以承担找表、按需看 case 和连续对照，因此不再作为唯一可视化入口。界面与 agent、Notebook 解耦，使用打包的本地资源，不依赖外部 CDN。

### 8.1 信息结构

| 视图 | 用户能了解和操作的内容 |
| --- | --- |
| 项目总览 | 项目用途、表与组合目录、代码入口、检查状态和缺失说明 |
| 数据表 | 实际位置、固定版本、schema、只读属性、用途；进入内容浏览 |
| Case 浏览 | 列表与详情、图片/文本/结构化字段、原始值、明确关联后的输入输出或 A/B 对照 |
| 加工组合 | 切换组合、查看接线、参数和配置、检查覆盖、源码与版本差异 |

默认首页是项目总览；进入某张表即可连续看 case。界面保留所选表版本、case 和对照设置。直接链接可定位到明确表版本或报告节点，不依赖之前的聊天或 Notebook 执行状态。

```text
工作区 · 项目用途
  项目总览 | 数据表 | 看 Case | 加工组合

看 Case：
  当前表与版本 · 可选对照表与关联字段
  case 列表 | 当前内容：文本 / 图片 / 表格 | 对照内容（按需）
            原始字段 · 上一条 / 下一条 · 来源信息

加工组合：
  组合列表 | 接线图 | 节点参数、schema 状态、源码、诊断
```

业务内容来自表；项目用途来自 README；组合用途来自保存的说明；步骤说明来自函数 docstring。没有说明时明确显示缺失。界面不能靠自动猜测或一次 agent 总结冒充项目事实。

### 8.2 接线与内容的关系

连接图提供缩放、平移、搜索、helper 分组和节点详情。源码展示固定快照片段与位置。节点区分输入表、转换、条件、合流、物化、计划输出和未解析部分；数据依赖与控制依赖分别显示。

从已绑定输入表可进入对应版本的 case 浏览；计划输出没有实际提交版本，不能点击后伪装成已有结果。共享上游线不表示引擎只执行一次。静态代码描述的连接与实际生成血缘分开，第三阶段才依据运行事件和回执显示真实产出。

报告对比区分输入版本、参数/资源、API、连接和源码变化。未检查、过期、解析不完整的组合仍出现在项目目录中；不能仅展示成功报告，使项目看起来全部可用。界面显式刷新检查状态，显示核对时间；不会在打开页面时执行业务或自动更新表引用。

### 8.3 本地接口与导出边界

`workspace view` 启动绑定到本机回环地址的薄查看服务。它复用工作区读取、表元数据、case 读取和静态检查接口，不新增执行器、数据库或业务服务。请求只能选择已绑定表、版本、受限字段和明确比较条件，不接受任意文件路径、SQL 或 Python。服务使用会话令牌与来源校验，默认不监听外部网卡。

读操作不改表、别名、业务代码或审核结果；用户显式刷新静态检查时可保存派生报告。任务数量、响应和媒体缓存有界，退出清理本任务 worker 和临时资源。候选 Python、Notebook cell 与模型配置内的工具不被执行。

导出包含项目目录、所选报告与明确覆盖范围，页面内可以切换已包含内容。未包含的详情标明缺失。导出页不连接工作区读取新数据，也不显示实时 current；后续代码变化需重新核对与导出。表名、文档、诊断和源码均按文本处理，不作为可执行页面内容。

本阶段不提供拖线编辑、业务执行按钮或审核结果写入。case 浏览是核心；评分、标签、通过/驳回和多人协作要等实际需求与写入契约明确后单独设计。

## 9 人与 coding agent 的使用流程

以下为拟定命令，不代表当前版本已提供。路径参数明确指向工作区，避免依赖当前目录。

### 人的流程

```bash
demiflow forge workspace init ./experiment
demiflow forge workspace location add ./experiment shared_gt --root /data/ground_truth --read-only
# 此例假设 gt@v3 已有唯一匹配的原生 Catalog 记录
demiflow forge table attach ./experiment gt --location shared_gt --path gt.lance --version 3
demiflow forge table show ./experiment gt --json
demiflow forge table sample ./experiment gt --columns id,score --limit 20 --json
# 通过平台 API 编写 flows，operator 实现独立业务步骤；参数文件可选
demiflow forge flow inspect ./experiment flows/questions.py:compose --params flows/questions_a.json --json
demiflow forge workspace view ./experiment
# 需要交接固定快照时，再显式导出
demiflow forge flow view ./experiment flows/questions.py:compose --params flows/questions_a.json --out ./questions_a.html
```

用户可以直接从工作区总览进入表和 case，按需查看接线；理解项目不需要 agent 或 Notebook。修改 flows 中的代码后重新检查，界面显示新报告及差异。

Notebook、普通脚本和 coding agent 均可调用同一入口及数据接口。Notebook 是代码载体，可以承担辅助分析；登记组合的接线仍集中在 flows，不能分散到 cell 中。本阶段检查保存的 Python 源码和明确绑定，不读取 kernel 内存或自动执行 cell；后续是否接入其他代码载体，按实际需求单独设计，不以 Notebook 为默认平台中心。

未登记的表在 attach 时另加 `--dataset-id`、`--schema-name`、`--schema-version`。绑定文件可直接由人或 coding agent 编辑，不要求额外执行组合注册命令；inspect 负责统一校验。

### Coding agent 的流程

1. 读取 `workspace context --json`：结构、可用表固定引用、标准版本、命令和检查预算。默认不包含样本行。
2. 用现有 `platform list/show` 查看真实 API；根据任务选择表和组合入口。
3. 按接线规范调用平台 API，在 operator 内实现节点业务；参数与变体就近维护，不手写重复图或绕过契约。
4. 执行 `flow inspect --json`，修复全部阻断项；平台能力不足时提出所属原生 API 的扩展，不把未知调用当作合法节点。
5. 交付可直接打开的工作区查看入口、组合说明、连接图、检查覆盖和差异；用户可自行看 case 与查源码。

Codex 等 coding agent 与人使用同一契约，不需要专用 MCP 适配、Agent 执行器或另一份简化标准。已有工作区文档和 AGENTS.md 不被初始化命令覆盖。

## 10 命令与保存协议

新增 `forge workspace`、`forge table`、`forge flow` 命令组，避免改变旧 v1 项目命令的含义。不设独立 compositions 管理层。最小命令面：

| 命令组 | 命令 | 行为 |
| --- | --- | --- |
| workspace | init / location add / context / view | 创建控制文件、明确数据位置、输出工作上下文、打开统一查看界面 |
| table | attach / list / show / sample / replace / detach | 管理工作区引用与只读查看；detach 不删表 |
| flow | inspect / view / diff | 检查 flows 中明确入口与参数、查看图、比较两份报告 |
| platform | 现有 list/show/snapshot/check | 查询与绑定当前平台，增加明确 v2 格式支持 |

只读命令不刷新 alias、平台绑定或代码。attach/replace/location 变更使用原子写入与旧摘要比对，防止人和 coding agent 同时改文件时覆盖对方。相同名称绑定不同内容返回 conflict；用户明确 replace 才更新。

报告按摘要创建不可覆盖文件，最后才原子更新该组合的 current 指针；并发检查若源码/配置/引用在期间变化，返回 source_changed，不发布混合报告。图和 JSON 都指向同一报告摘要。清理缓存仅限生成目录，不删除表、代码或运行证据。

JSON 诊断至少包含 `code`、`severity`、`message`、`source.path/line/column`、`node_id`（若可定位）、`field_path` 和 `remediation`。成功操作及 checked 退出 0；invalid/incomplete/stale/conflict 退出 1；CLI 参数错误退出 2。schema 警告可与 checked 共存，但覆盖字段不能伪装为完整业务验证。

Python API、CLI 与本地界面共用实现，提供工作区读取、表绑定/检查/case 读取、组合检查、报告比较与导出；不另写 Notebook 或 agent 专用链路。

## 11 资源上限与边界行为

初始上限只能收紧，超限明确失败或返回带缺口的报告，不自动放大。

| 增长对象 | 初始上限与处理 |
| --- | --- |
| 工作区控制输入 | 位置 16 个，表引用 1,024 个，组合 256 个；列表默认 50、最多 200，分页读取 |
| 源码与配置 | 目录项 1,024、深度 16、单文件 1 MiB、选定闭包总计 16 MiB；项目说明最多 64 KiB，先准入再读取 |
| AST | 单文件 50,000 节点、合计 200,000；调用上下文 256、深度 32；参数求值只处理有限字面量和已绑定值 |
| 连接图 | 1,024 节点、4,096 边；列表/页面分组显示，报告最多 8 MiB |
| 派生文件存储 | 每次 HTML 最多 16 MiB；工作区 inspections 最多 128 份报告、总计 1 GiB，含临时输出预留；超限停止新增，要求显式清理生成文件，不自动删除历史 |
| 原生连接声明 | 每个 API 最多 16 KiB，仅有限 JSON 数据；不包含可执行分析回调 |
| Catalog 查询 | 固定 Catalog 版本、过滤和投影、分页扫描；返回记录和编码字节都设上限，禁止先 to_table 全量读取再切页 |
| schema | 最多 2,048 字段、嵌套深度 16、规范化结果 1 MiB；超限只返回限制诊断 |
| 列表与 case | 列表默认 20 行、最多 100 行、16 列、256 KiB；详情单次响应最多 1 MiB，文本默认展示 16 KiB，未知读取上界不靠展示截断规避 |
| 图片 | 原始文件最多 8 MiB、解码最多 16 百万像素、缩略图最多 512 KiB；读取与解码前准入，不先解码再缩小 |
| 查看服务 | 同时最多 2 个数据 worker、等待请求最多 8 个、媒体缓存 32 MiB；超限明确繁忙或资源不足，不无限排队 |
| 进程 | 检查与表查看各次最多 60 秒，单命令并发 1；stdout/stderr 和临时文件均有界 |

Lance/Arrow 读取 metadata 和单值可能在 Python 检查前发生原生分配，使用隔离进程、余量和环境保护；不能把输出大小当成实际解码或 RSS 上限。超时、取消和异常清理本任务子进程组及未发布文件。预览与图导出不执行任何 HTML 中的字符串或候选 Python。

源文件、引用文件和表根拒绝符号链接、路径逃逸、特殊文件与可检测的并行替换；显式外部根不通过全盘扫描发现。样本读取必须有用户选择的表和列，检查报告不写入环境变量值或凭据。任意候选代码的 OS 隔离不由本阶段的静态检查承诺。

## 12 代码范围与实现顺序

| 位置 | 必要修改与复用 |
| --- | --- |
| `forge/` 工作区模块 | 位置、引用与组合绑定的解析、摘要、原子更新；不新增存储引擎 |
| `forge/` 接线检查模块 | 受限接线语法、平台 API 来源与边界硬检查；有界解析、诊断与派生报告 |
| `forge/` 查看模块及静态资源 | 工作区界面、受限本地接口与导出；复用数据/检查能力，不新增业务存储或执行引擎 |
| `forge/platform*` 与标准资源 | 接入原生语义、Lance 公开入口和明确版本；复用第一阶段基础 |
| `data/` 原生 API 定义处 | 只增加必要的只读连接声明和声明一致性测试；不改变 Dataset 执行语义 |
| `lance/registry.py` 与原生读取所属模块 | 补足实际需要的有界查询、行定位及 case 投影读取；复用 DatasetRef，不在 Forge 放另一套查询/解码实现 |
| 文档、示例、测试、打包 | 人与 agent 使用指南、A/B 示例、资源与兼容验收、HTML 离线资源分发 |

执行器、模型客户端、请求账本、服务和生产数据不因本阶段顺手改造。原生 runtime 的历史分发身份问题在第四阶段解决；阶段二不需要伪造运行环境才能绘图。

通过 Review 后，按以下次序实施：工作区与表引用 → 有界 case 读取与统一界面 → 原生连接语义和 v1/v2 兼容 → 静态检查与接线视图 → 联合验收。界面设计先用示例数据 Review；真实表读取的类型、规模和媒体边界另行验证，不能以设计原型代替已实现能力。

## 13 验收矩阵与演示脚本

| 类别 | 必须验证 |
| --- | --- |
| 表归属 | 默认数据根与外部只读根均可接入；跨根同名表不混淆；接入不改源表或其 Catalog |
| 固定版本 | head 只在显式接入时解析；源表新增版本不漂移已绑定输入；版本回收后明确失败 |
| 多组合 | 同源输入的 A/B 参数或代码不同，生成不同报告；修改 A 不改写 B 的报告 |
| 独立理解 | 不打开 agent 或 Notebook，仅凭界面能找到项目用途、数据位置、case 内容、组合用途、接线和未完成项 |
| Case 浏览 | 文本、图片、小表格与原始字段可查看；版本和定位稳定，分页投影；明确关联后可对照，缺失/重复匹配不误配 |
| 接线归属 | 登记组合入口和组合 helper 集中于 flows；Notebook/脚本调用相同入口，隐藏 cell 或全局状态不算完整连接 |
| 硬约束 | 非平台表级加工、直接模型客户端、私有调度、隐藏 helper 接线和不确定控制流均不通过；缺口图不作为合格流程 |
| Operator 边界 | 输入输出及原生调用协议可检查，已知越界阻断；未做的行为验证明确保留，不以普通函数身份免除契约 |
| 动态 API | 平台 fixture 新增带连接语义的公开方法，无需改 Forge 方法名单即可发现和绘图 |
| 接线 | map 链、多输入 join/union、helper、多输出、分支与有限循环显示完整；同名普通对象不误判为 Dataset |
| schema | 已知缺列报错，未知 schema 如实显示，业务注解不冒充实测类型 |
| 不执行 | 含顶层副作用、构造器、默认值及自定义 Agent 工具探针的候选代码，在 inspect/view 中都不运行 |
| 图一致性 | 图和 JSON 同摘要，源码位置可定位；图差异与绑定变化一致；离线旧页面不显示实时新状态 |
| 页面内容 | 恶意表名、文档、源码与表字段只作内容显示；本地服务不接收任意代码/文件路径，不开放原表写入 |
| 资源失败 | 大目录、宽 schema、巨大文本/二进制值、超多节点、超时、取消、并行变更和输出冲突均有界且不发布半份报告 |
| 兼容 | 第一阶段目录/快照与旧 v1 项目回归；历史 DatasetRef、Catalog 和证据不被重写 |
| 独立安装 | wheel/sdist 包含查看资源，离线打开无 CDN；CLI 与 Python 返回同一报告 |

最终演示使用自有小型 fixture：打开工作区总览 → 找到固定输入和已有候选表 → 连续查看图文 case、原始字段及明确关联的 A/B 内容 → 切换到 flows 中的组合接线 → 修改 A 并查看差异 → 故意接错字段并定位诊断 → 恢复后结构检查 checked。浏览使用预先准备的真实 fixture 表，不能把它们宣称为本阶段执行候选加工的产物；实际运行与结果追踪仍在第三阶段验收。

## 14 本次 Review 的关键决策

1. 一个工作区多表、多组合；默认真实表在 data/，外部表只读引用，表生命周期独立。
2. 接线、默认参数和变体集中在 flows，较长参数文件就近保存；取消独立 compositions 层，Notebook 和脚本是可选调用方。
3. Flow 必须使用平台 API 接线，operator 只承担节点内业务；采用明确契约和硬检查，未知主连接不通过。能力动态来自原生 API，不写死业务排列。
4. 统一工作区界面是主要查看入口，case 浏览与接线图同属核心能力；本地只读接口支持按需读取，离线导出保存固定范围的快照。
5. 接线完整、schema 已知和业务验证分别标识；不能把图可见或 checked 当作运行许可。
6. 普通文本、图片与结构化 case 要有实际可用的有界读取；浏览不写审核结论，未知大小或不支持表示明确报告限制。
7. 平台事实新增字段使用 v2 格式，v1 保留原语义；新规则和绑定不改写既有证据。
8. 项目无需 agent 或 Notebook 也能理解；业务运行、结果追踪仍在第三阶段，本阶段不引入审核工作流或 Agentic 编排。

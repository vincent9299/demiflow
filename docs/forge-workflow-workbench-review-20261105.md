## 完整设计必须闭合的事项

### A1 项目与运行的入口不依赖当前 Flow 有效

项目检查、运行能力说明与历史记录在未绑定原生 Flow、配置丢失或已删除时仍须可达。选择历史 run/attempt 后，图、日志、指标、结果和控制始终引用该封存对象，不能因切换当前配置而替换身份。已有运行的停止资格由当前 run_control 权限和原运行协议判断，不能附加当前流程检查通过或当前流程仍登记的条件。

依据：D0 第1、3、6、7节已有此方向，但无 Flow 的项目级入口和选择状态转换仍待完整契约；`run_admission.inputs` 对新的受管提交明确要求登记入口和参数绑定，与历史 run 的查看/控制不同。

验收包含：空项目、旧入口未绑定、多流程切换、当前文件/登记变化后查看和停止已存在运行、旧 checks/run 深链接与刷新。

### A2 诊断表达必须获得可证明的来源和影响范围

允许本任务增加必要的兼容结构化诊断字段。分类依据从实际诊断产生处给出明确原因、来源、范围及与动作的关系；不得通过英文字符串或同一个 FL-01 规则号猜测。未能分类的诊断保留未知与原文，不能通过前端重标改变原检查结论。项目总体未完成、某配置检查结果与 prepare/start 准入分别表达。

依据：`project_check.check` 将多种异常及 discovery 诊断归入 FL-01/incomplete，并限制每个报告引入的诊断数；仅按 rule/status 无法可靠区分源码违规、读取/平台/资源失败。现有原始 detail、code、status、report/entry/params、覆盖与截断事实需要保留；改变生产者时须说明协议兼容与旧记录的降级策略。

验收包含：同一 FL-01 的不同原因、未知码、跨流程问题、检查自身失败、预算耗尽、截断和缺少行为/Review证据。

### A3 展示缓存与当前有效依据分开

“显式刷新才核对”不能使旧报告长期显示为当前有效。明确缓存键、核对时点、失效来源及缓存年龄；无法核对时显示最近一次已验证事实与待核对，而不是当前通过。有效配置覆盖、开发对话或外部编辑、平台/标准/权限变化均有可说明的处理。缓存不授予执行能力，prepare/start 继续做现场校验。

前端需要选择代次/请求身份和过期响应丢弃规则；仅 AbortController 不证明旧响应或服务端工作已取消。保存当前草稿、已准备 request/run、运行 attempt 与历史报告是独立生命周期。准备响应丢失继续查询原 request_id；提交/停止沿用 expected 和 expected_attempt，不产生重试即新作业的路径。

依据：D0 第7节缓存建议；`project_check.status` 的新鲜度判定；`run_requests` 的准备回执/恢复和 `runs.start/cancel` 的预期身份协议。

验收包含：响应乱序、准备响应丢失、源码与权限在页面外变化、有效配置覆盖、当前/封存之间切换及多项目隔离。

### A4 单请求上限之外闭合部署总量

2秒/256MiB 是提案，需核对冷启动和真实宿主分区，不作为现成保证。完整设计须规定跨项目和客户端的解析并发、排队/拒绝、同时驻留的源码/AST/序列化/缓存对象及取消/超时后的清理。客户端取消不等于解析进程退出，资源许可只能在相应任务确实结束后释放。读取拥塞时保留停止和小快照能力。

优先复用现有 worker、HTTP工作槽及宿主资源归属，必要扩展纳入同一设计，不建立独立无限 worker 池或隐含增加预算。当前 workspace worker 会加载原生库，并有基线+384MiB的地址空间保护；受准备lease的调用另计768MiB进程树RSS预算。新静态读取不能直接把256MiB数字套到该路径，也不能绕过宿主的总预留。

依据：`workspace_worker.operation/main`、`run_domain.preparation_lock`、`PREPARATION_RSS` 与 D0 第7节。图缓存8MiB序列化字节不等于解析对象或宿主RSS硬上限。

验收包含：冷启动、多客户端/多项目并发、小预算解析、慢读/超时/取消、缓存驱逐和读取饱和时停止运行仍可用。

### A5 原项目图保持有依据的局部投影

复用 discovery 的安全路径、证据和预算机制；同请求尽量提取紧凑事实并及时释放AST，避免另扫同一闭包或长驻全部源码/AST。只标出静态可证明关系，动态或未知保留位置与原因；图类型、依据身份、完整性与展示裁剪分别呈现。不能依靠新图为旧入口开放执行，也不能建立另一个宽松的静态检查器。

依据：D0 第4节；`project_discovery.entry_source` 已为同模块多入口提取紧凑事实，明确避免缓存整份AST和raw载荷。新增图读取应说明与现有发现、报告及检查的职责和共享边界。

验收包含：同模块多入口、不明调用/动态分支、源码读取中变化、读预算与图节点/边数超限、原生图复用及完整图的展示裁剪。

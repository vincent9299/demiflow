## 实施前纳入的两项修正

### 原生诊断纳入有界存储

目前 `forge/run_worker.py:99` 将 executor.resource_root 指向封存 source；`execution/native_resources.py:69—74` 将 query 诊断落在其 `_demiflow/dataset_native/queries`，`execution/datafusion.py:477—480` 直接用文件接收子进程 stdout/stderr。现有 supervisor 只保护 work、evidence/checkpoints 和输出，因此不能只覆盖 RunLog 或 prepare 时的目录体积。

明确原生诊断的受管目录、运行中单文件/总量上限、轮转和保留。动态诊断与源码封存、业务资源解析分开，不能为搬日志改变作者路径语义。普通诊断可按预算丢弃并标记；必要控制/提交事实保持原可靠性。RM-16 增加原生子进程日志爆量、多 query/attempt 累积以及实际峰值，覆盖写入过程。

### 准确界定资源域

`execution/native_resources.py:70—74` 的 query 池使用 `tempfile.gettempdir()`；`forge/runs.py:721` 为各 run 设置独立 TMPDIR。内层 query 池因此可能分开，它不自动构成部署域的共享运行配额。

可以保留这些原生池，由外层薄租约完整预留所管理运行的总量；无需为本任务统一所有普通 Dataset 的池。RM-05 明确验证不同 TMPDIR、项目、CLI/HTTP 进程及 active>1 的覆盖边界。旧封存运行和未参与该域的进程不能被计作已纳入管理，也不能自动改写或接管。

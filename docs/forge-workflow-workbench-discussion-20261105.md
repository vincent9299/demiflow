## 2. 屏幕怎么组织

```text
项目列表 │ 项目 tabs
         │ 流程选择   配置选择              当前依据 / 当前运行
         │ 图/节点配置 | 检查问题 ① | 运行监控 | 输出结果
         │
         │ 数据源 → 算子 → 输出             图 / 节点详情
         │ 图上的参数摘要、问题和真实观察   说明、配置、问题、运行或结果
         │
         │ 一句当前结论 + 一个主要下一步
```

- **读图与配置**：点击源节点查看固定输入与读取参数，点算子查看用途、实现与参数，点输出查看位置和提交策略。点击“整图配置”配置流程参数及运行预算。参数摘要直接呈现在节点，值的来源可展开定位。
- **检查**：在同一图上标出问题节点/边，右侧解释影响、位置和处理方式。不能归节点的问题保留在全局列表。违规、部分构图和无法构图分别展示，不把图能画出来当作合规。
- **监控**：在固定 run/attempt 的封存图上展示真实动作观察，右侧呈现选中节点对应的实际 action/node/occurrence。惰性算子可能融合；没有独立观测的节点标为“未单独观测”，融合组耗时不拆分给每个节点。CPU/RSS 放在整次运行级。
- **结果**：输出节点标提交事实，右侧查看固定版本及证据。失败或停止仍可有已提交结果；清理、停止证明和恢复资格分别呈现。

### 配置挂载与实际代码的对应

| 挂载处 | 内容 | 第一版原则 |
| --- | --- | --- |
| 数据源节点 | 数据引用/固定版本、投影、明确读取参数 | 原生参数中可确证的值可编辑；不扩展资源授权 |
| 算子节点 | 实现引用、输入输出字段、业务参数和已支持执行参数 | 说明“做什么、调用谁、配置来自哪里”；代码字面量/动态来源只读定位 |
| 输出节点 | 已声明位置内的相对路径、受支持模式和 CAS 基线 | 不通过图新增位置或放开写权限 |
| 整张图 | 入口/配置、共享流程参数、资源与累计运行预算 | 共享参数明确列出受影响节点；局部配置不能扩大继承预算 |

图是实际源码/参数的投影与编辑入口，不创建第二套图形化流程定义。只有能证明节点字段对应某个原配置 JSON pointer 的字段才可写回同一配置；保存前显示差异并校验预期摘要，外部编辑冲突时保留草稿。文件修改权限必须显式给出，与 run_submit/run_control 分开；既有只读项目保持只读。保存后旧检查变为待核对/过期。写在 Python 代码里或来源不明的值提供精确定位，通过现有开发功能修改。

样稿中的编辑、保存、检查都作用于本地测试状态，不写实际文件。正式的来源生产者字段、参数写回/CAS 和权限契约需要在完整设计中评审。当前图/运行封存视角明确切换，运行封存参数只读。

桌面采用图和详情并排；窄屏把节点与详情顺序排列，保留所有操作和文字依据，不把大图缩到无法阅读。项目导航沿用抽屉；不改变现有开发对话的会话、历史或迭代时间线。

## 3. 三条主要使用路径

### 原项目尚未接通

选择项目 → 看到原入口与配置 → 看已证明的局部关系和未知部分 → 查看当前支持缺口 → 明确下一步由谁完成。

平台始终展示准备/提交、监控/停止、结果管理的能力及项目条件。旧入口缺少原生绑定时，“准备运行”不可用，旁边直接说明原因；不因为没有运行记录而把运行功能藏起来。登记、识别、绑定、检查、授权和实际执行是六件不同的事。

identity 只作为只读调查样例；接入与业务改造由用户完成。样稿使用独立的“原项目示例”，不展示或执行 identity 配置。

### 原生流程从问题处理到提交

选择流程/配置 → 在图上看到问题节点 → 查看关联问题 → 定位源文件 → 用户在开发功能修正 → 重新检查 → 核对输入/输出/预算 → 准备 → 对照本次封存摘要 → 提交。

选节点后可以只看关联问题，但必须保留“全部问题”及总数，避免筛选造成“问题消失”。样稿中的“模拟修正”只演示交互，不会改文件。原始诊断和规则编号始终可展开。

**用户最新要求主按钮为“运行”，点击后真实提交作业。** 普通路径只需一次主动操作；内部仍按现有 prepare → start 协议完成有效检查、封存、预留和启动。运行输入/输出覆盖值属于待准备检查的草稿，不能把原配置报告显示为覆盖值已检查；准备得到的有效报告和封存图才对应本次实际运行。该要求替代 D0/D1 的普通用户“先准备、再点提交”路径。

运行点击时固定项目、选择代次与有效载荷，持久保存原 request_id。准备结果丢失先查询原请求；启动响应丢失先读同一 run/attempt。选择或权限变化、迟到响应和错误不能触发其他项目或另一次启动；自动串联无法继续时保留“已准备/未确认”等真实事实，提供继续原请求的操作。重试沿用 expected/expected_attempt；停止仍独立于当前配置合规。

### 运行、停止和结果

提交 → 保持该 run/attempt 的身份 → 看状态、动作进度和指标 → 请求停止 → 等执行端确认 → 看已提交输出和未完成部分。

停止请求已保存时显示“正在停止”，不能立即显示“已停止”。未确认或清理未完成时保留原因与占用事实。失败、取消、进程停止、清理和提交状态不合成一个模糊的红/绿结论。返回当前配置与查看封存运行必须是两个明确入口。

## 4. 图究竟表示什么

| 图的类型 | 依据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- | --- |
| 源码观察图 | 已声明入口、明确引用、有限静态读取 | 有定位依据的局部关系 | 完整语义、通过检查、实际执行 |
| 原生检查图 | 绑定具体配置与输入身份的检查报告 | 该报告覆盖的接线、字段、数据/值/动作边 | 算子业务效果、已经产出结果 |
| 运行封存图 | run 封存报告，叠加该 attempt 的真实观察 | 本次实际准备的图、执行观察和输出事实 | 所有节点都单独测量、逐行血缘 |

图标题旁固定显示类型、流程/配置、摘要短码、核对时间与完整性。节点先给简短用途、算子/实现名、关键参数，再展开源码行号、参数来源、输入输出字段、关联问题；运行中仅按可证明的 action/node/occurrence 或融合范围显示观察。首版的确定性说明来自实际 API/源码与显式 docstring；缺少用途说明时显示缺少依据，不调用额外付费模型补造业务意图。

已存在的原生图直接复用。原项目新增只读的局部图投影：只连接可证明的字面量引用与明确变量数据依赖，不按文件顺序、算子列表或业务字段名补造边。分支、循环、动态路径和未展开调用显示未知区域及原因；声明关系用独立线型，不能伪装为数据流。identity 的动态调用不承诺被画成完整可执行图。

## 5. 检查怎么让人看懂

首先给当前流程的操作结论，例如：**“1 个问题需要处理：输出字段与契约不符，当前不能准备运行。”** 项目整体缺行为/Review 证据仍显示未完成，但不自动等同于某个 Local Flow 的运行禁令；实际准入继续由现有准入/prepare/start 决定。

| 类别 | 用户看到的含义与动作 | 保留的事实 |
| --- | --- | --- |
| 代码/配置问题 | 定位文件与节点，修改后重查 | 原规则、category/status、完整原诊断 |
| 平台支持缺口 | 当前协议或算子组合尚不支持；说明接入条件 | unsupported/unknown 不改写为业务错误 |
| 读取或操作范围不足 | 哪个资源未读取，哪个动作无权限，谁可调整 | 数据路径越界和提交/控制权限分开 |
| 尚未检查/覆盖不足 | 展示已读范围和未检查部分 | 不能把“未读”显示成通过 |
| 依据已变化 | 保留旧报告，提示变化来源与重新检查 | stale 不覆盖历史结果 |
| 检查执行失败 | 显示工具/资源失败，允许有依据的重试 | 与候选代码 invalid 分开 |

中文说明采用明确诊断码/规则映射，不能依靠英文字符串猜分类。未知码显示“尚未归类”并保留原文。是否阻塞某个动作独立于问题颜色：未证明只影响另一流程的问题，不得被误当当前流程失败；缺少覆盖依据时显示无法判定。

## 6. 运行页的状态草图

| 状态 | 主内容 | 主要动作 |
| --- | --- | --- |
| 无记录/未接通 | 平台能力、项目条件、接入下一步 | 看入口和支持范围 |
| 权限不足 | 可查看的事实，缺少的具体权限 | 读配置/检查；有 control 时仍可停止 |
| 已准备 | 固定输入、有效配置/图、输出、预算、封存摘要 | 提交本次运行 |
| 运行中 | 可靠状态、当前动作、CPU/RSS/动作吞吐、采样时间 | 停止运行 |
| 正在停止/未确认 | requested/terminating/killing/confirmed 的说明 | 刷新事实；按权限显式核对 |
| 失败/已停止 | 停止证明、错误、部分提交、清理与恢复资格 | 查看结果；有资格时技术恢复 |
| 成功 | 各输出固定版本与结果证据 | 看数据/Case，作为后续输入 |
| 失联/准备响应丢失 | 保留最近事实、请求 ID 和不确定状态 | 查询原请求，不能另建一次提交 |

CPU 来自进程 CPU 时间差/实际间隔，单位为核；RSS 为进程树采样和，可能重复共享页；吞吐按 action/node/occurrence 的观察计算。指标缺失显示“暂无采样/不可用”，真实零值显示 0；趋势有缺口时不连线补零。首版不制造全局百分比、ETA 或 CPU/RSS 硬配额。

## 7. 工程方向（讨论后细化）

前端统一保存 `项目 + 流程 + 配置 + 当前/报告/运行依据 + 节点/整图选择 + 观察视角`。切换视角不重选流程；run/attempt 永远引用封存事实。配置和报告变化使当前草稿待核对，不能暗中替换正在看的历史运行。刷新使用可校验的定位引用恢复；实际产品的草稿内容与权限不写入分享链接。样稿定位中仅含可公开的测试状态。

后端继续复用 discovery、统一检查器、原生图、Dataset、准入、prepare/start/cancel、可靠 journal 和现有遥测。图投影层负责读模型、局部图和诊断表达；配置写回是经单独授权、CAS 校验的原参数文件编辑，不引入第二套执行/检查/调度/配置存储。参数来源关系由生产者明确给出，不能按值相等反推。

拟议新增两个有版本的只读投影：工作台上下文与图。前者提供稳定流程目录、选择依据、动作条件及诊断引用；后者按明确的 discovery/report/run 身份读取有界图。具体请求字段、摘要校验和缓存失效在讨论后形成完整契约。准备的现场校验和封存后确认仍是执行事实来源，展示缓存不能授予权限或检查通过。

旧 `flows`、`inspection`、`checks`、`runs`、`run` 定位仍可读：分别映射管道配置、报告图、项目检查、管道内历史索引和固定运行。旧 `overview` 定位映射 Readme，数据和开发入口保持。保留 v1/v2 解析；若新增 v3 工作台引用，需前后端 schema 同步，并验证未知/删除对象、刷新、前进后退和跨项目隔离。旧链接不得静默落到另一个流程。

### 资源预算的初始建议

| 对象 | 初始设计上限与超限行为 |
| --- | --- |
| 公开发现 | 沿用 128 文件/4 MiB、单源码 1 MiB、配置/README 64 KiB；不递归扫历史或数据 |
| 新局部图读取 | 包含在独立请求的上述总读取预算内，不再叠加一份发现扫描；最多 16 个明确源码文件、50,000 AST 节点/文件、100,000 总节点、调用展开深度 4；最多 256 图节点/512 边，超限保留局部并标范围 |
| 解析保护 | 复用现有 worker/HTTP工作槽并核对冷启动、宿主分区；D0的2秒/256MiB仅为已撤回的初估，不是可直接套用的预算。完整设计须合并计算源码/AST/序列化/缓存和跨客户端并发，明确总许可、超时后的进程排空与释放条件；读取拥塞不能占用停止/小快照通道 |
| 图布局 | 首屏最多 64 节点/128 边，其余按连通片或节点邻域查看；不把全图缩小到不可读；一帧目标 16 ms，累计布局预算初值 100 ms，超限降级成节点/邻接列表 |
| 缓存/并发 | 单图 JSON ≤1 MiB；服务最多 16 图/8 MiB，客户端最多 4 图/4 MiB；同选择单请求在途。图是最近一次核对的事实，变化提示/重新进入/操作前按规则失效重验；无法核对显示待核对，不长期宣称当前通过。以选择代次丢弃迟到响应；客户端取消不等于服务端进程退出 |
| 观测 | 沿用小快照≤128 KiB、趋势≤600点/240 KiB；活动运行约2秒、展开趋势5秒、隐藏暂停、失败退避至30秒；不扫描全量历史求进度 |

这些是待工程验证的提案，不是实现已有保证。超限、缓存年龄、未读取及截断必须可见；图的展示预算不削弱现有检查和执行拒绝条件。

## 11. 数据分析与同页呈现：新增讨论

用户补充的数据目标：在“数据”中集成类似 Jupyter Notebook 的分析体验，先了解当前项目有哪些关联表、字段及枚举值分布，再用非常简单、能自行修改的脚本查询，并灵活呈现结果。该项是新的数据分析能力设计。D1.2 已提供浏览器内测试表与可编辑的受限 SQL 演示，尚未接通项目查询、Python 内核，也未安装或启用 Jupyter。

### 同页交互原则

- 保留“开发、管道、数据、Readme”四个项目 tab。每个 tab 在原页完成主要任务，主操作、选中对象和结果尽量同时可见。

- 从管道表节点可以原位预览；需要完整分析时由用户主动进入数据 tab，延续表与版本选择，不自动跳转。

### 数据 tab 的产品提案

```text
开发    管道    数据    Readme

项目关联表/字段 │ 当前表与固定版本 / 预览 / 选中字段分布
               │ 可编辑的分析单元
               │ 单元输出：表格、图表、文本或图片
```

左侧是项目数据目录，区分输入、中间结果和输出；来源可证明时关联管道节点、产生它的运行与提交版本。目录注明识别范围，不把公开声明/当前可读记录等同于整个磁盘的完整表清单；未提交的计划输出不能当成可读结果。

选表后直接看行数、固定版本、字段名/类型/可空性与少量样例。选字段在同页查看缺失数量、不同值数量及分布：低基数值看频数/占比，高基数看 Top K 与其他值，数值看范围/直方图，必要时由用户选择全表统计。全量、抽样、估计、截断和未完成分别标明，不能把前N行或采样分布当作全表事实。

Notebook 式区域提供可编辑的代码单元与紧邻输出，支持新建/运行/中断单元、重新运行和保存分析。优先提供读取所选数据、筛选、分组统计、枚举频数和绘图等短模板，减少从空白脚本起步。Python 交互和 SQL 单元的实际集成方式在完整方案中比较，不将“界面像 Notebook”当作 Python 内核已经接通。

同一有界查询结果支持表格、柱状图、折线图、文本与图片等呈现；图形必须注明数据与聚合依据。分析笔记保存代码、参数、输出及数据版本身份，修改单元或更换数据后旧输出明确标为待重算。已有业务 Notebook 和其输出不会被本功能重写。

## 18. 通用 Case 三分区与字段格式（用户讨论，D1.6）

用户进一步提出可以收敛为三个部分：定义Case需要查看/复核的内容字段（模型输入、输出等），分组/筛选字段，以及标注区；同时希望字段指定message、图片、text、md、dialogue、code、audio、video、tag、html、json等预览格式，左侧数据目录可收起。推荐按此组织第一版，不把Case分析扩成任意页面设计器。

### 固定三部分，字段驱动呈现

1. **导航与选样**：数据版本/范围、分组、筛选、排序和Case列表。配置哪些元数据和已有评测字段可筛选，分组键与模型/checkpoint等输出变体维度分别声明。
2. **当前Case内容**：按输入、输出、参考/答案、其他需查看或复核的字段分区。单Case阅读与同Case多输出对照复用相同字段组件，图片画廊作为选样/布局预设。评测分数与理由保留其模型/规则和版本来源。
3. **评测与人工标注**：展示已有自动评测，按任务配置人工标签、评分、偏好、备注或纠正值；模型结论与人工草稿/已保存记录分别保留。仅查看时可隐藏标注操作。标记可针对Case、指定输出变体或显式可复核字段，身份包含固定来源、Case键以及对应variant/field，不用页号作标记身份。

每个内容字段分别声明“来源路径、标题、角色/区域、展示格式、格式选项、顺序/折叠与可复核性”。角色例如input/output/reference/evaluation，与text/image/messages等展示格式分开。配置不改变原列内容或模型实际输入；同一字段改预览类型时按对应结构校验，格式不匹配给出原因和原文/结构化回退，不悄悄重跑或转换业务数据。

示意：`request.messages → 输入 / dialogue`，`answer → 输出 / md`，`reference_image → 参考 / image`，`metrics → 评测 / json`；`dataset/category/score/status`可以声明为筛选字段。复杂派生字段在原Notebook/管道计算，查看器绑定已产生的结果，不新建业务查询或评测执行器。

### 格式与预览方式提案

| 格式 | 预览方式 | 关键选项/关系 |
| --- | --- | --- |
| text | 保留原文，长文折叠、复制 | 换行、预览长度 |
| md | Markdown排版与原文切换 | 清理嵌入内容，保留来源 |
| code | 指定语言高亮、行号、复制 | 语言与折叠；查看不执行 |
| json | 可折叠结构树与原文 | 展开深度、显示键；不先无限展开 |
| message | 单条角色/内容消息 | 保留role与有序多模态内容片段 |
| dialogue / messages | 按角色与轮次查看多轮对话 | 同源消息组件；角色/内容字段显式映射 |
| image（图片） | 缩略图与同页放大/缩放 | 图注、顺序、尺寸、允许的原图读取 |
| audio | 音频播放器，可关联已有转写 | 时长、播放速度；不自动转写 |
| video | 封面与视频播放器 | 时长、已有字幕/时间点；不为预览自动抽取全片 |
| tag | 标签块、图例及显式筛选操作 | 值/显示名/颜色；查看标签不等于人工确认 |
| html | 隔离预览与源码 | 不继承平台DOM、token、内核或运行控制 |

消息内部的图片、文本、音频等复用相同预览组件；数据目录样例、Case主体和Notebook富输出也复用这些字段渲染器。展示类型是视图配置，不改底层表schema；重新绑定数据源时检查字段/结构兼容。普通操作通过界面选择字段与格式并保存视图；首次配置或新增缺失组件可以由AI coding生成可复用描述/组件，不为每次筛选或换列重写查看代码。

现有固定快照、Case身份、HTML隔离、授权媒体引用及资源联合预算继续适用。音视频不自动播放或后台全量解码；按需加载、取消/释放播放器与对象URL。媒体编码字节、解码像素/帧、时长、并发、缓存和输出保留要分别限制。SSH路径须经实际授权的Web读取/预览能力解析，不能把远端路径字符串显示为可用媒体URL。原位放大优先，不新增常规查看弹窗。

### 已实际提供的字段预览

- text保留基础值与换行；md提供基础标题、段落、列表、加粗与行内代码，未接完整Markdown插件系统。

- message / dialogue分别呈现role/content单条消息或消息列表；样稿支持文本与图片片段，最多12条消息/每条8片段，不宣称全部第三方多模态消息协议已经兼容。
- image使用原合成SVG，支持同一字段内放大/还原，内部滚动不造成整页横向溢出。

### 视图与标注的保存语义

“保存视图”只保存本浏览器中的版本化展示描述、字段绑定、问题定义以及当前分组/筛选/搜索条件；刷新恢复最近保存值。未保存配置保持内存草稿，配置项输入不合法时保留输入并阻止保存，预览沿用最近有效值。字段/选项等文本输入只更新必要预览，避免blur重绘吞掉紧随其后的保存点击。

“保存标注”使用独立的浏览器记录，绑定固定快照、Case/输出身份及完整问题定义；题目名称、类型、选项、必填性或评分范围变化后，旧答案不会当成新问题的答案。旧定义下的值可展开查看，新答案独立保存。旧版Case浏览器标签/备注只读导入，原localStorage记录保留，新版保存到独立v2记录；这不是业务人工表迁移。

标注失败或必填未满足时保留草稿且不推进Case。保存并下一条按固定排序的可见集合定位，即使当前Case因标记退出筛选也不跳项。标签与备注、模型评测、原Case字段分别管理。当前问题定义下的标注状态用于筛选，旧定义下的值不冒充当前答案。

视图与标注都使用简易本浏览器版本检查；可发现已发生的其他页面更新并保留当前草稿，但不是跨用户事务或原子CAS。保存标注不隐式保存视图，也不写业务表、模型结果或Notebook输出；答案附带定义以便解释当前未保存的视图参数。

## 21. 多次运行与每次独立监控（讨论补充，样稿未变）

用户确认希望同一管道可以有多次运行，能够选择运行记录，并查看每次运行自己的节点状态、日志和监控。监控围绕当前选中的一次运行展开，继续复用平台现有 `runs` / `run_view`，不建立第二份运行状态账本、执行调度或遥测引擎。本节补充后续完整方案；D1.8仍为原独立讨论样稿，不代表真实多运行或节点日志能力已交付。

### 使用流程

进入“运行监控”后，顶部显示选中的运行编号、开始时间、状态及尝试代次；最近记录可直接切换，“运行记录”原位展开更多记录。没有显式选择时可建议最近的活动运行；用户已选定后，新运行或新重试只提示可切换，不抢走当前观察上下文。

选择一条记录后，图展示该次运行的封存关系，右侧查看所选节点的可关联观测与异常，下方查看本次运行日志。整次运行级展示状态、最近更新时间、已采集的进度、CPU/RSS等指标以及停止入口；输出节点连接本次实际已提交结果及未完成事实。失败、停止或清理未完成仍保留已有提交，不根据单一红/绿状态隐藏结果。

同一运行的多次尝试以attempt区分，可明确选择历史代次。查看旧代次时不自动跳到最新代次；原代码/配置已修改、流程已删除或当前检查未通过，都不改变历史运行的封存图与日志归属。停止资格按所选运行、当前有效代次及控制权限判断，独立于正在编辑的流程是否仍存在或合规。

### 同一次运行的上下文与异步隔离

统一选择身份为 `项目身份 + run_id + attempt`，同时持有本次封存依据、图绑定身份与前端选择代次。快照、节点观察、控制事件cursor、指标序列、日志offset、结果与停止目标均归属这个上下文；前端只持有现有事实的展示投影，不复制一套权威状态。

- 切项目、运行或attempt时先递增选择代次，取消旧页面的读取/计时器，停止旧身份的后续轮询；新上下文明确加载自己的快照和封存图。旧响应即使无法取消，也必须通过项目、运行、attempt及选择代次核对后才能应用。
- 请求历史代次时显式传attempt；“最新代次”先解析为具体值，再建立当前观察。不能让某个未传attempt的延迟请求把新代次数据混入正在看的旧代次。
- 事件cursor、日志offset和指标窗口按完整身份分别保存或重置，不能把A运行的cursor/offset接到B运行，也不能跨attempt复用。图/来源缓存同样包含封存身份；封存缺失时明确不可用，不用当前源码图替代历史。
- 停止按钮在点击时固定目标身份与expected_attempt；请求期间切换选择，响应只更新原身份的事实，不把当前页面另一次运行标成正在停止。旧attempt控制冲突时要求核对明确目标，不能自动向新attempt再发一次停止。请求已接受仍等待执行端确认停止/清理。
- 轮询失败或页面失去更新时保留最后快照与其时间，并显示待更新/连接问题，不把读取失败推断为节点失败、作业停止或无日志。完成状态、进程存活、清理与提交分别保留现有事实。

### 节点状态、异常和日志的真实范围

图上状态依据已有的action/node/occurrence观测及其明确关系显示；存在可证明的等待/执行/成功/失败/跳过事实时才使用相应标记。未单独观测的节点标明未单独观测；融合执行的节点显示所属执行组与观测范围，不把整组耗时、行数或失败原因拆分复制为每个逻辑节点的独立事实。整次运行成功也不自动证明每个静态节点都独立执行过。

点节点可查看已关联的观测、指标和异常证据。上一轮讨论中“选节点后筛选相关日志”是期望交互，需有可靠的结构化日志关联才成立，不能作为现有API已具备的能力描述：

- 当前Web `GET run-logs`只接受run_id和可选attempt/offset；`runs.logs`读取对应attempt的分段文本并返回next_offset、轮转/淘汰等事实，没有node/action/occurrence筛选参数，也没有全量节点归属保证。
- 当前 `run-events` 的响应明确为 `scope=control_events_only`，用于控制状态事件；不能将它当成完整逐节点执行日志或完整节点事件流。节点观察继续来自现有快照/执行证据，而非由控制事件补造。
- 当前默认保留运行/attempt级原始日志，节点选中不改变其真实范围。缺少可靠关联时显示“本次运行日志，未提供节点关联”；内容搜索只能称为文本搜索。已知节点异常证据可以单独呈现，不能冒充完整节点日志。
- 后续若补节点关联日志，需独立评审结构化记录中的项目/run/attempt/action/node/occurrence、来源流、时间/序号、覆盖/截断/轮转及有界读取契约。相关片段须显示范围；无法关联的原始日志仍可查看。此次不新增该后端能力。

### 多运行的读取与资源组织

运行列表复用现有有界分页及摘要，默认20条，现有接口上限100条；优先按需加载下一页。当前摘要含输出信息，进一步精简摘要需要单列增量契约，不在浏览器中先读取全部运行再分页，也不为每个历史运行加载封存图、指标和日志。

详细图、快照、事件、指标和日志优先只观察当前选中的一个运行/attempt；同一数据通道仅一项读取在途，日志未展开时不持续读取，离开监控停止轮询。分页列表单独按需刷新状态摘要，不能逐条拉取完整详情。运行封存图与来源继续遵守前述图/源码缓存预算；日志沿用现有分段读取和保留边界，客户端只保留有界尾部并明确截断/轮转，不能无界拼接。停止与轻量状态读取保持原公共优先级，不被大量历史图或日志请求占满。

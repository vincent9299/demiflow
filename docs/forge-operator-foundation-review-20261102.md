# Forge 通用算子方案复审与验收矩阵

日期：2026-11-02。对象：[中粒度方案](forge-operator-foundation-design-20261102.md) 与 [源码级方案](forge-operator-foundation-source-plan-20261102.md)。本记录是基于源码的方案自审，不是实现验收，也不宣称经过独立第三方评审。

## 1 评审基准

以下第 1–9 节保留批准前的方案自审基线；实施结果与逐项证据见 [实施验收](forge-operator-foundation-acceptance-20261102.md)。设计时不实施代码。所有公开原生数据能力应使用统一契约与观察入口；实际可运行性按原生支持、组合限制和本次策略确定。不得通过删除门禁声称通用，不得为单个业务或模型建立专用 Forge 路径。

检查六个方面：职责单一、依赖方向、静态与实际语义一致、完整资源所有权、失败/取消/部分提交、兼容与可验收性。原有 dirty 文件、业务仓、生产数据和运行服务不属于本轮编辑范围。

## 2 第一轮 来源和架构边界

| 发现的问题 | 方案修订 | 复审依据 |
| --- | --- | --- |
| 把“所有 API 都被发现”理解为“所有算子都能受管运行” | 分开契约、后端、策略和运行证据；目录未知项必须显示原因 | 当前仅 12 处 flow 声明，异步可静态检查但 runs 明确拒绝 |
| 试图删除所有类型分支来实现通用 | 保留原生语义与编译所需分派，移除 Forge 重复名单和逐 API 特判 | 原生 source、join、batch、prompt、sink 具有实际不同的语义 |
| 把原生领域规则放进 Forge | 纯原生分析返回字段路径和错误类别，Forge 附源码位置/规则码 | 数据与执行层不得导入 Forge AST、workspace 或页面 |
| 新建一个注册框架包住所有算子 | 扩展现有 flow 声明和原生对象；两个公共函数模块，无业务注册或新基类 | 当前 fn/actor、Dataset 和平台动态目录均可复用 |
| 用 planning traits 的默认 transform 作为支持证明 | planning 保持资源规划职责，单独核对真实后端能力 | `operation_traits` 对任意 LogicalOp 有 fallback |

结论：共同机制和领域规则有各自的权威来源；“统一接入”没有被解释成任意代码通行。

## 3 第二轮 静态事实与执行对应

| 发现的问题 | 方案修订 | 对应源码 |
| --- | --- | --- |
| 给所有节点塞预期 metadata，再比较同一份 metadata，会形成自证 | 实际计划描述从真实对象提取；仅真正丢失语义的降低才补最小来源 | `checked.py`、新 `plan_facts.py` |
| 模型 API 降低成 AsyncMapOp 后，原配置和效果可能被忽略 | 从原生 PromptActor 的 operation、runtime、条件和输出读取实际事实，核对各副本 | `Dataset.map_prompt_async`、`PromptActor` |
| 把异步返回当同步 map 的 record | 明确 row/None/list、flat iterator、batch 和字段缺失；静态与运行类型一起扩展 | `flow_contract`、`operator_check`、`runtime_contract` |
| 异步物化执行原 self，检查后计划未贯通 | 两分支统一消费 checked 结果；内部物化不再追加伪业务节点调用公开动作 | `Dataset.materialize`、`materialize_stream` |
| 以 label 或 stage 名称映射图节点 | 用 action/node/occurrence；融合 filter 保留对应，组耗时不伪拆 | `stream._materialize`、`StreamStats` |
| 公开 query 都当纯读元数据 | query 是否执行数据由原生契约区分，必要时进入同一动作门禁 | `Dataset.schema/take/count/iter_rows` 等 |

结论：存在独立的预期事实与实际事实，核对发生在消费输入/启动资源前；图身份不依赖显示名称。

## 4 第三轮 资源 失败与兼容

| 发现的问题 | 方案修订 | 验收要求 |
| --- | --- | --- |
| actor 只凭策略属性识别，取 __call__ 后可能漏清理 | 识别生命周期与实际拥有者、动作内去重；不重复清理 StreamMapRuntime 的 worker | 无策略 actor、共享实例、部分 start、线程在途 |
| async 检查发生在 await 前，或被业务 catch 吞掉 | await 后校验；平台检查置于业务 catch 外；保留原生业务错误语义 | 真实错误类型/超限必须硬失败，业务允许错误仍按原生处理 |
| Prompt 配置从 work 或当前工作区读取，证据漂移 | 配置封存；只读源、账本、scratch 分根；文件和 endpoint 参与核对 | 准备后修改配置、改变目标、取消清理均验证 |
| 每级队列行数有限但宽行/批/list/在途仍无字节上界 | 核算同时驻留的所有平台载荷并加有界准入，说明候选内部临时分配保护范围 | 慢消费者、宽行、批满、放大、父缓冲、故障清理 |
| dead_batches 只限制批数，仍可保留巨量原始数据 | 加总字节预算或保留固定引用/诊断，不能复制整批后才裁剪 | 重复失败大批次必须触发真实限制 |
| RequestGate 按 action 重置，被误当 run 总额度 | 明确预算作用域，多动作计算保守上界，累计额度来自原生持久账本 | 同源两动作、重试/修复、重启不能重新获得额度 |
| 监督进程清理宽限短于原生请求排空时间 | 准入时核对取消策略与有限 deadline；强杀保留 uncertain/cleanup incomplete | 不宣称远端请求已撤回或线程已停止 |
| 用 action_events 追加不断变化的进度 | 保留不可变事实表；同 journal 新增有界观察快照与单调序号 | 旧进度不可覆盖终态，崩溃不推断完成 |
| 新旧格式混用或长期双判断 | 格式独立升版、旧记录只读、新运行重检查，逐族迁移删除重复判断 | 旧记录仍可看；普通 Dataset 不强制新业务门禁 |

结论：数据完整性、性能计量、原生业务错误、平台硬失败分别有可测试口径；控制记录没有替代原生请求或提交账本。

## 5 第四轮 文档与验收闭环

复审进一步补充：

1. 原生语义函数的固定输入/输出边界和分阶段资源解析，防止为了静态分析开放任意文件访问。
2. actor 类/实例、绑定方法拥有者和已有 worker 生命周期之间的责任划分。
3. 观察实例数、单条大小和合计配额取交集，准备时预留终态空间，不能结束时才发现保存失败。
4. 明确公开 API 总盘点包含动作、查询与构造；不把文件内定义数称为全部算子数。
5. 明确本阶段必须真实贯通多个语义族，不能仅交付目录和 supported 字段。
6. 所有测试条目都对应最终使用链路或故障边界；未执行的测试不写成通过证据。
7. 后端、pull/stream、同步/awaitable、inline/thread/process、实例作用域分开表达，避免统一协议再次混淆原生模式。
8. 抽取参数规范化不得静默收紧普通 Dataset 的原有行为；受管策略限制单独诊断。静态预检仍可读取有界固定表元数据，禁止的是提前消费业务数据或启动外部效果。
9. 节点级 DAG 不等于逐行血缘；调用关联必须有真实引用/业务键，证据读取不得全量加载账本后分页。
10. 实际计划匹配、指标采集和缓存都有明确增长变量；增加普通原生/受管/观察三种模式的性能对照。

当前方案层面没有保留已识别的职责冲突或依赖环。尚需通过实施验证的事项是：各原生领域的实际契约覆盖、具体内存峰值、取消/强杀故障行为以及性能成本。它们已列为实施准入/验收项，不以本记录宣称已经解决。

## 6 硬检查和验收矩阵

UC 表示本阶段新增的通用能力检查，不取代既有 FL/OP/EX。每项实现后需关联代码、实际测试日志和必要浏览器证据。

| 编号 | 检查内容 | 必须覆盖的反例 | 通过口径 |
| --- | --- | --- | --- |
| UC-01 来源 | API/契约来自同一真实平台快照 | 候选伪造 handler、同名私有函数、原生声明修改 | 不调用候选解析函数；声明漂移使报告失效 |
| UC-02 覆盖 | 公开 API 的角色和能力状态完整 | 新增 API、继承成员、别名、缺契约、query 有实际执行 | 目录无静默漏项；unknown 不变成 supported |
| UC-03 绑定 | 真实签名、默认值、显式 None、配置引用一致 | 展示 repr 被当默认值、不透明默认、配置修改、目标漂移 | 静态与实际规范参数一致；必要未知阻断 |
| UC-04 后端与策略 | 契约、后端、策略分开计算 | 单节点支持但组合不支持、原生支持但本地策略拒绝 | 同一原生规则用于检查与执行；失败原因明确 |
| UC-05 结构对应 | 高级 API、降低、融合、多输入、物化准确映射 | 用裸 AsyncMapOp 冒充模型、重复 union 输入消失、handle 调换 | 原生实际事实逐项可核对，未知降低阻断 |
| UC-06 实际值 | 参数、返回、字段、null、基数和 batch 正确 | async 回错类型、返回 list/None、超宽对象、批形状错误 | await 后/展开时真实校验，不能以注解代替 |
| UC-07 错误边界 | 硬检查与业务错误策略分离 | catch Exception 吞契约错误、错误响应变正常行、错误预算口径 | 平台硬失败终止；原生允许的业务错误显式记录 |
| UC-08 生命周期 | 构造/start/stop/close 的拥有者准确 | 无策略属性 actor、共享实例、构造/启动部分失败、双 close | 合法对象按实际作用域清理；已清理与未知分开 |
| UC-09 动作接点 | 检查后 source/plan 确实执行 | 异步 materialize 丢检查、内部追加伪 action、预检前消费数据/发请求 | 一次逻辑动作对应一次事实；失败预检零外部效果 |
| UC-10 资源 | reader/queue/worker/batch/output/journal 有界 | 慢消费、父缓冲、宽行、展开、dead_batches、磁盘满 | 超限拒绝或失败，不截断后报成功，不无限保留 |
| UC-11 多动作 | 重复消费的身份与预算正确 | 两个相同 label、共享上游两次运行、额度随 action 重置 | 分动作记录，不承诺仅执行一次；额度口径准确 |
| UC-12 取消 | stop/deadline/线程/请求有一致传播 | 阻塞线程、长请求、部分初始化、SIGKILL、父进程退出 | 停止新调度；有限清理，未知效果不误报完成 |
| UC-13 证据 | 原生请求/提交引用有效 | 丢回执、请求 uncertain、引用其他 run 的路径、超大正文 | 不据日志推成功、不自动重试、不泄露跨根内容 |
| UC-14 观察 | 身份、计量作用域、聚合与限额准确 | filter 融合、同 label、进度乱序、最后快照失败、缓存重放、无逐行引用 | 不虚构进度/血缘；性能随本次规模有界，不随历史全量增长 |
| UC-15 可扩展性 | 同语义 API 不改 Forge 专用代码 | 只改 JSON 的伪 alias、隐藏效果、类型子类伪装 | 真正增加原生 API 并实际执行；checker/runner/UI 无该名字特判 |
| UC-16 多族集成 | 通用机制覆盖不同语义类别 | 普通 fn、异步/actor、flat/batch、join、模型、非模型资源节点 | 每类有原生对照、失败边界和同一工作区实际结果 |
| UC-17 用户入口 | 页面/CLI/Python 读取和操作同一事实 | 只读 GET 触发调用、页面放行 CLI 拒绝、SSH 重连丢状态 | 可独立理解项目、定位节点和看结果，无 agent 隐藏状态 |
| UC-18 兼容分发 | 旧格式、普通 Dataset、打包资源正确 | 旧 checked 升级权限、未受管运行被强制新门禁、缺网页/worker | 历史可读；相关原生回归；安装包外真实运行 |

## 7 独立语义验证方法

不能只测试“静态和运行时调用同一规范化函数后摘要相同”。每个语义族还必须用独立预期检查实际数据：

- map 的保留/替换字段、nullable 与缺失。
- filter / async None / flat_map / batch 的行数和展开语义。
- join 的空值、重复键多重性和字段冲突；不比较原生未承诺的顺序。
- 模型 when/error_output 路径的字段可用性、实际请求与响应引用。
- 物化与多次 action 的执行次数、资源关闭和新表回执。

增加定向变异反例：篡改运行时实际参数、换 callable/资源、让原生返回结构与声明不符。检查必须确实拦截，不能仅验证自己的报告字段。

真实集成使用自有临时表、受控本地资源、fixture 图片与模拟请求服务；查看请求数和结果事实，测试服务不得伪装成真实模型质量验证。真实外部请求、共享服务和生产操作不因设计通过而自动获得授权。

## 8 设计完成与实施完成的区别

设计完成条件：模块职责、依赖、静态/实际数据流、配置绑定、故障/资源、兼容和验收均已明确；已识别问题完成修订，没有依赖“先放开再补”的步骤。

实施完成条件：UC-01 至 UC-18 与相关既有回归具有实际证据，多类算子端到端运行，可从统一界面看到准确的图、状态、结果与失败原因。本次已实施，实际验证结果单独记录，不能将本段设计自审当作测试证据。

# 共享工作区同步：分阶段 Review

对应方案：[已批准设计](forge-shared-workspace-panel-design-20261103.md)。本轮只改变查询与展示，不改 Flow 执行、提交、恢复或平台快照准入。

## 阶段一：有界读取

- `workspace_changes` 只生成派生文件元数据标记，没有新增数据库、持久化索引或事件总线。
- 源码清单与工作区发现共享遍历函数：flows/operators 各 1,024 项、深度 16，覆盖所有普通文件元数据（声明配置没有扩展名限制）；不扫描 Lance、图片、封存 runtime 或账本内容。
- 表和报告清单沿用受限控制目录；运行清单复用已有 128 项限制。检查 SQLite 主文件、WAL、rollback journal 元数据，读取实际状态仍交给 runs/RunJournal。
- 运行列表先校验全部有界身份、排序，再读取所请求页的输出事实。保留未显示页的根目录、run_id、manifest 摘要检查。页内容超过 8 MiB 明确拒绝，未修改执行成功与部分提交的判定。
- 复审修订：输出动作属于 Forge manifest 语义，应在 runs.py 提取；原生 RunJournal 只接受通用读取投影，不解析 Forge 的 outputs。
- 首轮 4 项后端验收通过；128 项清单、20 项页耗时 0.850 秒。SQL trace 未读取节点观察、completion，未执行写入。该数值是本机样本测量，不是延迟 SLA。

## 阶段二：单条同步链与界面边界

- 自动轮询、手动刷新、重新可见共用一个在途任务；上一轮结束后再计时。当前运行复用此调度，移除独立的每秒运行轮询。
- 没有变化只读取 changes；当前活跃运行读取真实监督状态。发生变化才重读相关区域；Case 和图片不因其他区域变化反复加载。
- 保持 ViewV1 的历史运行/报告/固定表身份；不自动导航到新实验，不升级到 head。
- Flow 表单草稿存在时保留表单，报告清单/依据仍可更新。未保存编辑不被元数据轮询当成工作区事实。
- 复审补齐同页竞态：运行详情、运行列表和产物列表都拒绝较早请求覆盖较新读取；结果别名在重绘前从当前输入读取，长度遵循既有 64 字符标识约束。延迟取消后的旧详情不得覆盖随后完成的新状态或用户新输入。
- 已保存报告的静态状态与当前依据明确区分，列表标注尚未复核；打开的报告按原摘要检查真实变化，不扫描所有报告来伪造即时验证。
- 网络失败保留旧内容，使用单一同步状态提示；恢复后重试 GET。写操作只由明确用户动作或 CLI 执行，不能自动重放。
- 删除页面对话按钮、对象发送选择、宿主能力数量、codex.js 的装载/路由及注释专用元数据；保留独立有用的定位链接、Case 选择与原生查看。
- 浏览器验收使用真实 HTTP、Lance、文件保存与 CLI，不使用宿主注册数量作为成功依据。

## 阶段三：最终验收

66 个不同相关测试项分批通过；最后的 10 项复测、节点选择竞态及最终文件版本的完整 CLI 两次实验也已通过。详细矩阵和实际结果见 [验收记录](forge-workspace-sync-acceptance-20261103.md)。

对任务开始时的 dirty 文件副本进行 AST/字节核对：prepare/start/cancel/reconcile/evidence 等写入行为、执行 worker、平台 snapshot 规则、原生日志所有写入方法均保持不变。未改动业务仓、共享环境或旧运行封存代码。原演示服务仍使用原工作区、原端口和原会话，16 项控制/历史文件摘要未变。

同一运行刷新期间的新节点选择以最新 View 为准；准备/打开显式链接时仍验证其指定节点，不用旧视图掩盖非法链接。实际浏览器和自动回归均覆盖这一边界。

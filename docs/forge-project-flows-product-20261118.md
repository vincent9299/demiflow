# 项目、算子库与多流程：产品设计与规范对齐

2026-11-18。本文件区分已实现的开发规范/登记检查与待实现的工作台页面。当前线上 59866 未因本设计改版。

## 1. 真人已确认的意图

- 沿现有 `operators + prompts + flows` 组织，不把所有业务强行抽象成“一个正式入口、多组配置”。
- 项目可以有多条独立流程；共享的是有明确能力边界的算子定义与 Prompt 定义。
- 每条流程可以有其接线所必需的业务参数；只有一份参数定义和当前值，无“入参文件/参数方案”选择。
- 算子默认配置、Prompt 定义、引擎内部参数各归其位。
- 产品仍以看懂真实 Dataset 算子图、API、输入输出和自定义代码/Prompt 为优先；配置检查等外围不抢占画布。

不把一个算子的每次调用当成新算子，不为跨流程复用复制源码，不因目录规范而创建包装执行器或模型 Actor。

## 2. 四种对象及唯一权威

| 对象 | 包含什么 | 不承担什么 |
|---|---|---|
| 项目 | 流程清单、代码与 Prompt 定义的归属、开发和数据上下文 | 不设必须执行的总入口 |
| 算子定义 | 真实函数/Actor 或具名 Prompt pack 条目；自身接口、默认值、源码/模板、输出契约 | 不携带某次运行状态、具体上游 Dataset 或流程私有阈值 |
| 流程 | 独立入口、Dataset 接线、必要业务参数；节点引用定义 | 不复制定义、不把无关流程塞进 stage 分派器 |
| 运行 | 选定流程、当时参数、代码/Prompt/模型依据、真实计划与结果/状态 | 不编辑当前定义或生成额外“参数方案” |

“定义版本”和“调用节点身份”不同。同一 `review.yaml:quality_review` 可被两条流程或同一流程两次调用；库中定义一份，图中调用分别呈现。模型配置的合法运行绑定显示在调用处，不把绑定后的副本注册成另一个算子。

## 3. 主导航与页面分工

`开发 ｜ 算子库 ｜ 管道 ｜ 运行监控 ｜ 数据 ｜ Readme`

### 算子库

- 项目级页面，不需要先选择流程，不显示流程参数。
- 左侧目录按代码算子、Prompt 算子组织；可显示明确引用的共享定义及其维护方。未引用但已声明的定义仍可浏览。
- 右侧查看 API 接口、输入、输出、实现代码或 Prompt。代码/Prompt 类型决定可用内容，不摆空白页签。
- 输入是定义要求的字段/变量、参数与默认值；实际某条流程的 Dataset Schema 属于调用节点。
- Prompt 展示完整正文、消息/图像绑定方式、输出 Schema、原生声明的模型与调用设置；正文默认可读，不埋进来源摘要。
- “使用位置”链接到真实流程及调用；动态引用无法证明时标明未知，不伪造完整引用数。未引用不等于不可用，也不据此自动删除。
- 定义与业务辅助函数区分：路径声明证明所有权，不自动证明目录里每个 helper 都是公开可复用算子。
- 编辑沿用开发/源码工作流，不新增网页专属源码副本。共享修改需展示已知影响范围，并使受影响的当前计划过期；不修改历史运行。

### 管道

- 多流程时左侧列流程名称及简短目的；单流程时直接进入，省去只有一个选项的下拉框。
- 头部只保留 `流程名称 · 当前计划状态 [业务参数] [源码] [解析] [运行]`；不再并排出现流程入口路径、参数文件、参数方案。
- 默认主体是图。节点目录作为图的浏览方式留在管道内，不再冒充算子库。
- 点击节点查看真实 API 调用、实际参数及来源、上下游 Schema、对应代码/Prompt；可跳到算子定义，返回仍定位原调用节点。
- 只显示引擎真实编译/封存计划。尚无计划时显示明确的解析入口；需要参数才展开缺失项。不能用静态调用语法图填补空白。
- 首个 action、未运行、动态后续动作未知等范围事实仍保留为紧凑状态，不因简化页面夸大图的覆盖。

### 运行监控

- 按具体 run/attempt 展示状态、节点观测、日志、结果和受支持的停止/恢复。
- 参数来自该运行的封存快照，默认只读。当前流程参数修改不影响历史，也不替换恢复参数。
- 历史节点默认查看当时实现/Prompt；跳到当前算子库需明确标为“当前定义”，不能静默混用。
- 运行图、源码、参数、观测与结果保持同一绑定；仅凭同名算子不关联历史状态。

## 4. 单份业务参数

### 一条流程的一份契约、一份当前值

契约来自该流程入口的具名参数、默认值及结构声明。参数页直接显示当前值，没有选文件、选配置、选方案的前置步骤。不同流程有不同参数契约；不从所有 API 参数收集出一个通用大表单。

| 示例 | 归属 | 产品呈现 |
|---|---|---|
| 输入 Dataset、固定版本、业务筛选范围 | 流程业务参数 | 单份参数表单，Dataset 引用有明确结构 |
| 这条筛选流程对外提供的质量阈值 | 流程业务参数 | 显示当前值、单位、合法范围和默认值 |
| 行函数内部默认处理方式 | 算子定义 | 算子接口的默认值；调用有覆盖时显示实际绑定 |
| 固定评审正文、默认模型声明、响应 Schema | Prompt 定义 | 算子库内管理；管道节点查看实际绑定 |
| worker 数、队列内部结构、资源协议、连接凭据 | 引擎/部署 | 不自动进入流程业务参数表单 |

流程确需暴露模型选择、并发等字段时，必须作为该流程明确的业务/运行契约有理由地声明；不因为底层 API 接受就默认展示所有字段。凭据不作为普通参数回显。

文件不是产品对象：确需 JSON/YAML 作为持久载体或导入/导出时，读写同一份当前值，不派生可选配置列表。此类高级能力可后延。

### 交互状态

1. 首次打开流程：有默认值直接显示，必填未填只提示具体字段；无参数则不显示空表单。
2. 查看参数：在同页详情区展开业务参数，图仍可回到；不跳到另一个配置中心。
3. 修改：本地未保存草稿有明确状态，自动解析/运行不使用未保存值。保存成功后更新唯一当前值并使旧预览过期。
4. 解析：使用已保存参数及源码快照，只编译，不读业务数据、调用模型或启动 worker。缺失条件据实说明。
5. 切换流程：每条流程分别保留自己的草稿/当前值；迟到请求不得覆盖新流程。
6. 并发修改：保存带当前 revision，冲突保留草稿并要求核对，不能静默最后写入覆盖。
7. 运行：提交时核对源码与参数 revision，封存完整有效值（含默认），沿原生运行/提交链执行。
8. 历史与恢复：读取原快照；改变当前参数不是改变已有运行的恢复输入。新运行由当前值另行提交。

未声明类型或无法可靠解析的结构要明确显示，不猜造表单字段或执行 Python 默认表达式来发现参数。

## 5. 接口与状态边界（产品实施契约，尚未实现）

- 项目目录：从实际注册的 `projects / flows / operators / prompts` 及受控源码读取；与开发工具共享定义，不重建私有业务登记。
- 定义引用：代码用所属项目、源文件、函数/类符号及源码摘要；Prompt 用所属项目、源文件、具名条目及摘要。语义版本保留原声明，不由页面猜测。
- 流程参数契约：从明确入口绑定生成；契约与当前值分开，当前值只有一份，带 revision。沿现有工作台持久化与权限边界扩展，不新建运行账本。
- 解析输入：`flow_ref + saved_arguments_revision + source_revision`，结果返回对应真实计划和同一依据。参数来源是否为文件不影响业务 API。
- 节点详情：调用身份 + 定义引用 + 已封存/已解析的参数与 Schema；节点目录、图和定义查看共享材料读取，不复制解释器。
- 提交/恢复：复用现有原生执行与回执。产品参数改版不能绕过 code pin、封存契约或历史保护。

工程实施前须按现有服务接口落具体字段与权限；本设计没有把这些示意字段宣称为已发布 API。

## 7. 产品验收必须覆盖

1. 两条真实 Dataset 流程共享一个代码算子和一个 Prompt；库里不按调用数复制定义。
2. 无参数流程可直接解析；有必要参数的流程只出现一份表单，没有配置文件选择。
3. 修改流程 A 的业务参数不修改定义默认值，也不改流程 B 或历史运行。
4. 修改共享代码/Prompt 后，两条受影响流程的当前图过期；旧运行仍能读当时材料。
5. 同一定义在图中出现两次，各自调用参数与节点身份正确；从库跳转不混节点。
6. 保存冲突、缺失参数、源码变化、快速切换、刷新都不展示旧绑定的图或详情。
7. 实际执行、提交、恢复沿现有链路，不增加工作台执行器、账本或第二份 Prompt。
8. 文件/Prompt 多定义、明确共享依赖、未引用定义、未知动态引用、非标准文件名均诚实处理。

这些是下一次产品实施的验收条件，不是本次规范工具测试的已通过声明。

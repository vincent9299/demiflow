# 原项目识别重复读取优化

同一 Python 文件可以声明多个入口。此前每个入口都会重新读取、解析整个文件：一个 786,738 字节的模块声明 8 个入口时，前 5 次成功读取已消耗 3,933,690 字节，剩余入口触发 4 MiB 总预算，最终只有 5 个入口被识别，另 3 个被报告为不可读。

`project_discovery.discover` 现在按源码路径复用本次调用内成功解析的声明摘要。每个成功解析的模块只保留内容摘要、顶层函数的数量和行号、旧协议 config 函数数量；不保留原始源码或 AST。逐入口的符号、重复定义和协议检查继续执行。语法错误等失败路径尚未保存可复用摘要，仍可能重复读取并触发预算；其失败和未覆盖状态继续明确报告，后续单独评估这部分开销。

每次复用前核对文件身份、大小与修改时间；首次读取和解析前后也核对相同信息，变化时报告冲突。摘要不跨 discover 调用保存，下一次识别仍读取当前内容。128 文件、4 MiB 总读取量、单源码 1 MiB、单文件 50,000 AST 节点及路径边界保持原值。不同源码文件仍共用总预算。

## 隔离样例对照

样例只在本地临时目录生成上述单模块和 8 个入口，不调用入口、模型、网络或数据表。耗时为依赖导入后 5 次识别的中位数，不代表服务吞吐或生产性能。

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 已识别入口 | 5 / 8 | 8 / 8 |
| 成功读取源码次数 | 5 | 1 |
| 成功读取源码字节数 | 3,933,690 | 786,738 |
| 识别耗时中位数 | 约 27 ms | 约 6 ms |
| 识别期间 Python 分配峰值 | 约 1.63 MB | 约 1.63 MB |

读取字节数减少 80%。Python 分配测量不包括依赖导入及原生分配，不作为进程 RSS 上限。没有调高预算、关闭检查、引入长期缓存或生成第二份业务接线。

# pplx CUDA Graph 正式集成：方案与 Review

日期：2026-11-01。范围：显式开启的 pplx 单卡图执行与独立 stream；不合批，
不改权重/精度/校准/原生分块逻辑，不占用或重启现有服务，不 commit/push。

## 设计

1. 一个模型专属执行适配器，复用原 HTTP worker、services 生命周期与 Dataset。
   不增加行调度、journal、后台捕获或代理。导入/解析配置不加载 Torch。
   每条 GPU lane 使用一个固定执行线程；取得 lane 后才能提交，至多一个任务，
   不另设请求队列。图全部销毁后才结束线程，底层库句柄不随 HTTP 连接销毁。
2. 共享不可变权重，分别持有模块可变状态和 CUDA stream。编码仍由原生 encoder
   完成；原生 decide 继续负责拆分问题、读出和校准。图片、多 chunk 等不满足
   图前提的输入走原生受限路径，不改写成另一种计算。
3. 精确 `(长度, 读出位置数)` 缓存，没有固定长度白名单或 padding 桶。
   有界热度记录达到阈值才捕获；全局缓存限制条目及显存预算；高频优先、同频 LRU，低频候选不能挤掉热图。
   进程捕获次数、累计捕获时间有限，预算耗尽后已有图继续用，冷请求走原生。
4. 读者保护普通推理/重放；写者独占捕获、回收和关闭。捕获前等现有 CUDA 工作
   完成。图保留所有静态输入、索引、mask 和输出，独立内存池，不共享任意重放
   顺序的可变缓冲。已使用的图在结果拷回 CPU 并同步后才可淘汰。
5. 两级内存约束：进程 Torch allocator 总上限（包含权重、图、临时工作区），
   以及缓存预留/驻留上限；分配前按形状估算工作区与图预留，无法放入预算则
   不捕获或明确拒绝过大请求。捕获期间临时收紧 allocator 限额，完成后按图
   私有 pool 的实际 reserved 字节计费。驱动/第三方工作区不在 Torch allocator
   限额内，保留设备余量并明确披露，不能把它冒充整个 GPU 进程的硬上限。
6. 每张新图首次 replay 与同一请求的原生结果精确对照；不匹配时返回原生结果、
   丢弃图并关闭本实例后续图加速。默认周期抽查图结果。捕获/执行异常不假装
   成功，CUDA 状态不可信时使服务失败，不能盲目重试。合批证据不能开启此路径。
7. 可观测性只提供有界计数和预算：命中、原生回退、捕获、淘汰、校验、实际
   缓存字节、预留峰值、是否失效。能力区分 stream 并行、缓存和 batch=false。

## 方案 Review

| 风险 | 约束与验收 |
|---|---|
| 只优化前 8 个长度 | 不预选长度；用真实样本冷/热/交错顺序，统计实际捕获长度数 |
| 捕获时别的 stream 分配 | 写者优先的排空门闩；包含 native 回退与检查调用 |
| 淘汰后异步访问已释放张量 | 读租约覆盖结果回传与 stream 同步；独占回收 |
| 动态更新 token 或 marker 丢失 | 同长度不同内容/读出位置交错复用，逐项原生对照 |
| 首次捕获更慢、不断抖动 | 热度准入 + LRU + 捕获数量/时间预算，报告冷启动成本 |
| 显存“先分配后检查” | 估算预留、缓存预算、临时 allocator cap 在 capture 前生效 |
| 原生逻辑被复制一份 | 继续调用原生 decide/encoder/reference_logits；只包装图执行 |
| 总并行改变图片/内部多 chunk | 这些路径保持原生并独占 GPU，不混用未验证图 |
| 行结果/预算变化 | 原算子回归 + 1k journal + 停机重放；配置仍完整内联 |
| GPU 监测被其他任务干扰 | 只用 GPU 1，采样同时检查本任务 GPU PID 归属 |

该方案优先消除 CPU 发射间隙、提高常见形状命中率。冷门长度、首次捕获、
工作区预算和低到达率仍会限制利用率；持续 100% 不是所有业务的承诺。
只有数值、资源、并发和生命周期回归通过后才报告正式能力可用。

## 实现 Review

- 编码前限制请求字节及问题重复展开规模，编码后限制 token 总量；不以分配后
  检查冒充编码分配前的保护。工作区估算不能证明第三方分配峰值，allocator
  限额仍作为隔离 worker 的最后保护。
- 关闭先拒绝等待请求，已取得执行槽的请求排空后释放图。GPU 执行异常唤醒
  等待者、使 health 返回 503；质量不一致则回原生并将 parallel 降为实际值。
- 更换调用线程、混合原生路径并开始淘汰时，首轮 GPU 测试发现非法地址访问。
  当前 Torch 的 `CUDAGraph::reset()` 会清理同一 capture stream 的 cuBLAS 缓存；
  独立图 pool 本身不足以防止图引用池外的共享 cuBLAS 工作区。
  捕获前清理旧 workspace 引用，使 capture 在本图私有 pool 内分配；捕获同步后
  清理全局引用，由图 pool 保留地址及计费。全部操作在独占门闩内执行。
  这是当前 Torch Inductor `clear_cublas_manager` 使用的方式，无需改外部环境或精度。
  启动先检查所需运行时 API，不支持则明确拒绝。
- 原生版本、Transformers Qwen 实现及适配器文件纳入 prepare 身份；代码或依赖
  改变后必须新 revision/prepare。运行中的旧服务不被自动重启或升级。
- 首轮缓存策略还暴露冷形状捕获抖动：800 条混合请求消耗 128 次捕获，
  捕获用时约 49 秒。默认热度阈值提高到 8，按有界频率优先保留热图、同频 LRU；
  新候选必须比需要淘汰的条目更常见，不能用冷门长度挤掉高频图。

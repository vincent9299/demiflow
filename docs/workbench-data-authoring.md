# DemiFlow 工作台与数据开发设计

一次数据分析或标注有三个长期可保留的产物：项目里可导入的 Python 工具、Notebook 中可编辑和重跑的 cell、与该 cell 关联的对话。数据页以 cell 及其输出为中心。开发页继续承载面向整个项目的会话。

## 使用路径

以“按组看平均分，然后把缺少评分的样本拿出来审核”为例。

1. 用户在左侧「数据字典」选表，在「工具」找到需要的分析函数或标注组件。工具可以通过选择加入助手上下文，也可由助手按需发现。
2. 中间显示当前 Notebook 的卡片，右侧显示选中卡片的对话。点加号在当前 Notebook 中建一格。打开另一份 Notebook 会切换文档。每个请求在发送时绑定项目、文档与 cell，随后点击别的卡片不会改变这次请求的目标。
3. 助手查表的实际版本、字段和工具的导入路径，用 Python 把读取、分析和显示接起来。更新后的源码在原卡片可见，用户可以手动修改。如果等待期间用户改过代码，保留用户的版本并报告冲突。
4. 有本轮运行许可时，助手可以在该 Notebook 的现有内核运行目标 cell。执行计数、输出、异常出现在卡片里，助手只根据真实回执说明结果。标注选项可由工具渲染为控件，人做判断，作者的回调决定怎样保存。
5. 希望跨 Notebook 复用时，将 Python 函数或类放进项目工具模块。项目内的其他 cell 可以直接导入。通用功能也能随第三方包或平台版本分发。

## 界面与代码职责

| 位置 | 用户看到什么 | 由谁维护 |
| --- | --- | --- |
| 开发页 | DemiFlow 顶部导航、会话列表、居中正文、贴右边的分段位置导航、底部输入框；右上可打开项目根目录 | 工作台适配 DSH 会话导航与文件树；移除旧会话菜单和轨迹入口 |
| 算子页 | 已声明的代码算子和 Prompt 算子，含尚未接线的定义；代码有语法着色和真实行号 | 项目在 `operators/` 声明算子；旧项目的流程直接引用用于兼容识别 |
| 数据字典 | 已绑定的表、项目声明引用，以及自动发现的 Lance 表。可增加数据目录。展开后查看真实字段及版本 | 项目在工作台登记数据位置，复用已有位置权限与固定版本读取接口 |
| 工具目录 | 项目、第三方、平台的可复用工具放在一起，分析、标注等用途可以作简短标签 | 项目自写或引入的模块放在 `data_tools/`，平台模块随 `demiflow.data_tools` 分发；仅展示显式声明的入口 |
| 中间工作区 | 简洁的带细边框卡片、可折叠源码、可交互输出，支持完整 Notebook 视图 | 原生 Jupyter 提供文档、编辑、内核与控件；普通完整 DataFrame 可使用 Observable Inputs |
| 右侧助手 | 当前 cell 的对话、所引用模块和更新反馈 | 助手通过命令行操作绑定的工作区；工作台校验当前权限、源码变化和执行回执 |

工具描述用户可以调用的能力。插件描述以后可安装或升级的扩展包。一个包可以导出多个工具，业务仓库也可以只维护几个 Python 文件。当前工作范围覆盖目录式接入；独立的插件市场、远程安装服务和业务项目迁移留待另行决定。

项目数据字典会扫描项目和已登记的数据位置，识别目录形式的 Lance 表。登记共享目录的命令示例为 `demiflow workbench location /path/to/project shared /path/to/shared-data`。默认只读。目录树按层遍历，深度与条目数有上限，超过条目预算会在字典显示提示。

## 工具作者

项目目录示例：

```text
operators/                 # 管道执行入口
data_tools/
  quality.py               # 项目直接维护的工具
  vendor_package/          # 引入的第三方 Python 模块或其轻量适配器
notebooks/
  质量审核.ipynb
```

例如在 `data_tools/quality.py` 显式导出一个已有函数：

```python
__demiflow_data_tools__ = {"missing_scores": "analysis"}

def missing_scores(frame):
    """查看还没有评分的行。"""
    return frame.loc[frame["score"].isna()]
```

cell 中用 `from data_tools.quality import missing_scores` 导入。第三方库原样安装到内核环境时，可在 `data_tools/` 写一个短适配器，声明真正要公开的函数。目录索引静态读取声明和签名，点击工具无需执行项目代码。平台内置模块使用独立的导入命名空间，避免项目同名函数相互覆盖。

## 对话接入与执行

`dataskill` 随平台发布，并在 cell 对话建立时注入，供支持 shell 的模型使用。Python 工具保持普通库接口。

| 命令 | 回执 |
| --- | --- |
| `data catalog list dictionary`、`data catalog list tools` | 当前项目的目录、条目标识和下一页 |
| `data catalog show dictionary ID`、`data catalog show tools ID` | 固定版本读表示例与字段，或真实导入路径、签名和说明 |
| `data cell show` | 目标 cell 的源码、输出摘要及本轮运行许可 |
| `data cell edit` | 从标准输入接收源码，按发送时的版本更新原 cell，或返回冲突 |
| `data cell run` | 在当前内核执行，返回执行计数与输出摘要，或具体异常 |

助手沿用工作台的项目与模型权限。命令绑定本轮，不传 Jupyter 管理凭据，不授予助手任意工作区写权限。编辑与运行分别核对；同一个命令不会随断线重放而重复运行。会话追踪应当能区分“生成了建议”“源码已更新”“执行成功”“内核返回错误”四种结果。

## 开发批次与验收

| 批次 | 工作 | 收口条件 |
| --- | --- | --- |
| 第一批 | DSH 会话滚动/文件树、算子显式声明和源码阅读、原生 Notebook 卡片与每格助手 | 长会话、加载历史、跳转、窄屏、手动改代码时收到异步回复、真实内核、GitHub main 及预览版本 |
| 第二批 | 统一工具目录、第三方与内置工具、可配置字典、模型通用 CLI、dataskill | 自写及第三方入口可导入；外部已登记目录能取到固定版本；CLI 编辑 A 时切到 B 仍只更新 A；手改保护；允许和拒绝运行；真实内核值与错误回传；重复订阅不会重跑 |
| 后续业务整理 | 梳理业务项目中混在算子目录的审核、展示和分析模块 | 由业务负责人逐个确认用途与公共接口；此前按用户决定保留原项目 |

第一批和第二批分别由隔离分支进入 integration。固定提交验收和差异裁定完成后，依次发布 main、推送 GitHub 并核对实际预览。开发文档定义交付标准，已发布状态以对应版本的发布记录为准。

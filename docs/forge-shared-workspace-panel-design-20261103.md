# Codex 对话与 Forge 操作台共享工作区：修订方案

日期：2026-11-03。状态：已按批准方案实施并分阶段 Review，测试与实际效果见 [验收记录](forge-workspace-sync-acceptance-20261103.md)。

本文件修正[此前方案](forge-codex-panel-design-20261103.md)的交互重点。用户明确：对话一直发生在 Codex，操作台保持一致即可；不需要选中 Case 后从操作台发起对话。

## 1 目标与纠偏

**Codex 和操作台使用同一个工作区、同一份运行事实。Codex 完成开发操作后，操作台更新相应内容。**

“保持一致”是数据、版本、状态一致，不是同步聊天、不要求用户选中 Case，也不是每次变更都跳转页面。

| Codex 中完成的操作 | 操作台应呈现的变化 |
| --- | --- |
| 保存 Flow、算子、参数或模型配置 | 当前源码/配置信息更新；相关旧报告依据变化时明确标记 |
| 完成一次静态检查 | 新检查报告可见，显示其明确代码和参数依据 |
| 准备/启动一次运行 | 运行列表出现同一 run_id，状态随原运行记录更新 |
| 运行提交结果 | 同一运行下出现真实结果引用，可查看、对照 |
| 继续加工或保留结果别名 | 新运行及明确固定版本引用出现在操作台 |

用户继续独立用操作台查看项目、接线、表、Case、运行和结果。平台不接管 Codex 对话，不要求“选择此对象 → 与 Codex 讨论 → 发送注释”才能使用。

## 2 保留什么，撤掉什么

保留：workspace/runs API、CLI、原生 Dataset 执行、检查/运行/结果事实、固定版本绑定、通用深链接、源码摘要核对、请求竞态保护、结果可视化。这些能力对任意 coding agent 都有用。

从本期产品主流程和验收门槛中移除：页面发起讨论、面向对话的 Case 选择、原生注释发送与 Site Tools 调用闭环。页面不再突出“与 Codex 讨论”“选择此对象”和注册数量；普通的表行/图节点选择仍是查看详情的操作。

`web/codex.js` 不再是操作台启动或同步的必需模块。宿主导航若以后有明确价值，再作为独立可选能力处理；本期不为此新增插件、MCP server、App Server 或浏览器命令桥。平台同步不能依赖模型能否拿到浏览器工具。

## 3 职责与数据流

| 部分 | 负责什么 |
| --- | --- |
| Codex | 与用户对话、编辑工作树；通过已有 CLI/Python 完成获授权的检查/运行 |
| 工作区文件、检查报告、RunJournal、原生结果引用 | 唯一项目与运行事实 |
| workspace.py / runs.py | 校验身份、读取事实、执行已有检查与运行操作 |
| WorkspaceServer | 原有鉴权 HTTP 与静态页面；提供有界的变化提示和读取入口 |
| 操作台 | 观察变化，读取对应事实，更新展示；保留当前页面和未提交编辑 |

数据流：`Codex → 现有工作区/API → 已保存事实 → 操作台重新读取`。用户在操作台使用已有运行按钮时，仍经过同一 API。页面不调用 Codex CLI，不把聊天记录复制到后端，也不把模型声称“已完成”当成运行成功。

## 4 最小同步机制

首轮使用有界轮询，复用现有 HTTP，不引入 WebSocket 服务、全目录 watcher、事件总线或新数据库。

1. **轻量变化提示。** 在现有 workspace API 中增加只读变化标记，HTTP 返回工作区所属及源码/配置、表引用、检查报告、运行区域的标记。标记从已有有界清单的文件元数据派生，不落盘为新实体。
2. **按需重读。** 页面可见时默认每 3 秒检测一次，上一轮结束后再计时。标记变化时只更新受影响的目录或当前视图；没有变化不反复加载报告、Case 或图片。
3. **运行状态复用原事实。** 当前活动运行继续读取既有运行状态和节点观察；运行列表也能发现 CLI 创建的新运行。统一安排刷新时机，避免现有运行轮询与工作区检测叠加。
4. **刷新是读取。** 刷新不自动 inspect、不准备/启动运行、不重绑平台、不补登记提交。源码改了但还未重新检查时，显示依据已变化，不能生成一份看似最新的图。
5. **用户位置保留。** 不自动从当前历史运行跳到最新运行，不把旧表版本替换成新版本。可显示“有新实验/结果”；用户自行打开。历史报告和历史结果保留固定身份。
6. **编辑保护。** 有未提交表单时不自动重建该表单；提示已有更新，待提交/放弃后再加载，避免另建逐字段冲突合并框架。

文件元数据标记只是刷新提示，不是完整性、执行准入或数据绑定证明；实际内容仍经过现有摘要、固定表和运行检查。手动刷新始终强制重新读取，不因标记未变跳过。需要覆盖的声明资源必须按现有工作区规范纳入清单，包含 `flows/` 下的 YAML/JSON，不能只观察 Python 文件。实际资源契约不限制配置扩展名，因此最终实现观察受限源码目录内所有普通文件的元数据，源码发现仍只解析 Python、参数入口仍只接受 JSON。

检测不得遍历 data/、Lance 内容、运行封存 runtime/、图片和模型账本。运行变化只检查现有最多 128 个 run 的控制文件/RunJournal 元数据（包含 SQLite WAL）；读取详情仍走 runs.py。源码、表和报告清单沿用现有数量/深度边界，超限明确报错。

源码复审发现：当前 `runs.list_runs` 对全部 run 调用 `show` 后才分页，间接读取全部节点观察；不能直接把它放进频繁自动刷新。启用同步前须把列表读取收窄为所需运行摘要，复用 RunJournal 的有界只读查询并保留身份校验，不读取 `node_observations` 或模型账本。完整节点详情仍仅在打开具体运行时读取；不新增摘要表或双写缓存。以接近现有 128 条上限的清单测量成本，通过资源验收后再启用周期刷新。

保证口径：健康连接下，通常在一个检测周期加实际读取耗时内反映已保存变更；不承诺跨文件原子快照或毫秒级实时更新。不处理尚未保存的编辑器缓冲。

## 5 刷新与服务生命周期

- 单页至多一条同步链；自动、手动及页面重新可见触发合并，不因重复点击制造 busy 错误。
- 切换页面使旧请求失效，旧返回不得把用户带回上一页或改写新页状态。
- 隐藏页面暂停检测；恢复可见时检查一次。失败显示连接/读取状态和最后成功观察时间，不自动重放写操作。
- 连接失败时保留可识别的旧视图并标明未更新；重试成功清除对应错误，不能仍显示“正在读取”。
- 沿用当前服务与 SSH 入口；查看服务有明确的独立运行生命周期，不绑定一轮临时工具调用。无需新增第二服务或额外转发。

## 6 源码级落点与实施顺序

| 模块 | 修订落点 |
| --- | --- |
| `workspace.py` | 增加有界变化标记读取；共享现有清单/路径边界，不把 source_inventory 或全量 report_status 放进周期轮询 |
| `runs.py` / `RunJournal` 只读查询 | 列表读取需要的摘要，避免全量节点观察；保留现有清单、身份校验、提交判定，写入/执行语义不变 |
| `workspace_view.py` | 新增一个有限只读变化查询入口，沿用鉴权/预算；无通用脚本或 agent action 接口 |
| `web/app.js` | 统一周期检测、手动刷新与运行轮询；按区域更新，保留历史定位/草稿；移除聊天导向的 UI |
| `web/view.js` | 保留通用准确定位，不添加 Codex 会话信息 |
| `web/codex.js` 与 index | 从操作台必需装载路径撤下；不再为本期同步扩展宿主工具 |
| 测试/文档 | 外部 CLI 修改 → 已打开页面更新；没有注释、没有宿主 API 也必须通过 |

顺序：①修复当前刷新/服务生命周期；②确认本方案（已通过）；③实现有界变化提示与自动刷新；④撤掉聊天导向入口并完成外部操作到页面更新的验收。

## 7 验收场景

1. 页面打开期间，从 CLI 创建检查/运行；页面无需手动重载就看到相同报告/run_id。
2. Codex 修改算子并保存；当前报告正确显示依据变化，历史运行的封存源码保持原样。
3. 从 CLI 启动、完成或取消运行；页面呈现相同状态、部分提交事实和固定结果版本。
4. 当前查看旧实验 A，另建 B；A 保持 A，列表出现 B，不抢走用户页面。
5. 未提交表单不被后台刷新覆盖；返回页面与手动刷新不并发堆积请求。
6. 服务短暂不可用后，页面给出明确提示；恢复后能够重试，旧错误消失，不重放任何写操作。
7. 普通浏览器无 Codex API，同步链仍成立；轮询不读图片/整表、不调用模型，不新增检查或运行。
8. 有界大清单、持续变更、页面隐藏和慢请求下，只有一个在途同步链，超限/失败明确可见。

此轮验收以“同一份工作区事实能否在操作台及时、准确呈现”为准，不以讨论按钮出现或站点工具注册数量为准。

# Unified native resource ceilings

Public `local_execution(native_resources=...)` now reaches both collecting and streaming action policy resolution. Memory, row size and spill ceilings constrain the original Bounds/store/allocator; batch rows bound Lance scan/hydration and terminal conversion; action and admission deadlines have active consumers. RSS and cgroup headroom are sampled guards of the actual host process, not OS isolation or prevention of arbitrary third-party allocations.

Native relational computation currently runs serially inside each admitted worker (one internal computation thread/partition); the legacy native `threads`/`partitions` values are upper ceilings, not Dataset output partition counts or requests to create a second DataFusion pool. They do not claim control of Lance/Rust/global third-party pools. Dataset replica and output block configuration remain separate and unchanged.

The optional native policy fields are absent from old wire and identity projections. New plans bind them. Live resume intersects current and sealed ceilings; required headroom takes the maximum. It preserves sealed physical IDs and assignments carry the effective worker limits. The original journal's already-established reservation ceilings remain immutable; tightening a previously used reservation ceiling can be refused, never silently relaxed.

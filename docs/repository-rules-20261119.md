# 分支、工作树与合入规则

- 2026-11-19 用户确认采用。
- 每条规则针对的现状、当天的完整盘点和一次性迁移步骤，见共享评审目录的
  `2026-11-19-merge-plan-and-branch-rules.md` 和 `2026-11-19-merge-plan-data.json`。

## 三条线

| 种类 | 名字 | 谁能动 | 怎么动 |
|---|---|---|---|
| 主干 | `main` | 用户，或用户授权的管理者 | 只快进到通过总闸的集成线提交，不直接提交 |
| 集成线 | `integration` | 一个管理者 | 只接受任务分支的合并，每次合并过合入闸 |
| 任务分支 | `<谁>/<领域>/<主题>-<年月日>` | 分支的负责人 | 从集成线当时的头拉出，一个分支只做一件事 |
| 归档 | `refs/archive/<年月日>/<原名>` | 管理者 | 不要的、被取代的分支挪到这里，不删对象 |

- `<谁>`：`gpt`、`claude`、`qoder`、`codex`、`human`
- `<领域>`：`engine`、`sdk`、`workbench`、`forge`、`test`、`docs`、`infra`
- 例子：`gpt/engine/p1-sdk-port-20261119`、`claude/infra/merge-gate-20261119`

过渡期：主干和集成线改名之前，主干是 `upgrade/architecture-20261108`，集成线是
`fix/prompt-replay-delivery-20261118`。已有的任务分支不改名，新规则只管之后新开的分支。

## 分支规则

| | 规则 |
|---|---|
| B1 | 只有一条集成线，名字固定 |
| B2 | 集成线当天是绿的，主干当天就前进一次 |
| B3 | 任务分支合入后当场删除。超过 3 天没合入的，负责人要么变基后交付，要么归档 |
| B4 | 合入只用带合并提交的合并（`git merge --no-ff`）。不用挑拣提交或重新实现的方式"取入"；要改，请负责人在自己的分支上改好再合 |
| B5 | 存档点用标签 `save/<谁>/<主题>-<序号>`，不开备份分支；合入后删除 |
| B6 | 不用 `git stash`。没做完的改动，在任务分支上用 `wip:` 开头的提交保存 |
| B7 | 交付的定义：分支在主仓的引用里，并且交付说明写了分支名和提交号。只存在于独立克隆里的提交不算交付 |
| B8 | 主干每次前进打标签 `main-<年月日>-<序号>`；预览每次换版打 `preview-<年月日>-<序号>`；引擎测试的已知状态清单绑定主干标签 |

## 工作树规则

| | 规则 |
|---|---|
| W1 | 工作树只放在 `_demiflow/worktrees/` 下，路径等于分支名 |
| W2 | 一棵树只对应一个分支，不换分支复用。新分支开新树 |
| W3 | 三棵固定的树：主仓（主干，各会话只读）；`worktrees/integration`（集成线，只有管理者写）；`worktrees/preview`（检出在预览标签上，服务只从这里启动） |
| W4 | 树和分支同生同灭：分支合入时，管理者移除树。有未提交改动的树不能移除，负责人先提交或明确丢弃 |
| W5 | `/tmp` 下只允许游离检出，用于基线对比和试合并。名字 `/tmp/demiflow-<谁>-<用途>`，谁建谁当天删 |
| W6 | 收工时树里不留未提交的改动 |
| W7 | 独立克隆只给写不了主仓 `.git` 的沙箱会话用。克隆里的分支交付时，由管理者当天取进主仓的引用 |
| W8 | 不在主仓的工作区里开发和跑测试。跑测试时在进程内确认 `demiflow` 是从自己的树里加载的 |

## 合入闸：每次往集成线合并都跑

在合并结果所在的树里：

    python tests/merge_gate.py

约一分钟。它做三件事：在子进程里确认 `demiflow` 是从这棵树加载的；核对七个冻结文件的摘要；
跑一组固定的守卫测试（包依赖棘轮、工作台与引擎边界、P1 边界、编译契约清单、旧执行代码保留台账、
已知状态工具）。任何一项不过，退出码为 1，这次合并不进集成线。

守卫文件缺失算失败，不算跳过。确实需要改冻结文件或守卫名单时，在同一次合并里改
`tests/merge_gate.py` 里的 `FROZEN` 或 `GUARDS`，并在提交说明里写明原因。

`python tests/merge_gate.py --list` 只列出名单，不运行。

## 总闸：主干前进之前跑

四条线的完整回归（标准、Ray、历史、历史 Ray），用 `tests/runtime_v3_regression_inventory.py`
产生回执，再用 `tests/engine_known_state.py compare` 和已知状态清单逐条比对。做法见
`docs/engine-known-state/README.md`。通过的标准是：没有清单之外的新失败，每一条差异都有归因。
通过后清单改绑到该提交，主干快进并打标签。

## 巡检：每天一次，只读

    python tests/repository_sweep.py --repository <主仓> --trunk main --integration integration \
        --clone <独立克隆路径> --patches

列出：主干落后集成线多少个提交；已合入却没删的分支；超过 3 天没合入的分支；可以移除的工作树；
有未提交改动的工作树；有进程在用的工作树；放错位置的工作树；目录已经不存在的工作树；stash；
独立克隆里没交付的分支。`--json` 输出完整清单。脚本只查询，不改任何东西。

`--patches` 会按补丁内容识别"提交号不同但内容已合入"的分支，较慢。规则 B4 落实之后不再需要它。

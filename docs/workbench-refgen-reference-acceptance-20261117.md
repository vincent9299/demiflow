# RefGen 标杆与真实算子图呈现验收（2026-11-17）

## 意图与交付边界

产品意图：在工作台看懂真实 pipeline，选择算子即可阅读其代码或完整 Prompt；完整业务流程具有可理解的数据流粒度，能看固定结果。引擎意图：同一 Dataset 声明用于编译和执行，输入、分支、模型、固定交付、结果与恢复使用平台现有权威。

本轮优先呈现，未扩大检查/配置产品设计。代码在隔离分支 `engine/gpt-runtime-v3-review-20261115`，没有修改主仓或原训练 pipeline。原 `refgen-synthetic` 在原位置读取。用户明确授权的新独立副本位于 `examples/refgen_reference_case`；它复制五份经 SHA 核对的 Prompt，没有复制生产启动器、训练加载器或 started/complete 恢复账本。

## 实现与用户看到的内容

- 解析调用实际 Dataset 编译器，返回真实节点、端口和边。不会执行行处理、启动模型或伪造 action 结果；范围明确为当前入口第一个 action。
- 新标杆使用一个完整 lazy Dataset 图和一个最终 `write_lance`，中途原生 `save_lance` 固定题图交付。真实编译结果为 **47 节点、52 条边**，包含八个真实模型节点，各出现一次。节点可以比用户的语义图更细，不通过空 map 拼展示层。
- 大图默认纵向，支持横纵切换、可读布局、适应全图、缩放、展开画布、键盘选中、算子定位和八个 Prompt 快捷入口。全图概览不承诺同时读清全部小字；可读布局保留正常字号并滚动定位。
- 源节点从封存的编译配置显示表名和版本；业务 label 取编译器已有呈现事实，不改变节点身份。
- 普通函数显示本次编译实际绑定的函数正文、文件摘要与行号；模型节点默认显示编译时选中的 Prompt 模板、版本、模型、服务类型、输入输出与响应 schema、请求上限。长文本自动换行，可分页读完。
- 材料与项目、入口、配置、预览摘要、logical/occurrence 身份绑定。刷新只保留定位线索，重新解析源码，不把浏览器缓存当执行事实。切换后的旧响应不可覆盖新选择。
- 无材料的标签禁用并解释原因；快照过期清空旧材料并提示重新解析。单个合法深 schema 超过展示预算时，只降级该节点材料，保留真实图。
- 配置中的凭据键和 URL 用户信息、query、fragment 不进入展示；数组中的 URL 同样处理。原 Prompt 正文和业务函数源码不会被重写为另一份程序。

## 完整业务链与真实性

三份固定源 → 关系/质量筛选 → 概念参考价值 → 联合出题 v4.1 → 每概念两组、每组三档 → 复用/合成/失败分支 → 合成图看图定稿 → 固定题图 → Boogu 有参/无参 → 概念呈现与文本遵循 → 明细和固定分母汇总。

一个概念的实际链路产生 42 次本地 HTTP 模型请求：质量 2、参考价值 1、联合出题 1、参考合成 1、定稿 1、作答 12、评分 24。结果包含 2 个固定题组、24 条评分明细与 12 条汇总。Dataset、对象读取、模型 transport/journal、固定表和提交都是真实平台实现；**只有外部模型响应由 fixture 产生**，生成图为合成像素，分数不能用于真实质量判断。

模型失败反例保留 24 个评分位置：一张作答图失败时，两路评分保留失败，其他 22 次评分正常执行。质量请求失败与“质量明确 reject”分开处理，不把请求失败当空候选池。最终 action ACK 后外层中断的恢复不增加模型请求或表版本；已成功完成的 RunContext 只读结果，不强行新建恢复 attempt。

完整链实际暴露并修复了控制回复重复携带递归 action declaration 的问题：worker 只需要 action ID 和预算，却收到整个深层声明，额外封装一级导致控制深度超限。现在仅返回消费者需要的身份与 limits；原 journal 声明保持完整，未调大契约预算，未绕过 code-pin 或修改提交权威。

## 十个独立检查角度

| 轮次 | 检查角度 | 发现/处理与证据 |
|---|---|---|
| 1 | 真实拓扑和身份 | 编译器节点、边、源和终端逐项对应；无静态图替代，无模型/worker 启动。`test_plan_capture.py` |
| 2 | 业务语义和完整范围 | 47/52 完整单 action；共享模型前缀只调用一次；去除仅为 label 添加的空 map。完整病例四项验收 |
| 3 | 名称、长文本与连线 | 修复 Prompt 横向截断、源节点无表名、主端口重复标注；截图实看后再测 |
| 4 | 大图操作 | 纵向默认、100% 可读布局、全图 fit、缩放、画布展开、Prompt 快捷定位、键盘选择；额外修复低于25%后“缩小”反而放大，用真实47节点图复验 |
| 5 | 代码对应 | 精确函数正文/行号/摘要；源码变更产生新预览，旧快照仍保持原材料；不可定位时不猜 |
| 6 | Prompt 细节 | 八个模板逐个读取；原项目三套配置的全文逐页拼接与服务材料逐字比较；版本/模型/绑定可见 |
| 7 | 缺失、上限与过期 | 禁用不支持标签、过期清旧文；独立复核发现并修复深 schema 拖垮图；缓存有条目/字节/时间上限 |
| 8 | 竞态与切换 | 晚到函数响应不得覆盖新 Prompt；离开页面、换项目/配置清除旧选择；手填配置与顶部选择同步 |
| 9 | 刷新与历史保护 | 刷新重新解析后恢复选择；既有 demo 七节点封存图仍显示；主仓、原 token 与原注册项目保持 |
| 10 | 真实视觉与结果 | 1600/1440 桌面及 780 窄屏截图亲检；完整固定结果接入数据目录；评分、分母汇总独立视图；默认去除大调用记录投影，保留原表全文，模拟身份显式标注 |

这些是不同风险角度的审查，不能理解为同一套测试重复十次。独立审查另复核了材料超限和数组 URL 两项反例；两项均有测试锁定。

结果呈现收尾另修复“无参条件的 null 参考图被报为媒体权限错误”：null 现在明确显示未提供媒体，不发起媒体核对或固定操作。Case 媒体测试中两个旧选择器在修改前的 `eea886c` 也失败；分别改为同时核对业务标题与实际 Case 行键、从现有“历史与恢复”入口打开嵌套历史面板。原有媒体依据、晚到响应、清除/恢复及收据断言全部保留。

## 明确保留的限制

1. 真实 Boogu 权重、真实图片质量、实际评分有效性和生产规模尚未验收。fixture 保留声明参数，但不执行真实扩散步骤。
2. 原生产三阶段仍是独立 action；不能把现在的完整标杆图挂到缺封存 DAG 的历史运行上。原业务的 started/complete 模型准入账本问题在只读审查中记录，未擅自迁移生产 pipeline。
3. 类实例、lambda 等 callable 的源码呈现仍有明确不可用情况；不能宣称所有 Python 写法均能精确定位。调用点无精确编译事实时不按名字猜行号。
4. 标杆项目的检查/受管提交尚未认证，网页运行按钮保持权限事实；完整执行证据来自隔离环境中的真实 Dataset/RunContext，不能冒充通过了 Forge 项目认证。
5. 本轮不是整个平台无缺陷或两大原始意图 100% 的证明；未受影响的历史验收不重跑，已有平台遗留项不因图呈现完成而消失。

P12 v2.1：对 Fable 有条件通过的答复

结论：三处意见均成立，两项阻塞已在设计中补齐；四条非阻塞建议也采纳。
依据是 main@e3b645b 的实际源码控制流、P4 守卫和全部模块/调用分类；没有运行产品测试或实施修复。

1. begin 失败不能制造运行失败
   同意。start 当前先 reserve，再 begin，异常处理可把 prepared 改为 launch_failed。
   本版明确 begin 在取得预留、创建 launch unit 和启动失败处理之前完成；失败保持 prepared，不 claim lease、不 spawn、不推进状态。
   同名 pending 保持显式 synchronize；不自动修复。begin 成功后若源尚未改变就失败，以所有者安全发布收尾 marker，原拒绝原因保留。
   补一个必要限定：_resume 的 begin 之前已有 register_results/clean_stopped，真实完成的恢复/清理不回滚。保证是索引拒绝不引发新 attempt 或伪造失败，不是整次请求零写入。

2. P4 消费者名单
   同意必须写清。选择不新增独立域消费者：DatasetRef 的构造、反序列化和固定身份校验留在 workspace 核心 helper；project_operations 只编排读取；table_bindings 不导入平台类型。
   pipeline_policy 使用 DEFAULT_LIMITS / resolve_payload_bounds，运行变化提示使用 observe_storage，均是已有索引导出，不需要逐文件扩独立域名单。
   本版预计 _surface 及生成说明零增减；实际 P4 守卫必须通过。若实现出现额外平台导入，先修订契约设计，不能临时加豁免。

3. 全模块分类
   同意。七个项目核心：workspace、checks、discovery、definitions、documents、io、index。
   三个应用角色：registry、watch、flow_arguments；另列 __init__。补 registry→api.serve 和 flow_arguments→graph.parameters→worker 路径。
   验收检查必须枚举实际目录，不能漏扫未分类模块；只宣称核心无静态路径到 runs，不宣称 projects 包整体无环。

其余选择：
   发布失败以有界诊断和既有 index 状态公开，不修改 report/manifest digest 或成功响应；不声称旧实现已经逐项反馈错误。
   complete=false 的可见变化仅影响缺索引且两域均空的旧根；--rebuild 才能证明完整，--synchronize 只结 pending。
   detach_table、set_table_view、workspace_context 保持登记表专用；报告 read_table 闭包显式传 resolver。
   runs 所有者与命令/协议入口分开；一次完整候选验收和发布，不让半迁移版本分别进入主干。
   引擎 platform_revision 与 Forge platform_snapshot 是两个不同检查；更新 Forge 快照不赋予旧运行跨版本恢复资格。

1. 本轮结论与范围

目标仍是工作台能看懂、配置和运行 Pipeline，并分析、比较和评测数据；本轮支持其中的架构职责与历史保护。P12 解决项目与运行的职责交叉，不增加业务能力，也不另建运行中心、状态库或执行 SDK。

现有产品已经能列运行、使用 run: 结果、预览与复核。问题在于项目核心反向进入运行管理，派生索引自己读取运行事实，项目刷新混入运行观察，预算规则寄居 runs。修改一侧时容易连带改变另一侧的身份、恢复和固定读取语义。

建议本批完成四条职责调整，并同批迁走会把项目核心绕回 runs 的 worker 代理及相关编排。只挪直接 import 不算完成。内部调用位置会调整，HTTP/CLI、Notebook 用户入口和持久格式保持；第 5 节单独披露旧无索引目录的保守 complete 状态变化。

本轮交付是方案与源码核对证据，未实施、未进行产品回归、未合入或部署。Fable 审阅对象是本稿的设计选择与验收条件。

范围外：全工作台 SCC 清零、projects.registry 的能力授予依赖、Notebook/analysis 服务组织、平台哈希范围优化，以及历史 P12 合列的 plan_revision 上界与 checked 对 _node_document 的私有引用。后两项属于引擎契约，不能因本批完成而宣称整个历史 P12 清零。

directory_operations.py（新增）显式 synchronize / rebuild，组合两域枚举器和所有者摘要，统一持 control_lock 与重建预算。日常列表、刷新不隐式调用；不修复原始运行，不修改历史报告。
table_bindings.py（新增）解析 selector 语法，按登记表 / run 结果路由，声明 TableResolver 协议；依赖只到基础类型与错误。不导入 projects 或 runs，不读取文件、做权限准入或验证提交，不含全局 registry、缓存或单例。
pipeline_policy.py（由 runs/limits.py 迁移）部署上限 → 项目政策 → 单次运行收紧；使用现有 P4 默认值及 payload bounds。不负责配额租约、累计用量扣减、worker 启停；不合并 Notebook SQL、analysis、Forge 对话预算。

应用模块只是承接已有跨域编排；不为每个既有函数套一层透传。项目核心的反向 worker import 要同时删除，调用方同批改入口，不在旧 workspace 中永久 re-export 新入口。

5. 契约 A：所有者 → 派生索引

资源 / 兼容条件固定约束
分页 / 状态原 entries / total / next_cursor / index 与 status 字段；limit 1..100，offset ≤1,000,000，cursor ≤1024 字符，epoch 重建后旧游标拒绝。日常读取不扫描源。
规模索引最多 1,000,000 项 / 256 MiB；pending 最多 256；active_runs 最多 256；marker 读取 4096 字节。保持 SQLite timeout、cache、mmap、journal 策略。
重建max_entries 1..1,000,000、timeout_s 1..300；流式枚举，所有目录项先计数，非法名字/符号链接/类型不符拒绝，不通过过滤隐藏增长；约每 100 项提交，末尾再次检查 deadline。不得先把全部摘要装入 list；磁盘峰值计旧库、临时库及 journal，沿库上限与原连接配置约束，空间不足失败。
遗留列表仅 index_not_initialized 继续原有有界 fallback；index_unavailable 不伪装为空，不扩大扫描。已存在源摘要错时不补造成功记录。
IndexEntry = {
  kind: 'run' | 'report',
  identity: run_id | report_digest,
  created_at: finite nonnegative number,
  digest: source digest,
  active: bool
}
SourceRead = IndexEntry | Missing   # 只有确认不存在才返回 Missing

run_index_entry(root, run_id) -> SourceRead     # runs 所有者
report_index_entry(root, digest) -> SourceRead # 报告所有者
index.begin(root, kind, identity) -> Marker
index.publish(root, marker, entry_or_missing) -> None | error_text
owner.publish_*_index(root, marker) -> None | error_text

Marker 保持现有 format / kind / identity / generation。
所有 marker / publish 操作在调用者持 control_lock 时执行。

run 摘要沿用 manifest.created_at / digest，active 按现有 ACTIVE 分类；先用 P4 observe_storage 分辨存在，再沿原 _load(detail='identity') 读取。report 摘要沿用已校验报告 digest 与文件 mtime，active=false。索引校验 kind/identity 与 marker 匹配、时间有限非负、active 为布尔和 digest 形状，但不验证业务源。

写入顺序不变：control_lock → begin 写 marker → 源事实发布 → 所有者安全发布摘要 → index 事务提交 → 再比较同一 generation → 删除 marker。索引或摘要读取失败都不得回滚已经发布的 run/report，也不能替换原业务失败。

必须将‘读取摘要’和‘调用 index.publish’一起放在所有者的 try/except Exception 内，返回 ≤1024 字符错误文本并留下 marker。禁止写成 index.publish(root, marker, run_index_entry(...)) 后误以为 index 内部 catch 能捕获参数求值错误。BaseException 不吞；进程中断后通过已有 marker 恢复。

Missing 只表示目标确实不存在；损坏、权限失败、P4 RunReadError、预算超限均是错误。沿用现行语义：Missing 可以完成本 marker，但不删除已有条目；清理失效目录成员由显式完整 rebuild 负责。旧不完整 run 在全量枚举中返回 Missing 时必须拒绝重建完成。

相同 identity 的源 digest 不得改变，排序时间不因重发变化；membership/active 更新与现有 revision 提示语义保留。revision 不是事实版本或权限凭证。提交后 marker 删除失败可重试，重复摘要写入不制造重复成员。

从 index._ensure 移除对 runs/inspections 的扫描。init_workspace 已独占新建 .forge 并拒绝既有控制目录，可显式 initialize_empty(complete=true)。其他旧根第一次创建缺失索引一律 complete=false，直到成功完整 rebuild；begin 不再猜测整个源目录为空。这是唯一计划中的索引可见状态收紧：旧空根第一次写入也可能显示不完整，而不会悄悄补扫。既有索引格式/epoch 不因本次代码升级重写，损坏索引不自动覆盖。

synchronize 迁到 directory_operations：持同一 control_lock，枚举并验证 bounded pending，按 kind 调所有者安全发布；返回原 status + errors。只处理 pending，不把未完整扫描的索引标为 complete。

rebuild 迁为应用枚举 + index.rebuild_from_entries：应用持锁，在共享 deadline/max_entries 内逐项调用运行/报告所有者，索引流式写临时库。全部源成功、预算未超、临时库提交关闭后才 os.replace；随后在锁内清理覆盖的 marker。源读取/枚举/提交/替换前失败保留旧库及 pending，清临时库和 journal。若 replace 已成功但 marker 清理失败，返回失败且保留剩余 marker，status 仍不完整；不得声称旧库未变或已经全部成功。

6. 契约 B：统一表选择 → 固定表绑定

TableResolver(root, workspace_control, selector)
    -> (control: dict, ref: DatasetRef, uri: Path)

registered selector: alias
run selector: run:<run_id>:<output_name>[:<attempt>]
optional attempt: 1..32；省略时沿现有选中 attempt 语义。

resolve_arguments(root, value, parameters, *, table_resolver)
    -> (arguments, tables, output_targets, control_digests)

_inspect_flow(..., *, table_resolver) -> 原检查报告
_report_status(..., *, table_resolver) -> 原状态/changes/verification
checks.check/status、_audit_check 等沿调用链显式转交同一窄能力。

plain alias 交项目登记表函数：保留 v1/v2 control、location 声明、ref.store_id 匹配、相对路径/符号链接限制及 display/provenance 校验。run: 路由交 runs.result_table：语法检查不提供权限或产物证明。未知/malformed selector 不回退为目录路径。

run 结果保持现有 _load(attempt) → _describe → _verified_output → DatasetRef 交叉校验，核对 version/schema_hash/row_count/relative_uri/store_id 与实际 uri；继承 attempt、checkpoint、native_stage_v3 的有效产物仍由现有 P4 证明。失败沿现有 ForgeError/code 返回，不把缓存条目或路径存在当成成功。

传统运行结果必须仍有当前声明 location，且实际路径与封存 output.uri 一致；native_submission 按现有封存 location_root 解析并做相同 uri/符号链接检查。本批不统一成新 location 模型，也不扩读权限。

未指定 attempt 的 selector 可能随后续恢复改变选中结果；每次解析得到固定 ref，不承诺 selector 永远指向同一结果。调用方已有 expected_binding、expected_result、source_snapshot 与读取前后复核必须保留。显式 attempt 继续读取该 attempt 的原生有效/继承产物，不自行选最新成功 attempt。

resolve_arguments 的四项输出格式保持：递归参数中的 table 变 uri/version；tables 保留 schema/row_count/identity；output_targets 仍由项目声明及 create/overwrite/checkpoint CAS 规则校验；control_digests 只记登记表控制文档，不为 run: 伪造 tables/*.json。保留 16 层、每列表 1024 项、参数结果 1 MiB 等现有预算。

TableResolver 由 worker.dispatch 或上层用例在当前进程组装，路由模块接收 registered_table 与 run_result 两个函数；manager 内可用自身 result_table 与项目函数组装，无需导入 project_operations。runs.admission/native_submission、graph、analysis 接收或在既有入口构造同样的路由。禁止进程全局默认解析器、启动时注册、调用顺序依赖和静默退回旧 workspace 路径。

解析器只封装函数，不缓存 root/control/ref；读取后复核必须传入重新读取的 workspace_control，不能捕获旧值。只有明确只处理登记表的项目本地操作可以直接用项目 table_binding；任何可能接收 run: 的入口都必须提供混合解析器。

跨 worker 边界仍传现有 JSON operation/root/arguments（必要时已有 bootstrap）；不发送 callable、闭包、DatasetRef 实例或 Python 对象。解析器在子进程 dispatch 内构造。FORMAT、1 MiB 请求、9 MiB 响应、现有错误码、超时/RSS/FD/authority 准入均不改变。

表版本列表/读取：run: 只允许封存版本；普通 alias 的历史版本仍需 Catalog 登记与 expected_version_binding 复核。媒体读取继续检查 field/provenance、媒体 location/授权和固定 source_snapshot；得到 TableBinding 不等于媒体读取许可。Notebook 的 SQL、会话、输出、能力和 host partition 均不因解析器搬迁获得新权限。

9. 失败与历史兼容：必须保持的可观察结果

触发应有结果
begin 后、源发布前退出原 marker 保留；显式同步按源存在/缺失处理；不伪造 run 成功。
源已发布，摘要读取或 SQLite 写入失败源事实保留，pending 可见，目录不完整；调用方沿已有 index error/reporting 规则反馈，不能撤销源或覆盖原异常。
旧 marker 重试时 generation 不同拒绝更新/删除别人的 marker；同 generation 重试不新增重复成员。
重建中源损坏/超预算/替换失败替换前保留旧库，清临时文件；不 complete。替换成功后清 marker 失败按第 5 节明确报告，允许重试。
run 结果无证明、location 改绑或 expected_* 不匹配原错误与冲突语义；不退为普通 alias、不读取最新版本、不补造 ref。
恢复切换 attempt / analysis 读取期间 alias 改绑显式 attempt 按其证据读取；默认 attempt 与所有前后 binding 复核继续生效，变化时返回 conflict。
索引缺失 / 损坏 / 遗留源不完整区分 not_initialized / unavailable / incomplete；只保留已有限制的 fallback，不在列表或刷新中隐式重建。
平台源码因模块迁移改变现有 snapshot 哈希包含工作台代码，历史 report/run 可能按既有规则判 stale。只读历史保持；需要重新准入时沿原显式 adoption/重新检查/新 prepare，不改旧 seal、摘要或执行资格。
权限或容量不足沿原 gate/lease/ceiling/reader 拒绝；解析到路径或索引记录不扩权。旧 Notebook 会话与授权不迁移、不重启。

保持 on-disk workspace/table/report/run/index 格式，不做扫描式迁移、不重签历史。模块搬迁仍会改变平台源码快照，这是既有升级语义，不把本批承诺成‘任意旧 run 都可直接恢复’。平台哈希去噪另立范围，不能为让本次测试通过顺手绕过。

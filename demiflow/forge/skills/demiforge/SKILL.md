# DemiForge 项目开发

1. **渐进式获取本项目上下文（先总览，再按需展开）**：
   - 先运行 `demiflow forge context --root .` 查看紧凑总览：已登记管道（含中文标题、摘要、入口路径与参数文件）、业务 Python 与沙箱配置、编排登记与草稿、角色目录统计与 SDK 索引。先根据标题直接定位目标入口与参数，避免盲目全仓 grep。
   - 按需展开细节：`--topic sdk`（实时发现的 SDK API 手册与当前项目用到的接口文档）、`--topic rules`（强制开发条款）、`--topic files`（全部角色文件清单）、`--topic flow|operator|prompt|workflow`（对应范例与正反例）、`--api SYMBOL`（单个 API 的完整契约、参数/返回值说明与源码文档，遇到不确定的公开接口用法或内部导入拦截时优先查询）、`--path REL`（聚焦文件及下游消费者）。纯解读任务到此即可回答。
   - 规划训练或旧训练脚本迁移时，先查 `--api demiflow.data:Dataset.fit`、`--api demiflow.data:TrainingRecipe` 和 `--api demiflow.data:PredictorSpec`。训练逻辑放在 trainer 回调里，由引擎接收 checkpoint 并交付受管模型。预测优先读取引擎交付的受管模型（或同图内 `checkpoints.select(...).predict(...)`），评测读取已提交表及其版本，拆成多条 Flow 时用 `workflows/*.json` 的 `$from` 衔接上游 `outputs` / `models`（见 `--topic workflow`），不要用散落临时清单文件做跨 Flow 协议或手工拼接 `runs/` 下的裸权重路径。用户要求先讨论时，交付拆分、数据缺口和待确认项，等确认后再改代码或启动作业。
2. **新建或修改标准文件**：标准角色目录为 `flows/`、`operators/`、`prompts/`、`configs/`、`data_tools/`、`notebooks/`、`workflows/`——Flow 运行参数与业务/部署配置统一放在 `configs/`，多管线 DAG 编排声明（`demiflow_workflow_v1`）放在 `workflows/*.json`（引用其他项目须使用已注册项目名或工作区 ID，禁止写绝对路径；先用 `--topic workflow` 查看编排声明和示例，在工作台用 `list_registered_projects` 按逻辑名称或工作区 ID 核实外部入口与绑定参数，用 `manage_project_layout` 的 `register_workflow` 操作登记。独立终端用 `demiflow forge add workflow --root . --register --path workflows/<name>.json`），采用扁平 JSON 键值（输入 Lance 表写 `{"uri": "data/in.lance", "version": 1}`，`version` 可选，外部只读表写绝对路径；输出 Lance 表写 `{"kind": "output", "uri": "data/out.lance"}`，默认 `mode="create"`；本地对象/图片目录直接传规范路径），运行产物放在 `data/`，可读运行日志在 `logs/`，Forge 平台内部状态统一收在 `.forge/`，`workspace.json` 仅保留项目可读清单（`name`、`entries` 及可选 `budgets`、`workflows`）。项目根目录只允许标准业务目录、`data/`、`logs/`、`docs/`、`tests/`、`runs/`、可选的 `pyproject.toml` 和经 Forge 校验的 `packages/`，以及隐藏目录，不散落非规范顶层目录、配置（`*.json`/`*.yaml`）、Notebook（`*.ipynb`，应移入 `notebooks/` 并保留输出）或脚本（`*.py`）；`flows/`、`operators/`、`configs/`、`prompts/` 仅保留活跃文件，废弃非数据文件直接清理，切勿转存或打包到 `docs/`；Notebook 复用工具归属 `data_tools/`（由数据页 Cell 助手编写维护，开发助手只读；发现散落的查看/标注脚本时用 `manage_project_layout` 的 `move_path` 归位）。新项目用 `demiflow forge init --root .`（接纳已有源码加 `--existing`），新增文件用 `demiflow forge add flow|operator|prompt`。已有文件按需求直接修改。
3. **改后自查与业务测试**：每次代码修改后，运行 `demiflow forge check --root . --path REL`（全项目验收运行 `demiflow forge check --root . --json`，会同时检查全项目 DF-02 目录整洁度；指定入口可加 `--entry REL.py:SYMBOL` 及 `--params REL.json`），根据诊断立即修正并复查。
   - **静态检查边界速查（切勿写临时 `_probe.py` 循环盲探检查器）**：Flow 接线层仅支持公开 `demiflow` API 与对静态参数/配置的纯 Python 校验（`if`/`raise`、`and`/`or`、`in`/`not in`、算术、静态推导式、纯内置函数及 `dict`/`str` 只读方法；注意 `if ...: raise` 仅用于非法参数直接拒绝，若需在默认 `false` 配置下仍能通过静态 DAG 构图检查的运行闸门请改用 `demiflow.data.require(condition, message)`），严禁在 Flow 接线期做任意磁盘 I/O 或用运行时数据决定拓扑；行算子仅允许纯计算/数据依赖（`json`/`hashlib`/`math`/`re`/`html`/`io`/`pathlib`/`typing`/`pyarrow`/`PIL`/`torch` 等），严禁导入宿主机副作用模块（`os`/`time`/`subprocess`/`socket`/`urllib`/`requests`/`shutil` 等，触发 `OP-05`）。**代码算子遵循 `DF-02` 算子自包含与语义充血七条硬门禁**：① **`OP-L1`** 公开业务算子模块（`operators/<domain>.py`）之间严禁互相导入（含函数内延迟导入）；② **`OP-L2`** 私有工具模块（`operators/_<util>.py`）仅放纯底层无业务依赖的叶节点工具（禁止与公开模块 1:1 同名影子 `_foo.py`、禁止私有模块之间互相导入、禁止 Flow 直接导入 `operators/_*.py`）；③ **`OP-O1`** 禁止无逻辑单行转发壳或赋值重导出别名（调参请在 Flow 中直接引用目标算子并传 `fn_kwargs`）；④ **`OP-O2`** 禁止公开模块通过 `from ._<util> import fn` 重导出私有函数/类作为公开入口（公开算子必须直接定义在公开模块中）；⑤ **`OP-S1`** 每个公开代码算子（函数/Actor 类）与 Prompt 定义必须写清首行中文业务语义描述（docstring / `description`），直接作为执行图节点说明展示；⑥ **`OP-P1`** 公开代码算子除首个数据行形参外的每个自定义参数必须在 docstring 的 `Args:`（或 `参数:`）段逐个写清中文含义并随签名变更同步更新（禁止残留已删参数，避免无语义黑盒 `options`/`config` 字典）；⑦ **`OP-E1`** 每个公开代码算子（顶层函数或可调用 Actor 类）必须在 docstring 的 `Example:`（或 `示例:`）段给出 1 条最小「`输入: ...`」「`输出: ...`」对比样例（仅列关键变化字段，兼容行变换、展开列表或过滤布尔值），并随产出字段变更同步更新，避免示例与代码漂移。项目源码须**自包含且仅依赖公开 SDK**，严禁导入 `demiflow.execution.<内部子模块>` 等平台内部实现，严禁跨项目 `import` 其他业务项目源码（触发 `DF-02`）。
   - **业务环境与外部依赖（`pyproject.toml` + `packages/`）**：
     - 业务项目以根目录 `pyproject.toml` 作为唯一依赖声明：`[project].dependencies` 声明安装到项目 Python 的 A 类包，`[tool.demiflow.packages]` 声明 B 类外部源码包（`{ source = "vendored", path = "packages/<包名>" }` 或 `{ source = "local_ref", path = "<外部绝对包目录>" }`）；仅使用 A 类包的新项目可用空 `[tool.demiflow.packages]` 表启用。
     - `pyproject.toml` 可直接新建、编辑和保存；`packages/` 与 `.forge/` 只读不可直写，需通过统一命令 `demiflow forge dep vendor <包名> <来源目录> --root .` 获取受管副本、用 `demiflow forge dep remove <包名> --root .` 解除声明并清理受管副本（绝不删外部 `local_ref` 原目录），用 `demiflow forge dep list --root .` 与 `demiflow forge dep verify --root .` 查看与校验（可先声明多个包再逐个 `vendor`，缺 A 类包时也可先获取 B 类源码）。在当前沙箱可读的非敏感目录内修改 `local_ref` 路径或完成 `vendor`/`remove` 后，下一条 `python`/`pytest` 立即生效，业务代码直接写普通 `import <包名>` 即可。
     - A 类环境包安装（`demiflow forge dep install --root . --python <项目Python>`）由项目所有者在受信终端执行，受限开发沙箱内保持离线。
   - **业务环境自闭环**：仅使用 `forge context` 报告的本项目业务 Python 环境在项目根目录运行 `python` / `pytest`（允许导入 `demiflow` SDK 及 `pyproject.toml` 声明的依赖包，不依赖平台宿主第三方包）。
   - 若 `forge context` 显示本项目尚未配置业务 Python 环境，**切勿**在宿主机搜索 Python/venv/pytest；完成源码修改与 `forge check` 静态检查后，明确提示用户在项目设置中配置该项目独立的 Python 解释器。
4. **严格遵守读写与沙箱边界**：写权限限定在本项目授权源码目录、`pyproject.toml` 及 `$TMPDIR`（**临时文件必须写 `$TMPDIR`，不要写宿主机 `/tmp`**），项目外目录一律禁止写入；严禁直接修改或破坏受 Forge 保护的文件与目录（`.env` 与 `.env.*`、`.forge/`、`workspace.json`、`AGENTS.md`、`PIPELINE_SPEC.md`、`packages/` 及整个 `data_tools/` 目录；`packages/` 仅允许经 `demiflow forge dep vendor/remove` 受控更新，`data_tools/` 由数据页 Cell 助手维护，开发助手只读）。项目运行凭证遵循 `.env`（本地真实密钥，不入 Git）+ `.env.example`（入库变量名模板，值为空）规范。登记/更新 Flow 入口、同步 `.env.example`（`sync_env_example`）、规范化 `workspace.json`（`slim_manifest`）、整理目录（`ensure_dirs`/`move_path`）或清理非规范/废弃非数据文件（`remove_path`）统一调用宿主工具 `manage_project_layout`（其中 `move_path` 完整保留 Notebook 输出，`remove_path` 严禁删除 Notebook、业务数据、`runs/` 及已登记文件）。读取项目外输入数据时，在工作台内使用 `read_input` 工具或按系统只读权限读取。
5. **独立评审与交付**：交付新增或实质修改的 Flow、算子、Prompt、跨管道输入或输出语义前：
   - 在终端/独立环境运行 `demiflow forge review --root . --entry REL.py:SYMBOL --goal "本次业务目标"`（复用参数，可附 `--evidence REL` / `--base REF` / `--path REL`）。
   - 在工作台开发会话中，独立评审由工作台宿主自动执行或通过宿主工具 `request_pipeline_review` 触发，不要在受限沙箱内直接跑 `demiflow forge review`。
   - 对影响交付的阻断项修正并复核；纯解读或文字调整可直接回答。
6. **登记新入口**：需向工作台公开新入口时，按权限使用 `demiflow forge add flow --root . --register --entry REL.py:SYMBOL`（可配 `--params`）；已有入口修改沿用原登记。结束时分别报告实际修改、静态检查、测试结果与尚待解决的限制。
